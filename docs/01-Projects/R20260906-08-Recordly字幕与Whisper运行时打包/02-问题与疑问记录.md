# 02 · 问题与疑问记录

> 来源：对话里点名的三个路径 + 「有 Whisper 还要下载」+ 「模型应随包」。

## 1. `.tmp/whisper-runtime` 是什么？

**开发机构建缓存，不是给最终用户的模型，也不会进安装包。**

| 路径 | 是什么 | 给谁用 |
|------|--------|--------|
| `.tmp/whisper-runtime/` | `scripts/build-whisper-runtime.mjs` 的下载/解压根目录 | 开发者本机、CI 打包机 |
| `.tmp/whisper-runtime/v1.8.4-windows-x64.zip` | 官方 **whisper.cpp v1.8.4** 的 Windows x64 **可执行程序包**（约 3.9 MB） | 构建时解压出 `whisper-cli.exe` + DLL |
| `.tmp/whisper-runtime/prebuilt-win32-x64/` | 上面 zip 解压后的目录（里面有 `Release/whisper-cli.exe`） | 再拷到 `electron/native/bin/win32-x64/` |
| `electron/native/bin/win32-x64/whisper-cli.exe` 等 | **已暂存的字幕引擎**（程序 + ggml/whisper DLL） | 开发运行、打进 app.asar.unpacked |
| `userData/whisper/ggml-small.bin` | **识别模型权重**（当前设计要用户现下） | 真正「听懂中文/英文」靠它 |

`.tmp/` 已在 `.gitignore`。删掉它只影响下次构建要不要重新下 zip，**不影响**已经拷好的 `electron/native/bin/...`。

一句话：**zip = 发动机；`.tmp` = 车间零件箱；模型 `.bin` = 油和地图。车间里有发动机，油箱仍是空的。**

## 2. 「明明有 Whisper 运行」看到的是哪一层？

常见三种「有 Whisper」，只有第三种才能出字幕：

| 你看到的 | 实际是 | 够不够生成字幕 |
|----------|--------|----------------|
| 构建日志 / `.tmp` 里下完 zip | 引擎构建成功 | 不够 |
| 安装包或 `win32-x64` 里有 `whisper-cli.exe` | 引擎已随应用 | **仍不够** |
| 字幕面板已选中/已存在 `ggml-*.bin`，且 `whisperModelPath` 有值 | 模型和引擎都齐 | 才够 |

界面「生成字幕」按钮的禁用条件是 `!whisperModelPath`（`SettingsPanel.tsx`），**不检查**引擎在不在。引擎会在点生成之后由主进程 `resolveWhisperExecutablePath()` **自动找捆绑的 whisper-cli**。所以：

- 引擎：**已经连通**（打包进 `electron/native/bin`，生成时自动解析）。  
- 模型：**没有连通**（不会去捆绑目录找 `.bin`，只认用户数据目录或你手选的文件）。  
- 面板里「选可执行文件」的回调已经接到 props，**界面没有入口**——设计上就是默认用捆绑引擎。

因此「有运行时还要下载」**不是误报，是当前产品把两件事拆开了**。使用指南 `R20260906-01/04` 也按这个拆法写了「首次要下载模型」。

## 3. 为什么总是下载不了？

下载的不是 `.tmp` 里那个 3.9 MB zip，而是：

```
https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-small.bin
```

落到：`%APPDATA%/Recordly/whisper/ggml-small.bin`（开发态是 `Recordly-dev`）。

失败的高概率原因见 `03`。和「引擎已经在」无关。
