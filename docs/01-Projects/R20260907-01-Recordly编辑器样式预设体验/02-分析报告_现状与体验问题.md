# 02 · 分析报告：现状与体验问题

> 结论以本仓库源码为准。调查日：2026-09-07。  
> 不改代码。本报告只回答：现在是什么、为什么怪、和大多数软件差在哪、改入口会碰到哪条旧约定。

---

## 一、这是什么功能（产品事实）

编辑器顶栏右侧、**导出按钮左边**，有一个书签 + 名称（未选中时显示「预设」）。点开后可以：

1. 把**当前编辑器一大包设置**另存为具名条目  
2. 点条目名称 → 整包套回当前课  
3. 点条目右侧 **X** → 从列表里删掉该条目  

存储键：`localStorage` / `recordly.editor.presets`（应用级，不是某一课文件里的样式表）。  
实现：`EditorPresetMenu.tsx` + `useEditorPresets.ts` + `useVideoEditorPresets.ts`。  
当前选中 id 只活在 React state 里，**不写入工程文件**；刷新后靠「设置指纹」再对上名字。

它保存的不是「导出档」，但入口贴着导出，所以看起来像导出预设。

## 二、入口：为什么会觉得「不该放在导出旁边」

### 2.1 界面位置

`EditorHeader.tsx` 右侧一排是：

```text
[ 预设菜单 ] | [ 导出菜单 ] [ 侧栏开关 ]
```

这是 `R20260906-14` D17 为了把顶栏收成「文字预设 + 文字导出」刻意放的。对 **VS Code 顶栏密度** 成立，对 **培训师心智** 不成立：

| 用户以为 | 实际 |
|----------|------|
| 这是导出用的预设（格式/清晰度/尺寸） | 套上会改壁纸、光标、缩放、画幅、摄像头框、字幕自动设置，以及导出编码/GIF，甚至本机 Whisper 路径 |
| 和「导出」是一套 | 和左边「画面 / 光标 / 摄像头」才是一套 |

导出菜单自己已经有质量、帧率、GIF 尺寸。再在旁边挂一个更重的「预设」，职责重叠、语义打架。

### 2.2 左边控制栏才是它的家

左轨默认停在 **画面（Scene）**，旁边面板里是边框、裁切、壁纸、缩放；光标、摄像头、字幕各有一页。  
各区块已经有「重置」——这是「改这一课的外观」的地方。

样式预设的用户目标是：**把这套外观存下来，下一节课再套。**  
所以它应该出现在「正在调外观」的旁边，而不是「马上要出片」的旁边。

左轨底部还有齿轮「设置」。那一页偏应用级（语言、关窗等）。样式预设可以进设置，但**每天剪课更常打开的是画面页**，不是齿轮页。

### 2.3 名字「预设」本身过载

仓库里至少四套东西都叫预设：

| 名称 | 在哪 | 是什么 |
|------|------|--------|
| 顶栏「预设」 | 导出左边 | 本题：一大包编辑器快照 |
| 运动预设 | 设置 → 动画 | 「专注 / 演示」光标运动配方 |
| 宽高比预设 | 画面/导出相关 | 16:9 等画幅 |
| GIF 尺寸预设 | 导出 | 原 / 中 / 大 |

使用指南也把「运动预设」写在设置里。培训师听到「预设」对不上同一件事。本题应改口为 **样式预设**。

## 三、交互：为什么「取消」会变成「删除」

### 3.1 界面只给了删除

列表每一行：左侧点名称 = 应用；右侧 **X** = `handleDeleteEditorPreset`。

- aria / tooltip 写的是「删除预设 {{name}}」
- 视觉是通用「关掉 / 去掉」的 X，不是垃圾桶
- **没有确认**
- 删的是当前条时，只把 `activePresetId` 置空，**已经套上去的设置原样留着**

所以：想取消选中的人会点 X；点完条目没了，画面还在。这是「看起来像取消、后果像删除、设置又不回退」的三重错位。

### 3.2 再点当前项不会取消

`handleApplyEditorPreset` 只做「再套一遍 + toast」。没有 toggle。  
列表里也没有「无 / 未使用预设 / 取消应用」。

### 3.3 「跳出预设」靠隐晦的指纹匹配

`useEditorPresets.ts` 里有一段自动对齐：

- 当前设置序列化后，若和某条快照完全一致 → 自动标成该条（打勾、顶栏显示名字）
- 一对不上 → `activePresetId = null`，顶栏变回「预设」

后果：

1. **没有「取消」这个动作。** 用户必须改任意被快照记住的项（壁纸、阴影、光标、导出质量、Whisper 路径……）才能摘掉名字。  
2. 改完只是显示上「没选中」，设置还是改过的那一版。  
3. 若改完碰巧和另一条「测试」完全一样，名字会跳到「测试」——像预设自己会换。  
4. 选中 id 不落盘，全靠指纹；两份预设若内容相同，会抢同一个勾。

这就是「明明是取消，为什么只能删除 / 只能去改某个地方」的根因：**产品没有「选中状态」这个一等概念，只有「设置像不像某条快照」。**

### 3.4 能力残缺（对照「完整、可理解」）

| 通用软件里常有 | 现状 |
|----------------|------|
| 不选任何项（无 / 默认） | 没有 |
| 取消应用，保留当前值 | 没有（只能改设置或删除条目） |
| 删除（确认） | 有删除，无确认，图标像取消 |
| 重命名 | 没有 |
| 套用后改过 → 更新原预设 / 另存 | 只有另存；不能更新；另存还禁重名 |
| 脏状态「已修改」 | 没有；一对不上就当没选中 |
| 恢复出厂 | 各设置区块已有 Reset，和预设无关，这点其实够用 |

## 四、快照范围：套一个「样子」会带走太多东西

`useVideoEditorPresets.ts` 的 snapshot 包括：

- 该带的：壁纸、阴影、模糊、缩放运动、光标、圆角、留白、摄像头**框**（不含视频源路径）、画幅  
- 不该跟「样式」走的：
  - 导出编码 / 后端 / 管线 / 质量 / 帧率 / 格式 / GIF
  - 裁切区域（这是**这一段录像**的构图，不是课件脸）
  - 自动字幕设置
  - 本机 `whisperExecutablePath` / `whisperModelPath`

培训师点「冲冲冲」可能只想换壁纸和光标，结果导出质量和本机字幕路径一起被覆盖。这既危险，也加重「它为什么在导出旁边」的误会。

## 五、对照大多数软件（习惯对齐）

| 软件 | 类似能力 | 放哪 | 取消 vs 删除 |
|------|----------|------|----------------|
| 剪映 / CapCut | 文字样式、滤镜收藏 | 左/右属性面板，跟正在调的东西在一起 | 不用某个样式 = 换回默认或取消选中；删除在管理里 |
| OBS | Profile / Scene Collection | 菜单「配置文件」，不在「开始录制 / 输出」按钮旁 | 切换档，不是 X 掉当前档；删除在管理对话框 |
| Word | 样式 | 开始选项卡「样式」，不是「打印 / 导出」旁 | 可以「清除格式」；删除样式在管理样式；二者分开 |
| VS Code | Profile | 齿轮 / 命令，不在 Run 按钮旁 | 切走当前配置 ≠ 删配置 |
| Camtasia / 多数剪辑 | Theme / 收藏效果 | 属性/媒体面板 | 应用是加法；垃圾桶是管理 |

共同习惯：

1. **可以没有当前具名项。**  
2. **应用、取消应用、删除是三个动词。**  
3. **入口跟「被保存的那些属性」在一起，不跟「出片/打印」在一起。**  
4. 改过之后承认「脏了」，让人更新或另存，而不是偷偷摘名或偷偷锁名。

OBS「永远有一个当前 Profile」不适合本题：培训师多数课只是「用默认脸，偶尔套一份收藏」，不是「每台机器必须挂一个配置文件」。

## 六、和旧方案的关联 / 冲突

| 来源 | 约定 | 本夹态度 |
|------|------|----------|
| `R20260906-14` D17 | 顶栏右：文字「预设」「导出」 | **冲突。** 密度可以保留「导出 + 侧栏开关」；预设主入口按本会话后说，迁走。不把整个顶栏重做一遍。 |
| `R20260906-14` 左轨 48 / 画面默认页 | 外观在左边调 | **一致。** 样式预设应落在这里。 |
| `R20260906-01` 使用指南 | 已写「右侧是预设、导出」 | 落地后同步改一句，并提示入口搬家。 |
| 运动预设 / GIF 尺寸 | 继续留在各自面板 | **共存。** 只改文案，避免都叫光秃秃的「预设」。 |
| 金路径 录→停→编→导 | 导出仍先选路再编码（14 已拍板） | **不碰。** |

没有「有了样式预设就没了导出」这种互斥。能共存：默认仍是「未使用样式预设 + 导出菜单里现调参数」。
