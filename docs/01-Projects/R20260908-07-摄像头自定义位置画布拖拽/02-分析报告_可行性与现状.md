# 分析报告：现状、根因、可行性

调查日：2026-09-08。只读。**未改产品代码。**

## 1. 结论摘要

| 问 | 答 |
|----|----|
| 画布拖位置能否做？ | **能。** 已有 `positionX/Y`（0–1）与 `getWebcamOverlayPosition`；预览气泡现为 `pointer-events: none`。 |
| 面板能否简化？ | **能，且应以收纳为主、删能力为辅。** 位置三套 UI 重叠是主因；素材常改却置顶展开。 |
| 有拖之后还要九宫格吗？ | **建议弱化、不删数据。** 九宫格适合「一键贴角」；日常主路径改为「自由摆 = 画布拖」。水平/垂直滑条可收进「精确」或仅保留数值回显。 |
| 风险 | 预览指针与缩放焦点/批注抢事件（中）；信息架构改动要补图贴，避免「控件消失」错觉。 |

| 2 | 随缩放变化 | reactToZoom | 中 | 无 tip，名长 |

## 3. 根因（为什么「看不懂」）

1. **同一意图三套入口**：九宫格、自定义开关、双轴滑条，都在回答「小窗在哪」。  
2. **低频顶在脸上**：素材路径+双按钮几乎每次录课不变，却占底部一整块。  
3. **发现性差**：`title`/图贴不齐；「随缩放」「边距」无一句人话。  
4. **自定义却不能拖**：模型已是自由坐标，交互仍停在滑条 → 体感「参数很多、手段很笨」。

## 4. 综合考量（原则对照）

| 原则 | 应用 |
|------|------|
| 不过度设计 | 不新面板、不新引擎；收纳 + 拖拽 |
| 功能完善 | 裁剪、替换/移除素材、贴角、外观滑条都保留通路 |
| 习惯对齐 | 画中画：剪映/OBS = 画布拖为主；贴角 = 快捷，不是主 UI |
| 用户视角 | 默认看见：显示、大小、裁剪、怎么摆、外观；高级/稀有收起 |
| 低风险 | 先改信息架构与 pointer；字段与导出几何不动 |

## 5. 「有拖之后还要不要别的位置控件？」

| 方案 | 利 | 弊 | 评判 |
|------|----|----|------|
| A 只留拖，删九宫格与滑条 | 最短 | 无障碍/精确数值、一键贴角没了 | ❌ 能力真丢 |
| B 拖为主；九宫格收成「快捷贴角」一行或菜单；滑条默认藏 | 主路径清，能力还在 | 多一次展开 | ✅ 推荐 |
| C 保留现状再加拖 | 改动小 | 更乱 | ❌ 违背诉求 |

**推荐 B：** 参数照记（`positionPreset` / X/Y）；UI 上「摆位 = 画布拖 + 一句提示」；九宫格降级为次要；水平垂直默认不展开。

## 6. 素材区

与「自定义位置」同型：**一行标题 + 开关/折叠钮**，默认 **收起**。展开后才见文件名、替换、移除。无素材时展开或顶栏轻提示「未关联摄像头素材」（施工时钉一句）。

## 7. 可行性与工作量（粗）

| 块 | 可否 | 量级 |
|----|------|------|
| 画布拖 + 反算函数 | 可 | 中（`VideoPlayback` + `webcamOverlay` 单测） |
| 位置区改版（收九宫格/藏滑条） | 可 | 小–中（`SettingsPanel`） |
| 素材折叠 | 可 | 小（本地 UI state 即可，不必持久化） |
| 图贴补齐 | 可 | 小（`data-tooltip` + i18n） |

不过度：本轮不做撤销大改、不做录制 HUD 拖拽。
