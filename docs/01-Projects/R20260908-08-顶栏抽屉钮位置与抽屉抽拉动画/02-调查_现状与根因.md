# 调查：现状与根因

调查日：2026-09-08。只读。**未改产品代码。**

## 1. 用户红框里的是什么

`EditorHeader.tsx` 左侧：`SidebarSimple` 按钮 → `onToggleSettingsPanel` → 翻转 `settingsPanelVisible`。  
紧挨着就是「文件(F)」「编辑(E)」菜单触发器。高约 24×24，图标 15px，和菜单文字同一条 **30px 应用内顶栏**。

它**不在** Windows 原生标题栏里（那一行是系统画的图标 +「Recordly 编辑器 …」）。用户说的「项目顶部 / 项目图标」在观感上常混指：

- 原生标题栏左侧应用图标，或  
- 应用内顶栏最左铬件。

## 2. Windows 窗口铬事实

`electron/windows.ts` → `createEditorWindow`：

- **非 Mac**：普通原生边框（无 `titleBarStyle: hidden`），标题栏由系统绘制。  
- **Mac**：`hiddenInset` + traffic lights，应用内顶栏左侧有 `pl-[76px]`。

因此：要在**真·标题栏里、紧贴系统图标**放 React 按钮，必须上 **无边框 / titleBarOverlay 自定义顶栏**（动 Electron 壳，面大、风险高）。

在**不改窗口框架**的前提下，能做到的最贴诉求是：把钮做成应用内顶栏**最左独立铬件**，与「文件/编辑」用分隔线拆开，尺寸加重到接近标题栏图标观感（约 18–20px 图标 / 28px 热区），而不是菜单项样式。

## 3. 「嘣」一声的根因

`EditorSidebar.tsx`：

```text
settingsPanelVisible ? <ProjectsPanel|ExtensionManager|SettingsPanel> : null
```

抽屉 DOM **整段挂载/卸载**，无宽度过渡。左轨 48px 一直在；280px 内容区瞬时出现/消失 → 预览被挤一下，体感就是「嘣」。

左轨图标已有 `motion` 做颜色/透明度；**抽屉面板本身没有** `AnimatePresence` / width 动画。

## 5. 可行性

| 项 | 结论 |
|----|------|
| 钮挪出菜单簇、加重铬件感 | **可**，只动 `EditorHeader` 布局/样式 |
| 真贴系统标题栏图标 | **可但重**：Windows 自定义 titleBar；本夹推荐作备选 |
| 抽拉动画 | **可**：抽屉保持挂载或 `AnimatePresence`，动画 `width` 0↔280 或 `x`，`overflow: hidden`；约 200ms ease |
| 风险 | 动画中测宽/预览 layout；折叠中途连点；无障碍 `aria-expanded` |

## 6. 综合判断

优先 **低风险双改**：

1. Header：钮离开菜单语义，做最左独立钮 + 分隔。  
2. Sidebar：抽屉开合宽度动画，禁止硬 `null` 闪切（内容可 `visibility`/`pointer-events` 在收合后关掉）。

自定义系统标题栏列为**可选增强**，默认不做。
