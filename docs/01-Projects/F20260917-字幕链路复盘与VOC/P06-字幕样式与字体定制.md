# 字幕样式与字体定制（ASS / SRT 差异与改法）

> 本文档为 `F20260917-字幕链路复盘与VOC` 的补充产出，来源：用户对 5 个模板成片提出的样式改进要求（字体不合适、不要黑边描白字、要纯白清秀字体）。
> 结论均基于本机实测，非推测。

---

## 一、ASS 与 SRT 的差异

| 维度 | SRT | ASS |
|:---|:---|:---|
| **本质** | 纯文本字幕 | 带样式与排版指令的字幕格式 |
| **能表达** | 序号、起止时间、文字 | 上述 + 字体、字号、颜色、描边、阴影、位置、对齐、**动画** |
| **样式来源** | **由播放器决定**（同一份 SRT 在不同播放器显示不同） | **写在文件里**，渲染器照做 |
| **本链路角色** | ASR 转写产物；文字优化环节的编辑对象 | 烧录用的中间产物（由 `subtitle-burn build` 生成） |

**关键点**：SRT 本身没有字体概念。烧录时 `subtitle-burn` 把 SRT 转成 ASS，**样式是模板写进 ASS 的**。因此「字体是否被修改」的答案是——**是，而且是必然的**：SRT 不含字体信息，字体一定来自模板。

### 每个模板在 ASS 里写的样式

| 模板 | 原字体 | 字重 | 描边 | 阴影 | 底框 |
|:---|:---|:---|:---|:---|:---|
| clean-bar | `Source Han Sans CN Bold` | 常规 | 4px 黑 | 0 | **有**（BorderStyle=3，半透明底栏） |
| slide-stack | `Source Han Sans CN Bold` | 加粗 | 5px 黑 | 3px | 无 |
| punch-pop | `Alibaba PuHuiTi B` | 加粗 | 6px 黑 | 4px | 无 |
| karaoke-glow | `Alibaba PuHuiTi B` | 加粗 | 6px 黑 | 3px | 无 |
| title-mask | `Alibaba PuHuiTi B` | 加粗 | 5px 黑 | 4px | 无 |

**原状态的三个问题**：① 5 个模板全在用黑描边 + 白字；② 4 个模板额外加了粗；③ 字体全是黑体（`Source Han Sans Bold` / `Alibaba PuHuiTi Bold`），没有更清秀的选择。

### 字体是怎么被挑出来的（不是硬编码）

模板只声明**字体角色**（`display` / `text` / `accent` / `latin`），由工具的候选链在本机挑第一个含汉字字形的字体，并**实测 libass 是否真接受这个名字**：

```json
{"display": {"family": "Alibaba PuHuiTi B",  "path": "...Alibaba-PuHuiTi-Bold.otf"},
 "text":    {"family": "Source Han Sans CN Bold", "path": "...SourceHanSansCN-Bold.otf"},
 "accent":  {"family": "HappyZcool-2016", ...},
 "latin":   {"family": "Source Sans Pro Black", ...}}
```

实测原因：libass 只按 `Fontname` 字符串匹配，同一个字体文件写「排版名」和写「nameID1」结果可能完全不同（前者静默回退）。所以换字体后**必须**验证是否真生效，不能只看名字写进去了。

## 二、目标样式与实现方式

### 目标
- 字体：清秀、不粗黑
- 颜色：**纯白**
- **不要黑边描白字**

### 实现路径（CLI 能力 + 后处理）

`subtitle-burn` 的 CLI **没有** `--outline` / `--shadow` 参数，只有：

| 参数 | 作用 |
|:---|:---|
| `--font` | 换字体 |
| `--no-bold` | 取消加粗 |
| `--color` / `--outline-color` | 改字色 / 改描边**颜色**（改不了宽度） |

描边与阴影由模板参数 `outline_ratio` / `shadow_ratio` 决定。文档 `D09` 提到过 `--template-file`，但 **`build` / `run` 子命令并未暴露该参数**（实测报 `No such option: --template-file`）。

因此采用 **build → 后处理 ASS → burn** 三步：

```powershell
# 1) build：换字体 + 去粗（秒级，不渲染视频）
subtitle-burn build "<遮罩底片>" --srt "<字幕>" --template clean-bar `
  --font 'Source Han Sans CN Regular' --no-bold --out-dir <工作区> --out-name raw_clean-bar

# 2) 后处理：把 ASS 的 Style 行 Outline 置 0、Shadow 置 3
.\set-ass-style.ps1 -In raw_clean-bar.ass -Out styled_clean-bar.ass -Outline 0 -Shadow 3 -Bold 0

# 3) burn：烧录
subtitle-burn burn "<遮罩底片>" --ass styled_clean-bar.ass --yes -o <输出目录> --out-name "纯白_clean-bar"
```

> **可用资产**：`assets/set-ass-style.ps1`（含字段序说明）+ `assets/字幕样式配置_纯白无描边.toml`（取值与依据）。

### ASS Style 行字段位置（改样式必须知道）

`Style:` 之后为逗号分隔的 23 段，**描边是第 16 段（索引）、阴影是第 17 段**：

```text
0 Name      1 Fontname   2 Fontsize    3 PrimaryColour  4 SecondaryColour
5 OutlineColour  6 BackColour  7 Bold   8 Italic   9 Underline
10 StrikeOut  11 ScaleX  12 ScaleY  13 Spacing  14 Angle
15 BorderStyle  16 Outline  17 Shadow  18 Alignment
19 MarginL  20 MarginR  21 MarginV  22 Encoding
```

**必须记录的一次踩坑**：我第一次用正则 `(BorderStyle,\d+,\d+),(\d+),(\d+),` 去改，结果匹配到了 `Bold,Italic,Underline` 段——**改的是 Italic/Underline，描边原封不动**。三个「变体」渲染出来像素完全一致（亮像素 18809 vs 18809，差异行数 0），才发现改错了。按逗号切分后取固定索引才可靠。

## 三、字体选型与实测对比

本机 52 个 CJK 字体家族中挑出的清秀候选（均已验证 libass 接受）：

| 字体 | 观感 | 结论 |
|:---|:---|:---|
| **Source Han Sans CN Regular** | 最清秀，笔画均衡，Regular 字重 | **本次选用** |
| Noto Sans SC | 略粗，现代感强 | 备选 |
| Microsoft YaHei Light | 纤细，小字号偏弱 | 备选 |
| DengXian Light | 很细，长句易糊 | 不推荐 |
| OPPOSans H | 偏粗 | 不推荐 |

## 四、描边与阴影的实测取舍

### 三版对比（clean-bar，1.5s）

| 版本 | 观感 | 结论 |
|:---|:---|:---|
| 4px 黑描边（原状） | 清晰，但正是用户不要的黑边 | 放弃 |
| 纯白 + 无描边 + 无阴影 | 最清秀，但浅色背景上发虚 | 需兜底 |
| **纯白 + 无描边 + Shadow=3** | 无黑边、纯白字，可读性有兜底 | **采用** |

对比图：`fonttest\描边三版对比.png`

### 阴影强度四档（punch-pop，浅背景）

| Shadow | 观感 |
|:---|:---|
| 0 | 浅背景上发虚 |
| **3** | 轻微立体感，浅背景也可读 —— **采用** |
| 4 | 更稳，字边缘开始显重 |
| 6 | 明显变粗，接近描边观感 |

对比图：`fonttest\阴影强度四档_punchpop.png`

### 必须知道的边界（实测）

1. **去掉描边后，可读性完全取决于背景明暗**：字幕落在深色衣服上时，无描边也清晰；落在浅色墙面上时，靠 Shadow=3 兜底才读得清。
2. **一次性说清一个易误判的点**：我一度据窄幅裁切认为「除 clean-bar 外 4 个模板白字都读不清」，抽整帧复核后发现是**裁切窗口取到了浅墙、没取到文字**造成的误判。实际 5 个模板在深色背景上均正常。**结论必须基于整帧，不能基于局部裁切。**
3. **clean-bar 最耐读的真正原因**：它用 `BorderStyle=3`——**半透明底栏**，在文字后方起衬底作用。这是它区别于其他 4 个模板的关键。
4. **title-mask 的固有短板**：中心定位使字幕落在浅色墙面与人物面部之间，是 5 个模板里语义可读性最差的一个。这与描边方案无关，换样式解决不了。

## 五、VOC 建议（回写 subtitle-burn-master）

| # | 建议 | 优先级 | 理由 |
|:---|:---|:---|:---|
| 1 | `build` / `run` 增加 `--outline <px>` 与 `--shadow <px>` | **高** | 当前改描边/阴影必须后处理 ASS 文件，属绕过 CLI；把用户逼到手工改字幕文件是不合理的 |
| 2 | `run` / `build` 暴露 `--template-file`（D09 已声明支持，实际未暴露） | **高** | 文档与实现不一致，用户按文档写会失败 |
| 3 | 模板文档补充每个模板的 `outline_ratio` / `shadow_ratio` 实际像素值 | 中 | 换分辨率后比例换算不直观（如 clean-bar 0.042×1280≈4px） |
| 4 | 增加一个「纯白无描边」预设模板 | 中 | 本次需求属常见审美取向（剪映用户习惯），但现有 5 个模板无此选项 |
| 5 | 字体角色文档补充「Regular 字重」候选 | 低 | 现有候选链偏向 Bold，想要清秀字体只能靠 `--font` 点名 |
