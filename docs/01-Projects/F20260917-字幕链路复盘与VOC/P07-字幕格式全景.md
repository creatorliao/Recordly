# 字幕格式全景与实战选用（SRT / ASS 及其以外）

> 本文档为 `F20260917-字幕链路复盘与VOC` 的补充产出。
> 所有结论均含本机实测证据（subtitle-burn 0.1.0 / subgen 0.2.0 / ffmpeg 9.0.1）。
> 用途：建立对字幕格式的完整认知，避免「只知道 SRT 和 ASS」造成的选型与踩坑。

---

## 一、先建立一个总览：字幕分四大类

字幕格式不是「一堆并列的选项」，而是按**承载信息的方式**分成四类。理解这个分类，后面所有格式都能归位。

| 类别 | 本质 | 典型格式 | 关键特征 |
|:---|:---|:---|:---|
| **① 纯文本** | 只有文字与时间轴 | SRT、WebVTT、LRC、MicroDVD | 样式由播放器决定；跨平台最稳 |
| **② 文本 + 样式/排版** | 文字 + 字体、颜色、位置、动画 | **ASS**、SSA、TTML/DFXP | 样式写在文件里；能做动画 |
| **③ 图形（位图）** | 每个字幕是**图片** | PGS、VobSub（.sub/.idx）、DVD Sub | 字体已烘焙，不依赖系统字体；不可编辑文字 |
| **④ 工程 / 承载** | 用于编辑或封装，不是最终格式 | Aegisub 工程、MKV 内嵌轨、MP4 mov_text | 服务于制作流程或分发 |

**一句话记住分类的意义**：格式的能力上限在类别上就已确定。纯文本格式再怎么折腾也做不出动画；位图格式再清晰也不能改字。

## 二、格式逐个详解

### ① 纯文本类

#### SRT（SubRip）
```text
1
00:00:00,000 --> 00:00:04,280
今年红杉的这篇报告里有一个框架让我反复看了很多遍
```
- **优点**：最通用。几乎所有播放器、剪辑软件、平台都吃。手改方便。
- **缺点**：无样式。同一份 SRT 在 VLC、剪映、网页播放器里长得都不一样。
- **实测**：本链路 ASR 直接产物（163 条），也是文字优化环节的编辑对象。
- **注意**：`subgen` 为防 Windows 中文乱码会**写 UTF-8 BOM**（可用 `--no-bom` 关掉）。BOM 会让某些工具判为格式不同——本次 `subtitle-optimize verify` 就因 BOM 丢失判红。

#### WebVTT（.vtt）
```text
WEBVTT

00:00.000 --> 00:04.280
今年红杉的这篇报告里有一个框架让我反复看了很多遍
```
- **优点**：W3C 标准，HTML5 `<track>` 原生支持。支持 cue 名称、样式类、定位（`line:`/`position:`）、说话人标记。
- **缺点**：比 SRT 复杂，老播放器支持不齐。
- **实测**：`ffmpeg -i a.srt out.vtt` 成功，时间码自动转成 `00:00.000` 格式（**注意不是 SRT 的逗号写法**）。
- **用在哪**：网页视频、在线课程、YouTube 类平台。

#### LRC
```text
[00:00.00]今年红杉的这篇报告里有一个框架让我反复看了很多遍
[00:04.28]它说的是AI创业者的价值进阶一共有三段
```
- **优点**：音乐播放器与卡拉OK通用，极简。
- **缺点**：**只有行级时间、没有结束时间**（靠下一行推算）；不适合长句字幕。
- **实测**：`ffmpeg -i a.srt out.lrc` 成功。
- **用在哪**：歌曲歌词、播客章节。

#### MicroDVD（.sub）
- **特征**：时间轴用**帧号**而非时间码 → **强依赖帧率**，帧率判断错就整体错位。
- **实测**：ffmpeg **只有解码器，没有输出 muxer**，无法产出。
- **用在哪**：老式 DVD 时代的遗留格式，现在基本只在转换旧资源时遇到。

### ② 文本 + 样式类

#### ASS / SSA（本链路的核心）
```text
[Script Info]
PlayResX: 720
PlayResY: 1280

[V4+ Styles]
Format: Name, Fontname, Fontsize, PrimaryColour, SecondaryColour, OutlineColour,
        BackColour, Bold, Italic, Underline, StrikeOut, ScaleX, ScaleY, Spacing,
        Angle, BorderStyle, Outline, Shadow, Alignment, MarginL, MarginR, MarginV, Encoding
Style: SB_clean-bar,Source Han Sans CN Regular,43,&H00FFFFFF,&H00FFFFFF,&H6E180F0B,
       &H80000000,0,0,0,0,100,100,0,0,3,0,3,2,36,36,96,1

[Events]
Format: Layer, Start, End, Style, Name, MarginL, MarginR, MarginV, Effect, Text
Dialogue: 0,0:00:00.00,0:00:04.28,SB_clean-bar,,0,0,0,,{\an2\pos(360,1127.24)\fad(200,140)}今年红杉的这篇报告
```

- **ASS 与 SSA 的关系**：SSA 是前身（Sub Station Alpha），ASS 是增强版（Advanced SSA，标记为 `V4+ Styles`）。ASS 向下兼容 SSA。
- **为什么它能力强**：它是**带排版指令**的格式。上面那条 `Dialogue` 里 `{\an2\pos(360,1127.24)\fad(200,140)}` 就是指令——对齐方式、绝对坐标、淡入淡出。
- **能做的**：字体/字号/颜色/描边/阴影/描边样式（含底框）、绝对或九宫格定位、旋转缩放、逐字高亮（卡拉OK）、入场动画（弹入、滑动、擦除）、图层叠放。
- **不能做的**（实测边界）：任意缓动曲线（`\t` 只有幂曲线）；抖动/震动（`\t(\pos)` 在 libass 里静默无效）；非矩形遮罩动画；贴纸/粒子/emoji 素材；渐变色/混合模式。
- **Style 行字段位置**（改样式必看，逗号分隔 23 段）：
  ```text
  0 Name      1 Fontname   2 Fontsize    3 PrimaryColour  4 SecondaryColour
  5 OutlineColour  6 BackColour  7 Bold   8 Italic   9 Underline
  10 StrikeOut  11 ScaleX  12 ScaleY  13 Spacing  14 Angle
  15 BorderStyle  16 Outline  17 Shadow  18 Alignment
  19 MarginL  20 MarginR  21 MarginV  22 Encoding
  ```
  **16 是描边宽度、17 是阴影宽度**。`BorderStyle`：`1`=描边+阴影，`3`=不透明底框（clean-bar 用的就是 3）。
- **本链路角色**：`subtitle-burn build` 生成的**中间产物**，由它烧成硬字幕。

#### TTML / DFXP（.ttml / .xml）
- **特征**：XML 结构，W3C/广播标准，Netflix 与广电系常用。支持精细样式与区域布局。
- **实测**：`ffmpeg -i a.srt out.ttml` 成功。
- **用在哪**：广播、流媒体平台的合规交付。

### ③ 图形（位图）类

#### PGS（.sup，HDMV PGS）
- **特征**：蓝光字幕。每帧字幕是**位图**，字体已烘焙进去。
- **优点**：显示效果与片方制作完全一致，不依赖播放端字体。
- **缺点**：**不能改文字、不能换字体**；文件大；需要 OCR 才能转成文本。
- **实测**：ffmpeg 有解码器（`hdmv_pgs_subtitle` / `pgssub`），**无编码器**。
- **用在哪**：蓝光原盘、部分高清下载资源。

#### VobSub（.sub + .idx 成对）
- **特征**：DVD 字幕。`.idx` 是索引与调色板，`.sub` 是位图数据，**两个文件必须成对**。
- **实测**：ffmpeg 能解码（`dvd_subtitle` / `dvdsub`），也标称有编码器。
- **用在哪**：DVD 提取。

#### 常见困惑：`.sub` 有两个完全不同的东西
| 后缀 | 实际格式 | 时间轴单位 |
|:---|:---|:---|
| `.sub`（配 `.idx`） | VobSub **位图** | 时间码 |
| `.sub`（单独） | MicroDVD **文本** | **帧号** |

拿到 `.sub` 先看有没有配套 `.idx`——这是最快的判别方法。

### ④ 工程 / 承载类

- **MKV 内嵌字幕轨**：MKV 是**最宽容**的容器，能装 ASS/SSA、SRT、VTT、PGS、VobSub 任意组合，可多语言多轨。
- **MP4 内嵌字幕**：**只能用 `mov_text`**。这是本次实测最硬的一条限制（见下节）。
- **Aegisub 工程文件（.ass 直接编辑）**：Aegisub 是 ASS 的事实标准编辑器，工程即 ASS。

## 三、软字幕 vs 硬字幕（本次实测的核心结论）

这是字幕工程里**最重要的一个区分**，也是本次踩到的实际问题。

| | 软字幕（Softsub） | 硬字幕（Hardsub） |
|:---|:---|:---|
| 存在形式 | 视频里的**字幕轨**，与画面分离 | **烧进画面像素**，与画面一体 |
| 能否关闭 | 能（播放器里切换/关闭） | 不能 |
| 能否改字 | 能（改字幕文件即可） | 不能（要重编码） |
| 样式保真 | 取决于播放器 | **完全一致** |
| 平台兼容 | 有些平台不显示内嵌轨 | **任何平台都显示** |
| 本链路 | 本次**未做** | `subtitle-burn` 做的就是硬字幕 |

### 实测证据

**MP4 装不了 ASS**：
```bash
ffmpeg -i video.mp4 -i styled.ass -map 0:v -map 0:a -map 1:0 -c:v copy -c:a copy -c:s ass out.mp4
# → Could not find tag for codec ass in stream #2, codec not currently supported in container
```

**MP4 能装 mov_text（SRT 系）**：
```bash
ffmpeg -i video.mp4 -i subs.srt -map 0:v -map 0:a -map 1:0 -c:v copy -c:a copy -c:s mov_text out.mp4
# → 0,h264,video  1,aac,audio  2,mov_text,subtitle   ✅ 成功
```

**结论**：想在 MP4 里放**可关闭的软字幕**，只能用 `mov_text`，而且**它会丢掉 ASS 的全部样式**（字体、描边、动画都没了）。想保留 ASS 样式又要是软字幕，**必须换 MKV 容器**。

> **这条对本次任务的意义**：用户要做「带样式的字幕」，且要发给别人看。硬字幕是正确选择——不管对方用什么播放器、传什么平台，显示效果都一致。软字幕做不到这个保证，且 MP4 根本装不了 ASS。

## 四、格式转换关系与降级规则

### 转换的可行性（箭头方向代表「可无损」还是「有损」）

```text
ASS ──→ SRT      有损：丢样式、丢动画、丢定位；只留文字+时间轴
ASS ──→ VTT      有损：同上
SRT ──→ ASS      无损升级：SRT 信息是 ASS 的子集
SRT ──→ VTT      基本无损
SRT ──→ LRC      有损：丢结束时间
VTT ──→ SRT      基本无损（丢掉 VTT 特有样式）
位图 → 文本      必须 OCR（如 PGS → SRT）
文本 → 位图      需渲染（如 ASS → PGS）
```

### 实测：ASS → SRT 会留下标签残留

```bash
ffmpeg -i styled_clean-bar.ass out.srt
```
产物：
```text
1
00:00:00,000 --> 00:00:04,280
<font face="Source Han Sans CN Regular" size="43">{\an2}今年红杉的这篇报告</font>
```

**意外发现**：ffmpeg 没有干净地剥离样式，而是把它转成了 `<font>` 标签，**而且 ASS 的覆盖指令 `{\an2}` 原样留在了文本里**。

**实践意义**：ASS → SRT 之后**必须人工检查或清洗**，不能直接当纯文本用。要干净转换，应回到上游 SRT，而不是从 ASS 降级。

### ffmpeg 的格式能力边界（实测）

| 格式 | 解码 | 编码/输出 | 实测结果 |
|:---|:---:|:---:|:---|
| srt / subrip | ✅ | ✅ | 可用 |
| ass / ssa | ✅ | ✅ | 可用 |
| webvtt | ✅ | ✅ | 可用 |
| mov_text | ✅ | ✅ | 可用（MP4 软字幕专用） |
| lrc | — | ✅ | 实测可生成 |
| ttml | — | ✅ | 实测可生成 |
| dvb_subtitle | ✅ | ✅ | 标称有 |
| dvd_subtitle | ✅ | ✅ | 标称有 |
| hdmv_pgs_subtitle | ✅ | ❌ | 只能读，不能写 |
| hdmv_text_subtitle | ✅ | ❌ | 只能读 |
| sami / scc / stl / jacosub / microdvd / mpl2 / pjs / realtext / subviewer / vplayer | ✅ | ❌ | **只有解码器，无输出 muxer** |

> 最后一行是常见误解来源：这些格式「ffmpeg 能识别」，但**不代表能生成**。实测报 `Unable to choose an output format`。

### 渲染：ffmpeg 的两个字幕滤镜（容易混）

| 滤镜 | 接受格式 | 说明 |
|:---|:---|:---|
| `ass` | **仅 ASS/SSA** | 直接按文件里的样式渲染 |
| `subtitles` | **多种**（SRT/VTT/ASS…） | 内部转成 ASS 后交给 libass |

**关键点**：`subtitle-burn` 用的是 `ass` 滤镜。这意味着**喂给它的必须是 ASS**——所以流程里才有「build 先生成 ASS」这一步。若想直接用 SRT，技术上要用 `subtitles` 滤镜，但那样样式就完全不受控了。

## 五、选型速查：什么场景用什么

| 你的目标 | 推荐格式 | 理由 |
|:---|:---|:---|
| 交给剪辑软件、改字、最保险 | **SRT** | 通用性最好，出问题最少 |
| 要「好看的字幕」，带样式/动画，烧进画面 | **ASS** | 唯一能表达描边/定位/动画的通用文本格式 |
| 网页视频、在线课程 | **WebVTT** | HTML5 原生支持 |
| 歌曲歌词 | **LRC** | 播放器通用 |
| 给平台/广电交付 | **TTML** | 合规标准 |
| 要与蓝光原盘一致的显示 | **PGS** | 位图，效果保真；但不可改字 |
| MP4 里放可关闭的字幕 | **mov_text** | MP4 的**唯一**选择 |
| MKV 里放任意样式软字幕 | **ASS / PGS / SRT** 均可 | MKV 容器最宽容 |
| 最终发布给不确定的观众 | **硬字幕（烧录）** | 不依赖对方环境，样式 100% 保真 |

## 六、常见误区（含本次实测到的）

| 误区 | 事实 |
|:---|:---|
| 「字幕格式就是 SRT 和 ASS」 | 至少四类十余种；还有位图类（PGS/VobSub）与纯文本类（VTT/LRC/TTML） |
| 「MP4 能装 ASS 软字幕」 | **不能**。实测报 `codec not currently supported in container`。MP4 只能 `mov_text` |
| 「ffmpeg 认识的格式就能生成」 | 不少格式**只有解码器没有 muxer**（sami/scc/stl/jacosub/microdvd…），生成会失败 |
| 「ASS 转 SRT 是干净的纯文本」 | 实测会留下 `<font face=...>` 标签与 `{\an2}` 指令，**需清洗** |
| 「.sub 就是一种格式」 | 有两种：VobSub（位图，配 .idx）与 MicroDVD（文本，用帧号） |
| 「软字幕和硬字幕只差能不能关」 | 还差样式保真与平台兼容。软字幕样式由播放器决定，平台可能不显示内嵌轨 |
| 「SRT 有字体信息」 | 没有。所以「烧录时字体被改了」是必然——字体只能来自烧录模板 |
| 「改了 ASS 的 Fontname 就一定生效」 | libass 按字符串匹配，写错拼写会**静默回退**到默认字体（文档 D09 有实测对照） |

## 七、本工具链的字幕能力边界

| 工具 | 能力 | 实测 |
|:---|:---|:---|
| `subgen transcribe` | 产出字幕：`--format srt,txt`（帮助文本被截断，实测 srt/txt 可用） | 163 条，缓存命中 0.56s |
| `subgen check` | 字幕质量体检（不产文件） | 0 错误 / 19 提示 |
| `subtitle-optimize` | **只改文字、不动时间线**，产出 SRT；`verify` 四项硬门比对 | 四项全绿，改动 10 条 |
| `subtitle-burn build` | **只生成 ASS**（秒级、零风险） | 调样式时最省时间的一步 |
| `subtitle-burn burn` | **只接受 ASS**，烧成硬字幕 | `--ass` 为必填 |
| `subtitle-burn run` | 一站式：转写 → build → burn → verify | 8/8 通过 |
| `subtitle-burn check-source` | 检测源片**自带硬字幕**（不检测台标） | high 置信检出 |

**两个值得记住的边界**：
1. 本链路**不产出软字幕**。`subtitle-burn` 只做硬字幕。若需要 MP4 软字幕，得自己用 `ffmpeg … -c:s mov_text` 做，且只能用 SRT 系（会丢 ASS 样式）。
2. **CLI 改不了描边与阴影**。只有 `--font` / `--no-bold` / `--color` / `--outline-color`（只改颜色不改宽度）。要改宽度得后处理 ASS 的 Style 行（见 `assets/set-ass-style.ps1`）。

## 附录：本文档的实测命令清单

```bash
# 查看 ffmpeg 支持的字幕编解码器
ffmpeg -hide_banner -codecs | findstr subtitle

# 查看字幕滤镜
ffmpeg -hide_banner -filters | findstr /R "ass subtitles"

# MP4 装 ASS（预期失败）
ffmpeg -i video.mp4 -i styled.ass -map 1:0 -c:v copy -c:a copy -c:s ass out.mp4

# MP4 装 mov_text 软字幕（成功）
ffmpeg -i video.mp4 -i subs.srt -map 0:v -map 0:a -map 1:0 -c:v copy -c:a copy -c:s mov_text out.mp4

# ASS 降级为 SRT（注意标签残留）
ffmpeg -i styled.ass out.srt

# SRT 转 WebVTT
ffmpeg -i in.srt out.vtt

# 查看视频里的字幕轨
ffprobe -v error -show_entries stream=index,codec_type,codec_name -of csv=p=0 video.mp4

# 烧录硬字幕（本链路主命令）
subtitle-burn run "<视频>" --srt "<字幕>" --template clean-bar --yes --json -o "<输出目录>"
```
