# P04-B-最佳实践_源片硬字幕与台标处理规程

## 一、背景与场景

我们接到的任务很普通：一段竖屏口播视频，转出字幕、改改错字、烧进画面。设备是现成的，三个 CLI 都在 PATH 上，转写模型早就装好了，连素材都在本机。按理说这是条顺路的活。

问题出在一个没人想到的地方：**源片自己已经烧死了中英双语字幕。** 中文字幕压在画面 76% 高度，英文紧跟其下，两行都是硬字幕，跟画面焊在一起。如果按原计划直接把新字幕烧到底部，结果就是两条字幕上下叠着——而 ffmpeg 全程不会报任何错，只有人眼能发现。

同一段画面右上角还有个 B 站台标（`Penny破圈观察 bilibili`）。用户原本以为所谓的「水印」是 ASR 认错的字，只存在于字幕文本里，所以一开始选的处理方式是「不动画面」。实测推翻了这一点：文字里干干净净，水印在画面上。

于是这条任务多出两个原本不存在的环节：**把旧字幕盖掉，把台标抹掉。** 这两个环节后面的每一步——字幕落位、模板选择、成片验收——都受它们牵制。本文记录的就是这两个环节怎么做对、以及做错时会付出什么代价。

## 二、核心原则

**坐标靠扫，不靠看。** 旧字幕在单行与双行时位置不同，台标的左右边界也不像看上去那么好估。抽一两帧目测，得到的数一定偏。

**用模糊，不用色块。** 拿半透明黑块盖台标，会透出字影，深色方块压在浅色墙上像贴了张纸。局部模糊是往背景纹理里融，看不出被处理过。

**固定区域要配时间门控。** 画面上的元素不是一直在。按固定区域无脑处理，早晚会切到别的内容。

**画面层定型了再烧字幕。** 遮罩没验收通过就往下走，等于给自己留一次完整重跑。

**验收要覆盖要素出现的窗口。** 只抽正常时段的帧，等于没验。

## 三、操作流程

### 步骤 1：判断源片干不干净

- **要领**：这一步必须在拿到素材的第一时间做，和 `ffprobe` 看规格一起，而不是等准备烧录时再补。
- **关键行为**：
  ```powershell
  subtitle-burn check-source "<源片>" --json
  ```
  看 `existing_subtitles` 与 `confidence`。high 置信就要当回事。
- **完成标志**：明确知道源片有没有自带硬字幕、台标候选在哪个区域。有则继续步骤 2；没有则跳过整个画面层。

> 这一步的判断是整条路径的分叉点。源片干净时，画面层完全不需要，任务就是原来的三步。

### 步骤 2：全片扫描，量准旧字幕的纵向极值

- **要领**：不要按 detector 的 `y0_ratio` 直接换算，它会把中英两行当成两条独立带。也不要用纯亮度阈值——白衬衫和手都会被算进去。
- **关键行为**：按 2fps 抽全片灰度帧，逐行算**纵向梯度**（字幕的黑描边会造成强梯度），统计每行强梯度像素数：

  ```python
  import subprocess, numpy as np
  src = r"<源片>"
  W, H = 720, 1280
  p = subprocess.run(["ffmpeg","-v","error","-i",src,"-vf","fps=2,scale=720:1280",
                      "-pix_fmt","gray","-f","rawvideo","-"], capture_output=True)
  buf = np.frombuffer(p.stdout, dtype=np.uint8)
  n = buf.size // (W*H)
  frames = buf[:n*W*H].reshape(n, H, W).astype(np.float32)
  tops, bots = [], []
  for f in frames:
      reg = f[900:1280, :]                  # 只扫画面下 40%
      g = np.abs(np.diff(reg, axis=0))      # 纵向梯度：描边处极强
      strength = (g > 60).sum(axis=1)       # 每行强梯度像素数
      idx = np.where(strength > 90)[0]
      if len(idx):
          tops.append(900+int(idx.min())); bots.append(901+int(idx.max()))
  tops, bots = np.array(tops), np.array(bots)
  print("顶部 p1=%d 中位=%d" % (np.percentile(tops,1), np.median(tops)))
  print("底部 p99=%d max=%d" % (np.percentile(bots,99), bots.max()))
  ```

- **完成标志**：`p1` 与中位数接近说明结果稳定（不是噪声）。本片实测 **y=976..1086**，p1=976。

> 本机注意：`python.exe` 若指向 `WindowsApps` 下的占位符会静默失败，用 `C:\Users\creator\AppData\Local\Programs\Python\Python312\python.exe`。需要 `numpy`。

### 步骤 3：放大读刻度，量准台标边界

- **要领**：台标的左边界最容易估错。本片估了 x≈548，实测从 **x=348** 开始，差了两百像素，直接导致第一版遮罩完全没盖住台标主体。
- **关键行为**：裁出台标区域并放大，画格线读坐标：

  ```powershell
  ffmpeg -v error -ss 30 -i "<源片>" -frames:v 1 `
    -vf "crop=400:90:300:0,scale=1200:270:flags=neighbor,drawgrid=w=1200:h=30:t=2:c=red@0.9" `
    -y "wm_zoom.png"
  ```
  裁剪起点 + 缩放倍数换算回原图坐标。本片实测 **x=348..690, y=30..60**。
- **完成标志**：有了台标的四个边界值，且已用放大图核对过。

### 步骤 4：找出动态元素的出现窗口

- **要领**：固定区域处理会切到别的内容。本片台标区右上方有条英文内容条，只在 4 个短窗口出现，却正好压在台标模糊带上。
- **关键行为**：按下区域深色像素占比扫描全片，把「内容条出现」的时段列出来：

  ```python
  # 顶部 200px 内，某行深色像素(<70)占比 > 55% 视为内容条
  for i, f in enumerate(frames):
      reg = f[0:200, :]
      darkfrac = (reg < 70).mean(axis=1)
      idx = np.where(darkfrac > 0.55)[0]
      if len(idx) > 3:
          print("帧 %d 内容条 y %d..%d" % (i, idx.min(), idx.max()))
  ```
  本片结果：**4 个区间，累计约 14s / 314s**（1.0–4.5s、19–23s、235.5s、276–280s）。
- **完成标志**：拿到所有需要「临时关闭遮罩」的时间窗，各留 0.5s 余量。

### 步骤 5：渲染遮罩底片

- **要领**：先 `split` 成两路，各自 `crop` + `boxblur`，再 `overlay` 回原位。台标那一路挂 `enable` 门控。
- **关键行为**：
  ```powershell
  $win = "between(t,0.5,5.0)+between(t,18.5,23.5)+between(t,275.5,280.5)"
  $fc = "split=2[b][w];" +
        "[b]crop=720:148:0:958,boxblur=8:2[bb];" +        # 旧字幕带
        "[w]crop=368:56:336:24,boxblur=12:2[wm];" +       # 台标区
        "[0:v][bb]overlay=0:958[t];" +
        "[t][wm]overlay=336:24:enable='not($win)'[out]"

  ffmpeg -v error -i "<源片>" -filter_complex $fc -map "[out]" -map 0:a `
    -c:v libx264 -preset veryfast -crf 20 -pix_fmt yuv420p -c:a copy -y "<遮罩底片>"
  ```
  裁剪区的 y 起点 = 实测顶部 − 余量。本片实测顶 976，取 958（上留 18px），高度 148。
- **完成标志**：底片生成成功，且**尚未**烧任何字幕。

### 步骤 6：按要素窗口验收

- **要领**：这是最容易省掉、也最不该省的一步。只抽正常时段，冲突时段的问题就查不出来。
- **关键行为**：正常时段与冲突时段各抽帧放大：
  ```powershell
  # 冲突时段（内容条出现）：确认文字完整
  ffmpeg -v error -ss 20 -i "<遮罩底片>" -frames:v 1 `
    -vf "crop=720:120:0:0,scale=1440:240:flags=neighbor" -y "chk_box.png"
  # 正常时段：确认台标已不可读
  ffmpeg -v error -ss 30 -i "<遮罩底片>" -frames:v 1 `
    -vf "crop=400:90:300:0,scale=1200:270:flags=neighbor" -y "chk_norm.png"
  # 旧字幕带：确认糊掉且无残影
  ffmpeg -v error -ss 3.5 -i "<遮罩底片>" -frames:v 1 `
    -vf "crop=720:200:0:900,scale=1440:400:flags=neighbor" -y "chk_sub.png"
  ```
- **完成标志**：三类样本都通过；旧字幕读不出、台标读不出、动态内容文字完整。

### 步骤 7：拿遮罩底片当输入继续往下烧字幕

- **要领**：此后所有转写、优化、烧录都基于遮罩底片，不再碰原片。
- **关键行为**：
  ```powershell
  subtitle-burn plan "<遮罩底片>" --srt "<字幕>" --template <模板> --json
  subtitle-burn run  "<遮罩底片>" --srt "<字幕>" --template <模板> --yes --json -o "<输出目录>"
  ```
- **完成标志**：`check-source` 在遮罩底片上返回 `existing_subtitles: false`——这是遮罩生效的反证。本片实测即如此，且成片校验 8/8 通过。

## 四、关键话术/提示词/工具

**源片探测（合并成一次）**
```powershell
# 环境
foreach($c in @('subgen','subtitle-optimize','subtitle-burn','ffmpeg','uv')){
  $cmd = Get-Command $c -ErrorAction SilentlyContinue
  if($cmd){ "[OK]   $c  $($cmd.Source)" } else { "[MISS] $c" }
}
# 规格
ffprobe -v error -show_entries format=duration,size,bit_rate `
  -show_entries stream=index,codec_type,codec_name,width,height `
  -of default=noprint_wrappers=1 "<源片>"
# 洁净度
subtitle-burn check-source "<源片>" --json
```

**遮罩定稿参数（本片实测值，换素材须重新测量）**

| 项 | 值 | 依据 |
|:---|:---|:---|
| 旧字幕带遮罩 | `crop=720:148:0:958` | 实测 976..1086 + 上下余量 |
| 旧字幕模糊 | `boxblur=8:2` | 糊掉字且不过度 |
| 台标遮罩 | `crop=368:56:336:24` | 实测 x348..690 / y30..60 + 余量 |
| 台标模糊 | `boxblur=12:2` | **色度半径必须 <16** |
| 时间门控 | `enable='not(between(t,0.5,5.0)+between(t,18.5,23.5)+between(t,275.5,280.5))'` | 内容条 4 窗口 + 0.5s 余量 |
| 编码 | `libx264 -preset veryfast -crf 20 -pix_fmt yuv420p -c:a copy` | 与烧录阶段对齐 |

**实测参考数据（本片）**

| 项 | 值 |
|:---|:---|
| 源片 | 720×1280 / 314.047s / h264+aac / **无字幕轨**（硬字幕烧在画面里） |
| 旧字幕纵向极值 | y=976..1086（全片 628 帧梯度扫描，p1=976） |
| 台标 | x=348..690, y=30..60 |
| 内容条窗口 | 4 个，累计约 14s / 314s |

## 五、常见误区

| 误区 | 正确做法 |
|:---|:---|
| 用 `ffprobe` 看没有字幕流，就断定源片干净 | 硬字幕是烧在画面里的，`ffprobe` 看不见。必须跑 `check-source` 并抽帧目视 |
| 拿半透明色块盖台标 | 用局部 `boxblur`。色块会透出字影，浅色背景上还会显出一个深色方块 |
| 按 detector 的 `y0_ratio` 直接换算遮罩范围 | detector 把中英两行当两条带，且只给"疑似"。用全片梯度扫描拿极值 |
| 用亮度阈值找字幕 | 白衬衫、手、浅色墙都会被算进去，结果明显偏大。用描边造成的纵向梯度 |
| 只抽一个时间点量字幕位置 | 单行与双行时字幕块位置不同（本片实测顶 976 vs 1000），必须全片扫 |
| `boxblur` 色度半径写 16 | 上限是 **<16**（写 16 会被 ffmpeg 拒绝并产出损坏文件，报 `moov atom not found`） |
| 遮罩只验收正常时段 | 按**要素出现窗口**验收，冲突时段单独抽帧 |
| 固定遮罩不挂 `enable` | 会切到动态内容。先扫出内容条窗口，再挂时间门控 |
| 遮罩刚能看就往下烧字幕 | 画面层定型并验收通过后再烧。否则遮罩一改，字幕必须重烧 |
| 目测估台标左边界 | 裁区放大 + `drawgrid` 读刻度。本片估 548、实测 348 |

## 六、适用边界

- **适用场景**：往已有视频上叠加字幕、处理固定位置的台标 / 水印 / 角标，以及任何「只改画面一部分、其余必须原样」的任务。
- **不适用场景**：
  - 源片本身干净——前置检查纯属冗余；
  - 目标水印会随画面移动——固定 `crop` 跟不上，需要逐帧跟踪；
  - 目标区域与必须保留的内容物理重叠——本片英文内容条文字右端 x≈450 与台标左端 x=348 真实重叠，二者只能取一。我们选择保内容条（它只出现约 14s 且是原片真实内容），代价是这 14s 内台标随原样露出。
- **前提条件**：本机有 `ffmpeg`（含 `ass` 滤镜）、可用的真 Python + `numpy`（扫描脚本）。
