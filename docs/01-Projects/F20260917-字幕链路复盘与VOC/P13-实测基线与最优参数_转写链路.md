## 二、⭐ 最优参数速查卡（直接抄）

### 场景 A · 口播录屏 → 要字幕（给人看，质量优先）**推荐**

```bash
whisper-cli \
  -m ggml-large-v3-turbo-q5_0.bin \
  -f <16kHz 单声道 wav> \
  -l zh \
  -t 8 \
  --vad -vm ggml-silero-v6.2.0.bin \
  -osrt -of <输出基名> -np
```

**为什么是这几个值**（每条都有实测支撑，见 §四）：
| 参数 | 依据 |
|:--|:--|
| `large-v3-turbo-q5_0` | 中文错例实测 **0/0/0**（small 是 4/4/7）；547 MB 只比 small 大 18% |
| `-t 8` | 默认是 **4**！改 8：英文 80.5 s → **52.4 s（+35%）** |
| `--vad -vm <silero>` | 重复幻觉 **7→0**、错字 **8→2**、耗时还从 93.4 s 降到 83.8 s；只要 **885 KB** |
| `-l zh` | 显式指定；`auto` 在短音频上偶有误判 |

**预期耗时**（中文 267.6 s 素材）：CPU `-t8` **≈100–210 s**；GPU ≈100 s（见 §三）。

### 场景 B · 口播录屏 → 要喂给 AI

在场景 A 基础上**加 `-ojf`**，再用 `assets\whisper-json-to-ai.ps1` 生成 `.ai.md` / `.words.jsonl` / `.word.vtt`：

```bash
whisper-cli -m ggml-large-v3-turbo-q5_0.bin -f a.wav -l zh -t 8 \
  --vad -vm ggml-silero-v6.2.0.bin -osrt -ojf -of out -np

pwsh -File .\assets\whisper-json-to-ai.ps1 -JsonPath out.json
```

> ⚠️ **硬前置：引擎必须 ≥ v1.9.2**，否则中文词级 token 是 `�`（实测 141 个里 38 个）。详见 P12 §三.3。

### 场景 C · 只要快（先看效果 / 低配机器）

```bash
whisper-cli -m ggml-small-q5_1.bin -f a.wav -l zh -t 8 --vad -vm ggml-silero-v6.2.0.bin -osrt -of out -np
```
`small-q5_1` 只有 **181 MB**（small 的 37%）。实测未单列该项速度，但减半体积通常带来明显加速。

### 场景 D · 纯 CPU、零外部文件（当前 Recordly 随包形态）

```bash
whisper-cli -m ggml-small.bin -f a.wav -l zh -t 8 -osrt -of out -np
```
**最低限度也要加 `-t`**。若连 VAD 文件都不想带，可退而用 `-mc 0`（见 §四.2 对比：它只治重复幻觉，不治错字）。

### 场景 E · 低电平录音（真实录屏的常见情况）

真实录屏平均电平实测只有 **-34.2 dB**（见 `subtitle-generate-master` D10），低电平下 whisper 错误率明显上升。
→ **先做 EBU R128 响度归一化（`loudnorm=I=-16`）再转写**，这一步是默认就该开的。

## 三、模型选型实测（速度 × 质量 × 体积）

### 3.1 速度（同一引擎 v1.8.4 CPU `-t 8`，除非另注）

| 模型 | 英文 206.4 s | 中文 267.6 s | 相对 small |
|:--|--:|--:|:--|
| `small` | **52.4 / 57.6 / 63.2**（中位 57.6） | 84.5 / 93.4 | 1.00× |
| `large-v3-turbo-q5_0` | 132.1 / 142.0 | 208.7 / 223.6 | **≈2.4×** |
| `large-v3-turbo`（f16） | 200.8 | 未测 | ≈3.5× |

**量化代价实测**：`turbo-q5_0`（547 MiB）比 `turbo` f16（1549 MiB）**快 1.5×**（132–142 s vs 200.8 s），体积只有 35%。
在干净 TTS 音频上两者错例都是 0，**无从区分质量差**——但那是因为测试素材太干净，不代表真实场景一样（见 §十）。

### 3.2 质量（中文 267.6 s，**错例计数**）

> 测试稿里故意放了三个已知难点：**护城河**（专有名词）、**后面**（近音）、以及一段会诱发**重复幻觉**的长句。
> 计数方式：在 SRT 全文里数错词的**出现次数**（数字越小越好）。

| 配置 | 条数 | 相邻重复 | 「护程」(应护城河) | 「后缅」(应后面) | 「比较具」(幻觉) | 句号数 |
|:--|--:|--:|--:|--:|--:|--:|
| `small` baseline | 36 | **6** | **4** | **4** | **7** | 24 |
| `small` + `-mc 0` | 41 | 0 | **5** | **5** | 0 | 34 |
| **`small` + `--vad`** | 56 | **0** | **1** | **1** | **0** | 22 |
| **`turbo-q5_0` CPU** | 96 | **0** | **0** | **0** | **0** | **0** |
| **`turbo-q5_0` GPU** | 82 | **0** | **0** | **0** | **0** | **0** |

**四条可执行的读法**：
1. **`--vad` 是性价比最高的一步**：重复幻觉 7→0，错字 8→2，**而且更快**。只要 885 KB。
2. **`-mc 0` 只治一半**：幻觉归零，但近音错字反而从 8 升到 10。**单用它不是好主意。**
3. **`turbo-q5_0` 质量最好**（全部归零），代价是 **2.4× 慢**。
4. ⚠️ **turbo 的标点更差**：句号数 **0**（small 有 24），全角逗号 0、半角逗号 198。
   → **换 turbo 必须配套补标点**（`subtitle-optimize-master` 有标点补全能力），否则字幕没有句末停顿感。

### 3.3 一句话选型

| 你更在意 | 选 |
|:--|:--|
| **准**（口播要发出去、要喂 AI） | `large-v3-turbo-q5_0` + `--vad` + `-t 8`（可接受 2.4× 慢） |
| **快**（先看效果、迭代） | `small`（或 `small-q5_1`）+ `--vad` + `-t 8` |
| **省空间** | `small-q5_1`（181 MB） |
| **要 GPU** | 必须 `turbo-q5_0` 才有意义（见 §四.5） |

## 四、参数实验实测

### 4.1 线程数（v1.8.4 CPU，英文 206.4 s）⭐ 最大的一处白捡收益

| `-t` | 耗时 | 相对 |
|--:|--:|:--|
| **4（默认值）** | **80.5 s** | 1.00× |
| 6 | 53.9 s | 1.49× |
| 8 | **56.7 s** | 1.42× |

- **whisper-cli 默认 `-t 4`**（`--help` 实测：[4]），8 核机器**一半 CPU 空转**。
- 6 与 8 基本持平（i7-9700 是 8 核 8 线程，无 HT 可榨）→ **取物理核数**。
- **Recordly 当前不传 `-t`**（`generate.ts:248-259`）→ 白白损失约 35%。

### 4.2 上下文与 VAD（中文 267.6 s）——见 §3.2 表

| 手段 | 治重复幻觉 | 治近音错字 | 速度影响 | 成本 |
|:--|:--:|:--:|:--|:--|
| 什么都不加 | ❌（7 次） | ❌（8 次） | 基准 93.4 s | — |
| `-mc 0`（关文本上下文） | ✅ 0 | ❌ 反而 10 次 | 74.3 s（**-20%**） | 0 |
| `--vad -vm <silero>` | ✅ 0 | ✅ 2 次 | 83.8 s（**-10%**） | 885 KB |

> ⚠️ `-nc` 这个"常识参数"在 v1.8.4 上**不存在**（实测报 `unknown argument: -nc`）。等价手段是 `-mc 0`。

### 4.3 量化（同一 turbo 架构）

| 文件 | 体积 | 英文 206.4 s | 说明 |
|:--|--:|--:|:--|
| `turbo-q5_0` | 547 MiB | **132.1 / 142.0 s** | 推荐 |
| `turbo` f16 | 1549 MiB | 200.8 s | 慢 1.5×，质量在测试素材上无差异 |

### 4.4 Flash Attention（v1.9.2 默认**开**）

| 配置 | 耗时 | 输出文本 |
|:--|--:|:--|
| GPU 默认（`-fa` 开） | 44.7 / 45.1 / 46.9 s | — |
| GPU `-nfa`（关） | 50.2 s | **与开时逐字相同** |

→ 在 GTX 750（CC 5.0）上开关差异在噪声内，**不影响质量**，无需干预。

### 4.5 ⭐ GPU 收益随模型变大而变大（**修正了上一轮报告的结论**）

| 模型 | CPU（同二进制） | GPU | GPU 收益 |
|:--|--:|--:|:--|
| `small` | 53.1 / 55.0 / 66.7 s | **44.7 / 45.1 / 46.9 s** | **约 1.2×** |
| `large-v3-turbo-q5_0` | 164.2 / 182.6 / 279.2 s | **83.5 s** | **约 2.0–2.2×** |
| `large-v3-turbo-q5_0`（中文 267.6 s） | 208.7 / 223.6 s† | **100.2 s** | **约 2.1×** |

† 中文 CPU 行用的是 v1.8.4，其余同二进制对比用 v1.9.2 —— 详见 §七。

**结论**：**GPU 只在 turbo 级模型上值得**。small 上 GPU 只有 1.2×，却要付 640 MB 运行时的代价。
GPU 利用率实测（small）：**平均 87.5%、峰值 100%、显存峰值 1025 MiB** —— 卡是真跑满了，慢是因为 GTX 750 本身弱（无 Tensor Core，ggml 对 ≤ Pascal 关闭 MMQ 快速量化核）。

### 4.6 其它

| 项 | 实测 | 结论 |
|:--|:--|:--|
| `--beam 1`（贪心） | 本仓 D10 实测：85.3 s → **103.7 s（更慢）** | **不是加速旋钮**，别用 |
| `-owts` | Windows 上产出 **0 字节**（默认字体是 macOS 路径） | 不可用 |
| `-t` 之外的多进程 (`-p`) | 未测 | 待验证 |

| K11 | **HF model card 的 SHA 列已过期** | 实算 tiny sha256 与 API `lfs.oid` 一致、与 card 不符 | 校验用 HF tree API 的 `lfs.oid` |

## 九、⭐ 口播录屏专用的一个结构性发现

**目标场景是"口播录屏"，那到底转写的是哪条音轨？** 代码给得很明确：

```text
electron/ipc/captions/generate.ts:119   pushCandidate(videoPath, "recording")        ← ① 录制文件本体（混音！）
electron/ipc/captions/audioCandidates.ts:13-18
                                        mic  → "microphone audio sidecar"            ← ② 麦克风轨
                                        system → "system audio sidecar"              ← ③ 系统声轨
electron/ipc/captions/generate.ts:126   webcamPath                                   ← ④ 摄像头音轨
```

`extractCaptionAudioSource()` **逐个尝试、第一个成功的就用** → **①混音轨永远优先**。

**后果**：如果录屏过程里电脑**正在播放声音**（放视频、开会、听音乐），口播的转写结果会被系统声污染——而这恰恰是"口播录屏"最常见的形态。

**建议**（按改动量从小到大）：
1. **不改代码**：把录像的 `.mic.wav` 音轨单独喂给 subgen / whisper-cli（mic sidecar 是独立文件）。
2. **改一行优先级**：口播场景把 mic 候选提到录制本体之前（或加一个"只用麦克风"的开关）。
3. **更进一步**：`convert -ac 2` 把 mic + system 合成**双声道**再喂 `--diarize` —— whisper.cpp 的 `output_vtt/srt` 会按声道能量写 `<v Speaker0>`，**等于免费的"你的声音 vs 电脑声音"分离**（源码 `cli.cpp:477-485`）。

## 十、测量方法学警告（必读，否则会误用上面的数字）

| 警告 | 说明 |
|:--|:--|
| **① CPU 计时方差极大** | 同一配置（turbo-q5_0 / v1.8.4 CPU `-t8` / 同一素材）实测 **132.1、142.0、191.9、267.6 s** —— 跨度 **2×**。原因未定位（热降频 / Windows Defender 扫描 574 MB 模型 / 磁盘缓存）。**结论：CPU 绝对秒数只能当量级用；比较必须在同一时间窗内成对跑。** |
| **② GPU 计时反而很稳** | small GPU：44.7 / 45.1 / 46.9 s（±2%）；turbo GPU：83.5 / 100.2 s。 |
| **③ 测试音频是 TTS 合成** | Windows SAPI 朗读固定文稿，**干净、无噪、无口音、无口癖**。真实录屏会更慢、更易错。所有质量计数（护程/后缅/比较具）在真实素材上**未必同样干净**。 |
| **④ 单次样本** | 多数配置只跑 1–3 次。标"单次"的不要当结论。 |
| **⑤ 评测不含"真实说话人"** | TTS 没有自然停顿与自我修正，**重复幻觉的诱发概率与真人不同**（很可能真人更容易触发）。 |
