# P01-复盘目标_字幕链路复盘与VOC

## 一、背景与动机

### 1.1 触发事件

- **完成一次真实交付**：对一条 53.3MB / 720×1280 / 5分14秒 / 314.047s 的竖屏口播 MP4（红杉 AI 行业报告解读），完成「识别字幕 → 优化字幕 → 烧录字幕」全链路。
- **交付结果**：5 个模板成片（clean-bar / punch-pop / karaoke-glow / slide-stack / title-mask）全部通过 8/8 成片校验。
- **触发复盘**：用户指出过程中**探索步骤过多**，希望去掉探索路径、只保留探索出来的最优路径，实现「更快、更省钱、同样目标」。
- **用户明确点名的意外收获**：AI 主动识别出源片自带硬字幕、并对硬字幕与台标（logo）做了处理——**这是用户原本没想到的**，用户判断「这部分做得也挺好」，要求单独调查并整理成实践/工具。

### 1.2 初始状态

- **起点**：用户提出三步意图（识别 / 优化 / 烧录），**未提供目标文件路径**，工作目录 `D:\code\Recordly` 内无待处理视频。
- **隐性未知（当时双方都不知道）**：
  - 源片**已烧死中英双语硬字幕**（画面 y≈976..1086）；
  - 右上角有 B 站台标 `Penny破圈观察 bilibili`（x≈348..690）；
  - 原片顶部在 4 个时间窗内存在英文内容条，会与台标区域**空间重叠**。

### 1.3 价值判断

- **用户判断**：整体做得好（结果达标），但**过程不够经济**。
- **判断依据（用户原话）**：
  - 「让他跑得更快，把原来那些探索的步骤路径都去掉，我们重点关注探索出来的路径」
  - 「更省钱、更快，能达到同样的目标」
  - 「他刚刚先识别了硬字幕，并对硬字幕和 logo 进行了一些处理。这些细节是我原来没有想到的，这一部分他做得也挺好。」
- **判断性质**：**执行问题**（方向正确，复盘如何把过程做短）。

## 二、核心复盘目标

### 2.1 主要目标

**把「一次成功的现场作业」压缩成「一条可复用的最优路径」** —— 复盘本次字幕链路，剥离探索性开销，产出一份可回写到 `D:\code\subtitle-burn-master` 的 VOC 输入文档。

### 2.2 成功标准

通过复盘，需要明确回答以下问题：

1. **路径对比**：本次实际走过的路径 vs. 事后已知最优路径，差在哪几步？
2. **浪费定位**：哪些步骤是纯探索开销（可被前置检查消除）？各自代价多少？
3. **意外收获的机理**：硬字幕识别与台标处理「怎么做、用什么方法、如何实现」？可复用性边界在哪？
4. **落点决策**：这部分该进哪个技能、以什么形态进（检查项 / 实践 / CLI 能力 / 新技能）？
5. **省钱机理**：本次为何零 API 成本？哪些设计保证了省钱，哪些环节本可更省？

### 2.3 成果验证

- ✅ **路径可复现**：给出「已知输入 → 最终成片」的确定性步骤清单，不含试错分支。
- ✅ **浪费可量化**：至少 3 处可量化的返工/空转，附实测证据。
- ✅ **实践可落地**：硬字幕/台标处理给出含实测数据与参考实现的规程，技能开发者可直接落地。
- ✅ **VOC 可回写**：产出符合目标仓（`subtitle-burn-master`）输入格式的需求条目 + 验收标准。

## 三、复盘范围

### 3.1 时间范围

- 单次任务全周期（从用户提出需求到 5 个模板成片交付）。
- 仅覆盖**一条素材**的完整链路，不含历史会话。

### 3.2 内容范围

- ASR 识别环节（`subgen transcribe`）的路径与开销
- 字幕文字优化环节（`subtitle-optimize`）的判据与时间轴校验
- **源片硬字幕识别与遮盖**（重点）
- **台标/水印处理与时间门控**（重点）
- 字幕烧录与模板对比（含 5 模板并行渲染）
- CLI 能力边界与技能协作契约

### 3.3 边界说明

- **重点**：
  - 探索路径 → 最优路径的**差集**
  - 硬字幕/台标处理的**方法、实现与可复用性边界**
- **不包括**：
  - 视频剪辑、抽帧、封面等本链路未触及的领域
  - 字幕措辞改写（本次刻意未做，属说话人原话）
  - `title-mask` 等模板的美学评价
- **复盘类型**：**执行问题**（方向正确，复盘过程与方法）

## 四、复盘价值

### 4.1 直接价值

- 下一次同类任务可**跳过探索**，直接执行已知最优路径。
- 把「AI 主动发现问题」的能力**沉淀为技能内置检查**，而非依赖当次运气。

### 4.2 方法论价值

- 验证「**前置检查消除返工**」这一模式：本次最大的浪费恰是缺少前置检查。
- 为「画面层处理该不该进字幕技能」提供一条有据可依的架构判据。

### 4.3 资产价值

- 产出可直接作为 `subtitle-burn-master` 的 VOC 输入，推动该技能从「文字+时间轴→硬字幕」扩展到「含源片预处理的完整入口」。

## 五、目标完整性检查

| 要素 | 状态 | 说明 |
|:---|:---:|:---|
| 方向（目标是什么）| ✅ | 探索路径→最优路径；硬字幕/台标处理沉淀 |
| 量化（差距多少）| ⚠️ | 时间差距可量化（见 P02 实测）；**金钱成本本次为 0，无省钱空间**，故「更省钱」应转为「更少算力/更少人工」 |
| 路径（怎么做）| ✅ | 全链路过程记录完整，含每次失败实测 |
| 共识（各方理解）| ✅ | 用户已确认三项决策：F 夹位置、回写落点 `subtitle-burn-master`、VOC 含参考实现 |

> **⚠️ 需在 P03 正视的一点**：本次全程本机离线（whisper.cpp + ffmpeg），**API 花费为 0**，因此「更省钱」在字面上无可优化空间。真实可优化的是**算力时间**与**人工确认轮次**。该点不回避，纳入 P03 得失分析。
