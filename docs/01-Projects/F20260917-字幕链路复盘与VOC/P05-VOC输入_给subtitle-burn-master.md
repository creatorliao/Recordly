## 一、这次用下来遇到了什么

我用 `subtitle-burn` 给一条 5 分 14 秒的竖屏口播片烧字幕。源片是外部拿来的，底部**已经烧死了中英双语硬字幕**，右上角还有个 B 站台标。

按 SKILL 的指引，我在烧录前跑了 `check-source`，它很准地报了「疑似源片自带硬字幕（high 置信）」。**到这里工具的判断完全正确。** 问题出在之后：

1. `check-source` 只告诉我「有」，没告诉我「在哪、多大、怎么盖」。它给的 `y0_ratio/y1_ratio` 把中英两行当成两条独立带，直接换算出的范围是错的。
2. 台标它没提。我是自己抽帧看出来的。
3. 没有任何环节提醒我「画面不干净时，接下来的路径会不一样」——我照常往下走，把字幕烧了，之后才发现台标遮罩切坏了原片顶部的英文内容条，只好遮罩重做、字幕重烧。

**代价**：遮罩渲染试了 5 个版本，字幕烧录完整重跑 2 轮，坐标目测量偏 4 次。而这一切的根因，是源片状态这个信息本该在第一步就完整拿到，却只拿到了一半。

另外发现一处文档与实现不符（见 REQ-5）。

## 二、需求条目

### REQ-1 【高】`check-source` 应同时输出「台标 / 水印候选区」

**触发场景**：拿到任何外部来源的素材（B 站、抖音、剪映导出），烧字幕前跑 `check-source`。

**现状**：只检测硬字幕，不检测台标。本次台标完全靠人工抽帧发现。

**期望行为**：`check-source` 的 `bands[]` 之外，增加 `overlay_candidates[]`，给出台标/水印候选区的像素边界与置信度。

**建议检测思路**：**时间持久性**。台标在整段视频里位置与形态稳定（存在帧占比接近 100%），而动态内容条只在少数窗口出现（本次实测 4 个窗口、累计约 14s / 314s）。对每个候选区统计存在帧占比，高者判为台标，低者归入「动态内容」并单独列出。

**验收标准**：
- 对本次样本，能检出右上角台标区并落在我实测的 `x=348..690, y=30..60` 范围内（允许合理余量）；
- 同时能识别出英文内容条属**动态内容**，不误判为台标；
- 理想情况下输出可直接使用的遮罩滤镜链（见 REQ-2 与 REQ-3）。

### REQ-2 【高】`check-source` 或新命令应能生成「遮罩滤镜链」

**触发场景**：`check-source` 报告源片不干净之后。

**现状**：我手工拼 ffmpeg 滤镜链，试错 5 版。

**期望行为**：输出一段可直接喂给 `ffmpeg -filter_complex` 的滤镜链，或提供 `subtitle-burn mask <video>` 子命令一步生成遮罩底片。

**验收标准**：
- 生成的滤镜链对本样本能一次跑通，产出底片上 `check-source` 返回 `existing_subtitles: false`；
- 色度半径参数在合法范围内（见 REQ-6）；
- 存在动态元素冲突时自动挂时间门控。

### REQ-3 【高】SKILL.md 应把「源片洁净度检查」提升为**任务起点闸门**

**触发场景**：任何「给视频烧字幕」的任务开始时。

**现状**：SKILL.md 的「烧录前必做的三件事」把 `check-source` 列在第 1 条，但位置在**烧录前**。这次我是准备烧录时才读到这里，已经晚了几步——转写、优化都做完了，画面层还没碰。

**期望行为**：把洁净度检查提到**任务第一步**，与「确认视频路径、确认模板样式」并列，并在路由表顶部明确写出：源片自带硬字幕时，路径增加「画面层」，且**画面层必须在烧字幕之前完成并验收**。

**为什么重要**：源片状态决定路径形态，不是烧录阶段的细节。它一变，字幕落位、模板选择、验收方式全都跟着变。

**验收标准**：读到 SKILL 开头就知道第一步要做什么；有明确标注画面层与文字层的先后顺序不可颠倒。

### REQ-6 【中】`boxblur` 参数应做合法性预校验

**触发场景**：手工拼滤镜链时。

**现状**：我写了 `boxblur=16:2`，ffmpeg 拒绝：`Invalid chroma_param radius value 16, must be >= 0 and < 16`。更麻烦的是**输出文件被写成损坏状态**（`moov atom not found`），我一开始以为是编码问题，排查了一轮。

### REQ-8 【高】增加 `--outline` / `--shadow` 参数，并暴露 `--template-file`

**触发场景**：想改字幕描边与阴影（例如「要纯白字、不要黑边描白字」）。

**现状**：CLI 只有 `--font` / `--no-bold` / `--color` / `--outline-color`。**`--outline-color` 只改描边颜色，改不了宽度**；描边与阴影由模板的 `outline_ratio` / `shadow_ratio` 决定。文档 `D09` 提到可用 `--template-file` 传自定义模板，但实测 `build` / `run` **均未暴露该参数**（报 `No such option: --template-file`）。

结果是：想改描边只能**生成 ASS 后手工改 Style 行**，等于绕过 CLI。

**期望行为**：
1. `build` / `run` 增加 `--outline <px>` 与 `--shadow <px>`（`0` = 关闭）；
2. 暴露 `--template-file`，与 D09 文档一致；
3. 增加一个「纯白无描边」预设模板（剪映用户常见审美）。

**实测依据**（本样本 5 个模板全部改用纯白 + 无描边 + 阴影 3）：

| 项 | 原状 | 改后 |
|:---|:---|:---|
| 字体 | `Source Han Sans CN Bold` / `Alibaba PuHuiTi B` | `Source Han Sans CN Regular` |
| 字重 | 4 个模板加粗 | 全部不加粗 |
| 描边 | 4–6px 黑 | **0** |
| 阴影 | 0–4px | 3px |

**ASS Style 字段位置**（改样式必须知道）：`Style:` 后逗号分隔 23 段，**描边是索引 16、阴影是索引 17**。

**踩坑记录**：用正则 `(BorderStyle,\d+,\d+),(\d+),(\d+),` 改会命中 `Bold,Italic,Underline` 段——改错了字段。三个「变体」渲染像素完全一致（亮像素 18809 vs 18809，差异行 0）才发现。若 CLI 提供参数即可根本避免此类错误。

**验收标准**：`--outline 0 --shadow 3` 生成的 ASS，其 Style 行第 17/18 字段分别为 0 和 3；无需后处理文件。

## 三、参考实现

以下均为本次实际跑通并验证过的代码，可直接用于落地与回归测试。

### 3.1 全片梯度扫描：精确定位硬字幕纵向极值

**为什么用梯度而不是亮度**：我先试过「灰度 > 205 且该行亮像素 > 60」，结果把白色衬衫和手都算了进去，得出 `min 900 / max 1279`，明显是衣服。硬字幕有**黑描边**，纵向梯度极强，而衣服、皮肤是软过渡——梯度法天然抗这个干扰。

```python
import subprocess, numpy as np

src = r"<源片路径>"
W, H = 720, 1280

# 2fps 抽全片为 raw 灰度流
p = subprocess.run(["ffmpeg", "-v", "error", "-i", src,
                    "-vf", "fps=2,scale=720:1280",
                    "-pix_fmt", "gray", "-f", "rawvideo", "-"],
                   capture_output=True)
buf = np.frombuffer(p.stdout, dtype=np.uint8)
n = buf.size // (W * H)
frames = buf[:n * W * H].reshape(n, H, W).astype(np.float32)

tops, bots = [], []
for f in frames:
    reg = f[900:1280, :]                  # 只扫画面下 40%
    g = np.abs(np.diff(reg, axis=0))      # 纵向梯度
    strength = (g > 60).sum(axis=1)       # 每行强梯度像素数
    idx = np.where(strength > 90)[0]
    if len(idx):
        tops.append(900 + int(idx.min()))
        bots.append(901 + int(idx.max()))

tops, bots = np.array(tops), np.array(bots)
print("检出字幕帧:", len(tops), "/", n)
print("顶部 y: min %d  p1 %d  p5 %d  中位 %d"
      % (tops.min(), np.percentile(tops, 1), np.percentile(tops, 5), np.median(tops)))
print("底部 y: 中位 %d  p95 %d  p99 %d  max %d"
      % (np.median(bots), np.percentile(bots, 95), np.percentile(bots, 99), bots.max()))
```

**本样本实测输出**：
```text
分析帧数: 628
检出字幕帧: 617 / 628
顶部 y: min 976  p1 976  p5 978  中位 980
底部 y: 中位 1068  p95 1084  p99 1085  max 1086
>>> 旧字幕纵向极值: y = 976 .. 1086
```
`p1` 与中位数只差 4px，说明结果稳定、不是噪声。

> **实现提示**：`p1` 与中位数接近可作为「结果可信」的判据。若两者差距大，说明检测被噪声干扰，应调整阈值。

### 3.2 扫描「动态内容」出现窗口

**为什么需要**：固定区域遮罩会切到别的内容。本片台标区右上方有条英文内容条，只在 4 个短窗口出现。

```python
# 顶部 200px 内，某行深色像素(<70)占比 > 55% 视为深色内容条
deep_rows = []
for i, f in enumerate(frames):
    reg = f[0:200, :]
    darkfrac = (reg < 70).mean(axis=1)
    idx = np.where(darkfrac > 0.55)[0]
    if len(idx) > 3:
        deep_rows.append((i, int(idx.min()), int(idx.max())))

times = [d[0] * 0.5 for d in deep_rows]
spans, s, prev = [], times[0], times[0]
for t in times[1:]:
    if t - prev > 1.0:
        spans.append((s, prev)); s = t
    prev = t
spans.append((s, prev))
print("出现区间:", spans)
```

**本样本实测输出**：
```text
含深色内容条的帧数: 27 / 628
出现时段: 首 1.0s  末 280.0s
出现区间数: 4
   1.0s .. 4.5s
   19.0s .. 23.0s
   235.5s .. 235.5s
   276.0s .. 280.0s
```
累计约 14s / 314s，各留 0.5s 余量后得到门控窗口。

### 3.3 遮罩滤镜链（定稿版·本样本实测跑通）

```powershell
$win = "between(t,0.5,5.0)+between(t,18.5,23.5)+between(t,275.5,280.5)"

$fc = "split=2[b][w];" +
      "[b]crop=720:148:0:958,boxblur=8:2[bb];" +          # 旧字幕带 → 模糊
      "[w]crop=368:56:336:24,boxblur=12:2[wm];" +         # 台标区 → 模糊
      "[0:v][bb]overlay=0:958[t];" +                      # 贴回旧字幕位置
      "[t][wm]overlay=336:24:enable='not($win)'[out]"     # 时间门控贴回台标位置

ffmpeg -v error -i "<源片>" -filter_complex $fc -map "[out]" -map 0:a `
  -c:v libx264 -preset veryfast -crf 20 -pix_fmt yuv420p -c:a copy -y "<遮罩底片>"
```

**参数来源**：

| 参数 | 值 | 依据 |
|:---|:---|:---|
| 旧字幕带 | `crop=720:148:0:958` | 实测 976..1086，上留 18px、下留 20px |
| 旧字幕模糊 | `boxblur=8:2` | 糊掉字且不过度 |
| 台标区 | `crop=368:56:336:24` | 实测 x=348..690 / y=30..60 加余量 |
| 台标模糊 | `boxblur=12:2` | 色度半径须 <16 |
| 门控窗口 | 4 个内容条区间各留 0.5s | 见 3.2 |

**验证结果**：
- 底片上 `check-source` 返回 `existing_subtitles: false`（遮罩确实生效）
- 烧录后成片校验 **8/8 通过**（时长差 0ms、音轨保留、yuv420p、字体真实生效、抽样 5/5 有字幕）
- 正常时段台标完全读不出；内容条时段文字完整保留

### 3.4 关键坐标测量法：放大读刻度

```powershell
# 台标区：裁 crop 起点 (300,0) 尺寸 400x90，放大 3 倍并画格线
ffmpeg -v error -ss 30 -i "<源片>" -frames:v 1 `
  -vf "crop=400:90:300:0,scale=1200:270:flags=neighbor,drawgrid=w=1200:h=30:t=2:c=red@0.9" `
  -y "wm_zoom.png"
```
换算：图内坐标 / 3 + 裁剪起点 = 原图坐标。

**本样本实测**：放大图内 `Penny` 起于 x≈145 → `145/3 + 300 = 348`；`bilibili` 止于 x≈1170 → `1170/3 + 300 = 690`。

> **踩坑提醒**：我第一次按视觉估算认为台标从 x≈548 开始，实际从 **348** 开始，差 200 像素，直接导致第一版遮罩完全没盖住台标主体。**台标的左边界必须量，不能估。**

### 4.2 边界与限制（请勿过度承诺）

1. **本规程的数值只对这条素材成立。** 换素材必须重新测量——这正是 REQ-1/REQ-2 要做的事。
2. **内容条与台标空间重叠时无法两全。** 本次选择保内容条（它是原片真实内容，只出现约 14s），代价是该时段台标随原样露出。这是取舍，不是缺陷。
3. **梯度法对「浅色 / 无描边 / 半透明」字幕的有效性未验证。** 本样本是「白字 + 黑描边」，梯度特征明显。若遇无描边字幕可能失效，退路是改用「帧间时间方差」检测（字幕区域帧间变化剧烈）。
4. **台标检测的「时间持久性」思路尚未实现验证**，属建议方案。
