# 03 · 调查：对标与根因

## 一、点名痛点：根因（本仓事实）

### 1. 裁完不靠拢（片头、中间一段、全轨）

**现象**：拉 clip 左缘、或分割后 Delete **中间一段**，轴上留下空档，后面正片/字幕/缩放都还停在原地，要一段段手推。这和剪映磁吸相反。

用户补齐的验收（必须进 WP-D，不能只做「左裁」）：

1. 裁/删的是**成片上的一段时间**（含中间），后面所有轨道自动靠过来。
2. **画面和字幕一起裁**：删掉的区间里有字幕，字幕一起没；不要画面没了字幕还漂在洞上。
3. Delete 删的是**正片那一段**时：正片、源音频、缩放、字幕、注释、外部音频**全部左移靠齐**。
4. 只 Delete 一条字/缩放：只去掉该块，**不**把整条正片挤过来（剪映也是这样，避免删个箭头整课乱跳）。

**根因不是缺一个 `if`，而是坐标粘在一起。**

`handleClipSpanChange` 只改当前 clip 的 `startMs/endMs`，不 `resequence`。`handleClipDelete` 丢掉该 clip 和落在其时间范围内的 zoom/annotation/audio，**不左移**后续 clip，也**不处理字幕**。

拉缘产生的 `removedSegments` 会整段滤掉重叠的 zoom/annotation/audio（重叠就整块删，不切开），`autoCaptions` **不在名单里**。跨在「删/留」边界上的字幕会错位或残留。

`startMs` 既是源入点又是轴上位置：把后面的块画到左边会改源入点，内容会错。OpenScreen 用双坐标 + `resequenceClips` 首尾相接。Recordly 空隙只进派生 `trimRegions`，轴上洞还在。

邻块逻辑是防重叠/换序，不是 ripple。

**对培训师**：剪映 = 中间废段一刀删掉，后面画面和字幕一起贴上来。Recordly = 源轴上挖洞，各轨各留各的。

### 2. 外在元素上下拖不动

**换轨数据是有的**：`AnnotationRegion.trackIndex`，`onAnnotationSpanChange(..., trackIndex)`，`resolveDropRowId` 允许 `row-annotation-*` → 另一条 `row-annotation-*`。

用户觉得废，是三道门槛叠在一起：

1. **没有空轨可落**。`TimelineCanvas` 按**已有块的** `trackIndex` 分桶画 Row。只有轨 0 上有字时，根本没有轨 1 的 drop target。新轨要走工具栏「添加图层」，不能像剪映拖到空白处自动建轨。
2. **跨类轨被打回**。`resolveDropRowId`：注释拖到 clip/zoom/audio 行 → 退回当前行。测试写死了这条（`timelineModel.test.ts`）。
3. **行很矮、未命中 over**。行高约 24px，垂直位移没进另一 `useRow`，`event.over` 仍是原行，`trackIndex` 不变。

注释**不做** overlap 检查（`hasOverlap` 对 annotation 恒 false），同轨可叠。失败感主要来自「没行可丢」而不是互斥。

OpenScreen：**故意不做** overlay 跨泳道——一种 kind 一条 lane。音频写入还强制同 kind 单行。所以「换轨」**没有现成 OS 代码可抄**，只能抄它的水平拖指针原语；交互应对齐剪映，不是对齐 OS。

### 3. Delete 不删选中

三层，前两层是体验门闩，第三层是接线 bug。

**门闩 1 — 必须时间线聚焦**（`useTimelineKeyboardShortcuts.ts`）：

```ts
if (!isTimelineFocusedRef.current) return;
```

点过预览、抽屉、字幕列表再按 Delete，监听在 window 上但函数直接 return。  
OpenScreen：`NewEditorShell.deleteSelection()` **不要求**时间线 focus；只跳过 input / textarea / `isModalOpen()`。

**门闩 2 — 优先级**（`resolveDeleteSelectionTarget`）：全选 zoom → keyframe → zoom → clip → annotation → audio → caption。残留的 `selectedZoomId` 会挡住用户以为选中的注释。

**Bug — clip 删除没接到时间线**（已核对）：

- `useTimelineSelection.deleteSelectedClip`：没有 `onClipDelete` 就静默 return。
- `EditorTimelinePanel` 传了 `onClipSplit` / `onClipSpanChange` / `onSelectClip`，**没有** `onClipDelete`。
- `handleClipDelete` 只接到 Settings（`useEditorSettingsPanelProps.ts`）。

因此：选中正片按 Delete → 判定 target=clip → `deleteSelectedClip` 空跑。  
注释 / 缩放 / 音频已接线，但仍受聚焦门闩影响——这能解释「有时能删、多数时候不能」。

**与旧方案冲突**：`R20260906-14` L6 写过「Delete 删缩放/字幕/文本，**别误删整段 clip**」。键盘不接 `onClipDelete` 很可能是当时有意留的。本次用户与 `AGENTS.md` 口诀都是「Delete 删当前选中」。代决见 `14` D-A。

`handleClipDelete` 本身会删落在该时间范围内的 overlay，**不会**把后面的 clip 左移（又回到痛点 1）。

### 4. 拖两端的「点」变成整块平移，拉不长时间

**现象**：用户抓块左右两端看起来能拖的点（白条端帽），预期是剪映式 **Trim**：一头钉住，另一头走，这段占用的时间变长或变短。结果整块一起跑，时长不变。

**专业软件约定（必须对齐）**

| 抓哪里 | 行为 | 时长 | 光标 |
|--------|------|------|------|
| 块**中间** | 平移（Move） | 不变 | grab |
| 块**左端** | 改入点（Trim In） | 变 | col-resize |
| 块**右端** | 改出点（Trim Out）；拉过成片末尾则**轴变长** | 变 | col-resize |

正片右缘受**源片剩余长度**限制；字/缩放/字幕/外部音频的右缘可以拉过当前正片结束，把成片轴撑长。  
**禁止**用「整块拖出轴尾」当拉长轴的手段（Recordly 现在正好反过来）。

**根因（本仓）**

1. **命中区叠在一起**。`Item.tsx` 把 `useItem` 的 drag `listeners` 铺在**整块根节点**上；左右 `.zoomEndCap` 只是 4px 装饰帽（`ItemGlass.module.css`），没有自己的 resize 会话。`dnd-timeline` 热区是 `resizeHandleWidth={6}`，和 4px 帽对不齐。用户点「点」，引擎经常收到 **drag** → `resolveDragEnd` **锁死时长**（`end = start + originalDuration`）。
2. **短块更糟**。`overflow: hidden` + `minWidth: 6`，两端帽挤在块内。OpenScreen `pillAffordance`：太窄则柄**翻到块外**。`R20260907-02` 已写「柄 6 + 窄块外置」，`Item.tsx` **没落地**。
3. **resize 被轴长夹死，drag 反而能撑轴**。`resolveResizeEnd` → `clampSpanToBounds(..., totalMs)`，右缘出不去。`getClipDragTotalMs` 却允许最后一条 clip **整块**拖过轴尾撑长轴。想拉长时抓端点失败或变搬家；误拖中间却拉出空档——和剪映相反。

**OpenScreen**：`startPillDrag` 分 `"move"` / `"l"` / `"r"`；`pillAffordance` + `PILL_HANDLE_PX=6`；`V4Timeline.geometry.test.tsx` 锁死左柄改入点、右柄改出点、中间平移。可抄几何，不搬 ventilate。

### 5. 时间轴配色怪，不像专业剪辑软件

**现象**：块一块一个高饱和色；浅色主题更像糖果（正片浅蓝满填、缩放浅紫、字幕粉）。选中还有 inset 1.5px 亮圈。培训师会觉得「花、AI、不认真」。

**专业软件怎么上色（要对齐的是气质，不是抄像素）**

| | 剪映 / CapCut | Premiere / 达芬奇 | OpenScreen | Recordly 现在 |
|--|---------------|-------------------|------------|---------------|
| 轴底 | 深灰 / 浅灰，安静 | 炭灰，几乎无彩 | `#0a0c10` 一类 | 未统一用 `--editor-timeline` |
| 块 | 低饱和实色，靠色相认轨 | 更灰的色相条 | `accent-soft` / `*-wash`，不是满霓虹 | 深色宝石色、浅色糖果满填 |
| 选中 | 边加亮、略提亮，不发光 | 细描边 | `accent-ring` 外圈（我们**不抄**外光） | inset 亮圈 + 边变 neon |
| 正片 vs 效果 | 正片沉、效果略跳 | 正片蓝灰、声绿、字黄 | 正片卡 + 效果 wash | 正片 `glassCyan` 与闲置 `glassGreen` **同色** `#183065` |

`R20260907-02` `03-规范` 已拍板、与上表一致：

- 实色、禁止渐变糖
- 正片 `accent / 18`，缩放紫 `/16`，音频绿 `/16`，字幕玫 `/16`，注释琥珀 `/16`
- 选中 2px 色相边，不要光晕

**根因**：规范停在文档，`ItemGlass.module.css` 仍是另一套硬编码 hex；浅色分支把 wash 做成了 **500 满填**。

**本夹做法**：只把时间轴块/轨底**落到已有色表**（WP-F），不重做抽屉、不抄 OS 11px 圆和 ring。色 token 真源仍认 `R20260907-02`。

### 6. 默认要有一条带波形的音频轨

**要的体验**：停录进编就能看见 **1 条**讲解声波形，安静处矮、说话处高，点波形对上画面。这是剪映/Premiere 找废段的基本手段。

**OpenScreen 有没有？有，但形态不同。**

| | OpenScreen | Recordly |
|--|------------|----------|
| 画在哪 | **画在正片块里面**（`ClipWaveform` + `useAudioPeaks` / worker） | **单独一行**源音频轨（`SOURCE_AUDIO` + `AudioWaveform` canvas） |
| 默认几条 | 不另开「讲解声行」；导入 BGM 才另有音频 pill | 设计上默认 1 条（mixed 或 mic）；实现上经常 **0 条** |
| 可抄 | `useAudioPeaks.ts`、`ClipWaveform`、`V4Timeline.waveform.test.tsx` | 轨 + canvas **已经在本仓**，优先修可见性，不必整包替换 |

用户要的是「默认音频**轨道**」，本仓独立轨比 OS「画在 clip 里」更贴。OS 可抄的是：**peaks 解码更稳、条更密、无声仍能认出是音轨**。

**本仓看不见的根因**

1. `EditorTimelinePanel`：`showSourceAudioTrack = clipRegions.some(c => c.showSourceAudio)`。旧项目没这个字段 → **整组不渲染**。
2. `visibleSourceAudioTracks` 在 peaks 未就绪或解码失败时是 `[]` → 有开关也没行。
3. `R20260907-02` T-J 把「默认一条讲解声」迁到 `R20260907-03`，视觉夹没落地可见性。新录虽写了 `showSourceAudio: true`，旧课和 peaks 失败时用户仍觉得「没有音频轨」。

**做法（WP-G，低垂）**

1. 有解说源则**默认显示 1 条**波形轨；`showSourceAudio` 缺省当 `true`；设置可关。
2. peaks 加载中画占位，失败再藏或提示「无声轨」，不要 silently 0 行。
3. 继续用 `selectDefaultSourceAudioTracks`，禁止默认铺系统+麦+混合三条。
4. 若本仓 `WaveformGenerator` 峰太糊或常失败：再**移植** OS `useAudioPeaks`（或把 `ClipWaveform` 叠进正片作增强，独立轨仍保留）。
5. 点波形 = 现有时间线 seek（已有），WP-D 合缝后波形 span 必须跟正片走。

不要另起第三条 peaks 引擎除非本仓解码确认挂了。

## 二、对标：剪映 / 专业工具 / OpenScreen

| 能力 | 剪映 / CapCut | Premiere 一类 | OpenScreen | Recordly 现在 |
|------|---------------|---------------|------------|---------------|
| 选中 + Delete | 删当前层/段，常合缝 | 删；ripple 可选 | 窗口级删，不要求 focus | 要 focus；clip 未接线 |
| 块两端 / 中间 | 端=改时长，中=搬家 | 同 | 外置柄 + move/l/r 分模式 | 端点易变搬家；resize 不能撑轴，整块拖反而能 |
| 删中间一段正片 | 后段+全轨靠上，区间内字幕一起没 | Ripple Delete | clip 删后 resequence；trim 轴上仍占位 | 留洞；`autoCaptions` 不跟删 |
| 叠层换轨 | 上下拖换图层/轨，可自动加轨 | 拖到 V2/V3 | **不做** overlay 换轨 | 字段有，空轨无 |
| 时间轴缩放 | Ctrl+滚轮，指针为中心 | 同 | 有，可抄 | 文案有，代码 return |
| 吸附 | 块边 / 播头 | 同 | `PILL_SNAP_PX=8` + 引导线 | 邻块硬夹紧；播头对关键帧 |
| 多选 | Shift / 框选 | 同 | Shift 多选 + 一次 undo | 仅全选 zoom |
| 右键菜单 | 有 | 有 | 无 | 无 |
| 分割 | 刀片 / Ctrl+B | Ctrl+K | **无**显式 split | 有 C |
| 撤销 | 有 | 有 | 有 | 有 |
| 块配色 | 低饱和认轨 | 更灰的色相条 | wash + 不抄其 ring | 浅色糖果满填、深色宝石色 |
| 讲解声波形 | 音轨/块上能看有声无声 | 音轨波形 | **正片块内** ClipWaveform | 独立轨已写，默认常不出现 |

要点：

- **Delete / 边柄几何 / 滚轮缩放 / snap**：OpenScreen 弱耦合，**优先抄**。
- **合缝**：抄 OS 的 **`resequenceClips` + 双坐标思想**，不要抄它的 trim-pill「轴上留洞、播放跳过」（那和用户要的剪映相反）。
- **换轨**：剪映有、OS 无；按剪映做，自己写空轨 + 落点。
- **边柄**：对齐剪映「中搬家、边拉时长」；抄 OS `pillAffordance`，不要保留「整块拖出轴尾撑长轴」。

专业工具里还有嵌套、链接、波纹开关。培训师不需要第一期就上开关；**默认合缝一种行为**即可（G4 不过度）。

## 三、OpenScreen 可抄性（按容易度）

| 序 | 项 | 路径（openscreen） | 可抄性 | 对本夹痛点 |

| 2 | Modal 下禁快捷键 | `modalGuard.ts` | 可直接移植 | 防误删 |
| 3 | Ctrl+滚轮缩放 / Shift 平移 | `V4Timeline` wheel | 可直接移植 | R5 |
| 4 | 8px 边缘吸附 | `V4Timeline` `PILL_SNAP_PX` | 可直接移植 | 手感 |
| 5 | 柄几何 / 窄块外置 / move·l·r | `V4Timeline` `pillAffordance` + geometry 测 | **可移植几何** | 痛点 4 |
| 6 | 播放头自订阅 / rAF scrub | `PlayheadOverlay` | 可直接移植 | 非痛点，顺手低 |

| 10 | region 复制粘贴 | `regionClipboard.ts` | 需适配 | 后置 |

不建议整包搬：`timelineMap.ts`（>700 行、绑 Axcut schema）、trim ventilate、音频强制单行（和「真多轨注释」打架）。

## 四、关联与冲突（动手前要认）

| 关系 | 说明 |
|------|------|
| 合缝 × 现有映射 | `mapTimelineTimeToSourceTime` 假定轴时间 ≈ 源时间。压缩轴之后必须改投影，否则字幕/缩放/导出对不齐。 |
| Delete clip × L6 | 旧方案怕误删整段；新需求要对齐剪映。推荐：删当前选中（含 clip）+ 撤销。 |
| 换轨 × OS | 不能「抄 OS 所以不做换轨」。OS 是反例。 |
| 合缝 × 用户故意留空隙 | 第一期不做「自由时间线」开关；若以后要，默认合缝 + 可选关闭。 |
| 边柄 × `R20260907-02` | 视觉夹已定「柄 6 + 窄块外置」，本夹负责**真做成 resize** |
| 配色 × `R20260907-02` | **不另起色盘**；WP-F 只改 `ItemGlass` / 轨底 token，落到已拍板的 `/16` 洗色 |
| 边柄拉长 × WP-D 合缝 | 先保证「拉的是时长不是搬家」；拉左缘后的靠拢仍归 WP-D |
| 本夹 × 02/03/04 | 改交互时不要重做抓手/标尺字/抽屉皮。 |

## 五、调查结论

1. 已有：**分割、拉缘、多类轨、设置里删除、撤销、clip 换序**。缺的是剪映级**收口行为**和键盘习惯。
2. 点名项里：**Delete、边柄、配色、默认波形轨**都是低垂；**换轨**中低垂；**合缝**中等（要拆坐标）。
3. 另外一颗低垂：Ctrl+滚轮缩放——文档承诺了，十来行就能对上剪映/OS。
