# 05 · 调查分析：金路径上哪些位置必须记日志

> 角色：培训师。金路径：选源 → 开录 → 停录/合成 → 进编辑器 → 导出。  
> 目的：出了错能从**这一次启动**的会话日志里对上阶段、看见失败原因，再改善。  
> 依据：`useScreenRecorder.ts`、`electron/ipc/register/recording.ts` / `sources.ts` / `export.ts`、`cursor/monitor.ts`、`useInitialEditorSource.ts`、`useExportRunner.ts`。  
> **本文件只定「记什么、记在哪」；不改产品代码。** 实现仍按 `04`。

## 0. 怎么记（统一规矩，避免记成噪声）

每条金路径日志至少能回答四句：

1. **在哪一阶段**（`scope` + `event`）
2. **跟哪一次录/导有关**（`corr.recordingId` / `exportId`）
3. **成功还是失败**（失败必须 `level=error` 或明确的 `*-failed`）
4. **用户看见了什么**（若弹了框 / toast / 红字，`data.userMessage` 与界面同一句话）

失败行额外必带：`error.name`、`error.message`、关键路径（helper / 成片 / 临时文件）。不要把整段 ffmpeg stderr 灌进会话日志（diagnostics sidecar 已截断保存）。

**不要记：** 逐帧、每个光标采样点、每次 `PERF:*` 毫秒、表单校验（「请输入预设名」）。这些对定位金路径断裂没有帮助，只会撑爆文件。

**现状缺口：** 下列「必须」点里，今天大多只有 `console.*` 或成片旁 JSON；**会话文件里一条都没有**（见 `03`）。`console` 打过 ≠ 已入档。

---

## 1. 启动（金路径之前，但没有它后面全对不上）

| 事件 | 位置 | 级别 | 必须带的数据 | 现在 |
|------|------|------|--------------|------|
| `app.start` | `electron/main.ts` `whenReady` 最早 | info | 版本、是否 packaged、`userData`、`recordingsDir`、os、本次 `logPath` | 只 `console.log` 两个路径 |
| `app.recordings-dir-failed` | `ensureRecordingsDir` | error | 错误对象 | `console.error` |
| `app.render-gone` | `windows.ts` `render-process-gone` | error | 窗口角色、`reason`、`exitCode` | 仅 console |
| `app.uncaught` / `unhandled-rejection` | `main.ts` 尚未挂 | error | 栈 | **无** |
| `app.exit` | `before-quit` / `will-quit` | info | 是否正在录/导 | 无 |

启动失败（窗口 `did-fail-load`）同样必须 error。否则「打不开编辑器」无法证明是主进程死了还是渲染裂了。

---

## 2. 选源（录之前的第一道闸）

| 事件 | 位置 | 级别 | 必须带的数据 | 现在 |
|------|------|------|--------------|------|
| `source.list-failed` | `sources.ts` `get-sources` | error | 平台、错误 | 部分 console |
| `source.select` | `select-source`（约 384 行） | info | `sourceType`（screen/window）、`id` 可截断、宽高、是否 HWND 有效 | **无业务日志**，只改 state |
| `source.select-invalid` | `recording.ts` `invalid-window` 返回 | error | 用户将看到的文案 | 返回 message，不写盘 |
| `source.bounds-unresolved` | `show-source-highlight` 窗口解析失败（约 425 行） | warn | sourceId、平台 | `console.warn` |

选源成功一条就够。列表里每个窗口不要打。  
`alert(未选源)`（`useScreenRecorder.ts` 1139 / 1612）必须同时 `ui.alert` + `recording.start-failed`（reason=`no-source`）。

---

## 3. 开录（金路径最容易断、也最容易被「静默回退」骗过）

主入口：`useScreenRecorder.ts` `startRecording`（约 1662）→ 主进程 `start-native-screen-recording`（`recording.ts` 431）。

### 3.1 必须记（成功也要记）

| 事件 | 位置 | 为什么 |
|------|------|--------|
| `recording.start-attempt` | `startRecording` 入口 | 证明用户点了开始；带 `recordingId`、倒计时秒数、是否开系统声/麦 |
| `capture.backend` | 判定 WGC / 浏览器 / FFmpeg 之后 | 卡顿根因第一刀：到底走哪条采集 |
| `capture.start` | `waitForWindowsCaptureStart` 成功返回前 | helper 路径、fps、窗口 HWND 或显示器、输出/临时路径、是否采系统声/麦 |
| `cursor.monitor-start` | `cursor/monitor.ts` `startNativeCursorMonitor` 成功 spawn | 对上「鼠标没跟上」：helper 是否真起来 |
| `recording.started` | `setRecording(true)` 且 `setRecordingState(true)` | 墙钟、`recordingId` |

### 3.2 必须记（失败 / 降级）

这些今天最危险：**用户还能继续录，但已经不是你以为的那条路。**

| 事件 | 位置 | 级别 | 用户是否知情 |
|------|------|------|--------------|
| `capture.unavailable` | `isNativeWindowsCaptureAvailable` 为假（443–448） | error | 随后可能 toast 回退 |
| `capture.already-active` | 已有 WGC 进程（462–466） | error | 返回 message |
| `capture.start-failed` | catch（639+）`Failed to start native Windows capture` | error | 渲染层可能 toast 后**回退浏览器采集** |
| `capture.fallback-browser` | `useScreenRecorder` 1733–1744 | **warn（建议升为醒目 warn，并带 userMessage）** | 有 `toast.warning`，**必须入档** |
| `capture.timeout` | `waitForWindowsCaptureStart` 12s | error | 走 start-failed |
| `cursor.monitor-failed` | helper 缺失 / spawn 失败（104、123、138、161） | **error**（今天只是 warn） | **用户不知情**；鼠标效果会 silently 退化 |
| `mic.fallback-browser` | 1824+ `microphoneFallbackRequired` | warn | console.info，几乎不可运营 |
| `mic.fallback-failed` | 1873–1885 toast | error + `ui.toast` | 有 toast，无文件 |
| `audio.system-unavailable` | alert 2008 | error + `ui.alert` | 有弹框 |
| `audio.mic-denied` | alert 2045 | error + `ui.alert` | 有弹框 |
| `recording.start-failed` | catch 2255–2261 `alert(failedToStart)` | error + `ui.alert` | 有弹框 |
| `recording.countdown-cancelled` | 1699 / 1780 | info | 不是故障，避免误判「没开录」 |

浏览器采集（回退后）还要一条 `capture.browser-started`：mimeType、是否含系统光标策略（`resolveBrowserCaptureCursorPolicy`）。否则日志里只有「WGC 失败」，看不出回退后是否真的在录。

FFmpeg 回退：`start-ffmpeg-recording` / `stop-ffmpeg-recording` 的失败已有 `console.error`，必须升为 `capture.ffmpeg-start-failed` / `stop-failed`。

### 3.3 录制中（少而准）

| 事件 | 位置 | 级别 | 说明 |
|------|------|------|------|
| `recording.pause` / `resume` | 原生 pause/resume IPC | info | 对时长对不齐 |
| `recording.interrupted` | `emitRecordingInterrupted` | error | helper 中途死；**今天只推渲染，不写盘** |
| `resource.snapshot` | 见 `04` §5 | info | 每 5s；解释卡顿是否打满 |

不要每个 MediaRecorder timeslice 打一条。

## 4. 停录 → 合成 → 进编辑器（「卡在整合」必须能证伪）

主入口：`stopRecording`（约 1267）→ `stop-native-screen-recording` → 可能 `mux-native-windows-recording`（1482）→ `finalizeRecordingSession`（741）→ `switch-to-editor`。

| 事件 | 位置 | 级别 | 必须带的数据 |
|------|------|------|--------------|
| `recording.stop-attempt` | `stopRecording` 开头 | info | `recordingId`、期望时长 ms、是否 WGC |
| `recording.stop` | IPC 成功且有 `path` | info | 成片路径、文件大小（若已有） |
| `recording.stop-failed` | 1328–1354 | error | 错误 + 将 toast 的全文 |
| `recording.recover` | `recoverNativeRecordingSession` 成功 | warn | 证明走了恢复，成片可能不完整 |
| `recording.recover-failed` | 1345 | error | |
| `mux.start` / `mux.complete` / `mux.error` | `recording.ts` 1498 / 1529 / 1553 | info/error | 期望时长、是否有系统声/麦、mux 摘要（时长、是否跳过 pad）。**不要**再抄 12KB processOutput |
| `mux.skipped-no-audio` | 无伴音直接 finalize | info | 否则会误判「没做 mux」 |
| `mux.no-pending-video` | 1493 返回 | error | |
| `mic.sidecar-store-failed` | `store-microphone-sidecar` | error | |
| `recording.store-failed` | `store-recorded-video` | error | 浏览器采集落盘 |
| `recording.session-persist-failed` | `finalizeRecordingSession` 759–768 | error | 进编辑器前元数据没写上 |
| `editor.open` | `switch-to-editor` 成功之后 | info | `videoPath` |
| `recording.finalize-failed` | `notifyRecordingFinalizationFailure` | error + `ui.toast` | 用户看到的长 toast |
| `webcam.background-failed` | 停录后异步 webcam 处理 | warn/error | 不要让主路径成功掩盖辅路失败 |

倒计时未真正开录就停（`nativeWarmStartActive` 分支 1270）：记 `recording.discard-warm-start`（info），避免当成 stop-failed。

## 5. 编辑器加载（编得动）

| 事件 | 位置 | 级别 | 说明 |
|------|------|------|------|
| `editor.load` | `useInitialEditorSource` 开始按 path 加载 | info | path、是否刚录完 |
| `editor.load-failed` | `project.setError`（无视频、加载失败等） | error + `ui.page-error` | **红字必须入档** |
| `cursor.telemetry-load-failed` | `get-cursor-telemetry` 失败（recording.ts 1990） | error | 鼠标回放会空，对上 09 |
| `cursor.telemetry-save-failed` | `set-cursor-telemetry` | error | |
| `editor.preview-init-failed` | `VideoPlayback.tsx` 初始化预览失败 | error | 能播时间轴但不能看画 |

工程打开/保存失败（`useProjectOpenActions` / `SaveActions`）记 `project.open-failed` / `save-failed`。不是金路径主链，但是培训师「下次接着剪」会走；有 toast 就必须入档。

## 6. 导出（导得出）

主入口：`useExportRunner.ts`；失败展示：`showExportErrorToast`（**收口点，必须挂钩**）。

| 事件 | 位置 | 级别 | 必须带的数据 |
|------|------|------|--------------|
| `export.start` | runner 校验通过、即将 new Exporter | info | `exportId`、宽高、fps、码率、pipeline、backend 偏好、是否 NVIDIA CUDA 可选、源 path |
| `export.backend` | 实际选中 modern / legacy / native / cuda | info | 与偏好不一致时要写明回退原因 |
| `export.progress` | **不要每帧**；最多 10%/25%/50%/75% 或每 15s 一条 | info | 防「卡死还是慢」 |
| `export.complete` | 存盘成功 | info | 输出路径、耗时、体积 |
| `export.failed` | catch / `showExportErrorToast` | error + `ui.toast` | 用户可见摘要 + 完整 message |
| `export.cancelled` | 用户取消 | info | 不要当 error |
| `export.save-failed` | `save-exported-video` IPC | error | |
| `export.native-failed` | `native-video-export-*` | error | 是否回退浏览器导出 |

无视频 / 未就绪的 toast（`noVideoLoaded`）记 warn 即可（操作问题，不是系统崩）。

## 7. 字幕（G3，金路径旁路，失败仍要入档）

| 事件 | 位置 | 级别 |
|------|------|------|
| `captions.generate-start` | `generate-auto-captions` | info（引擎路径、模型是否打包、源音频） |
| `captions.generate-failed` | `useAutoCaptionController` toast | error + `ui.toast` |
| `captions.whisper-missing` | 运行时/模型不在 | error |

成功一条 `captions.generate-complete`（条数、耗时）即可。

## 8. 所有错误 UI（横切，不是阶段）

只要用户看见失败，会话日志必须有对应行。按收口记，不要每个按钮手写一遍：

| UI | 收口 | event |
|----|------|--------|
| `alert(...)` | `useScreenRecorder` 7 处 | `ui.alert` |
| `toast.error` / `toast.warning`（回退） | `notifyError` / `notifyWarn` | `ui.toast` |
| `showExportErrorToast` | 已是单点 | `ui.toast` + `export.failed`（可一行） |
| `project.setError` | setter 旁或包装 | `ui.page-error` |
| `dialog.showMessageBox` warning/error | 主进程 | `ui.dialog` |

校验类（空名称）可只 toast、不写文件，或 `level=debug`。金路径相关校验（未选源、无成片）必须写。

---

## 9. 对照金路径：一次正常走完，日志里应能看见的骨架

智能体打开**这一次**启动文件，滤 `level>=info` 且 `scope` 属于金路径，应类似：

```text
app.start
source.select                  sourceType=window
recording.start-attempt        recordingId=...
capture.backend                windows-wgc
cursor.monitor-start
capture.start
recording.started
resource.snapshot              phase=recording   （若干条）
recording.stop-attempt
recording.stop
mux.start → mux.complete
editor.open
editor.load
export.start
export.backend
export.complete
app.exit
```

任何一步变成 `*-failed`，后面可以没有，但失败行必须带 `userMessage`。  
若出现 `capture.fallback-browser` 而没有 `cursor.monitor-start`，即可解释「成片卡 / 鼠标对不齐」为什么和原生路径不是同一套假设。

---

## 10. 明确不要记的位置（防过度设计）

| 位置 | 原因 |
|------|------|
| `handleCursorMonitorStdout` 每条 STATE/INTERACTION | 高频，telemetry sidecar 已有 |
| `modernFrameRenderer` / 逐帧 encode | 一次导出会炸文件 |
| 源列表里每一个窗口 | 噪声 |
| 公告打开失败以外的营销逻辑 | 不在金路径 |
| 字体 URL 校验 | 非金路径 |
| 已有 `PERF:MAIN` / `PERF:RENDERER` 全量进会话文件 | 默认关；要查性能开 `RECORDLY_LOG_DEBUG` |

成片旁 `*.recording-diagnostics.json` **继续写**，会话日志只记相位摘要。两者分工：sidecar 给这一条录像的媒体证据；会话日志给这一次启动的时间线。

---

## 11. 对改善工作的用法

定位时按阶段问：

| 日志停在 | 先查 |
|----------|------|
| 没有 `capture.start`，有 `capture.start-failed` / `fallback-browser` | helper / WGC / 权限 / 窗口已关 |
| 有 `capture.start`，没有 `cursor.monitor-start` | 鼠标不同步（09）先查 helper |
| 有 `recording.stop`，有 `mux.error` | 卡在整合，不是采集 |
| 有 `mux.complete`，`editor.load-failed` | 路径/媒体服务 |
| 有 `editor.load`，`export.failed` | 导出后端/磁盘 |
| 全程成功但成片卡，且 `resource.snapshot` 内存/CPU 打满 | 去 `R20260906-12`，不是先改产品交互 |

## 12. 对工作流

不改变录→停→编→导操作。只规定日志埋点；实施等「开始做」，顺序见 `04` §7。
