# 01 · 需求：日志与可观测性

> 2026-09-06 用户口述。先落盘，再调查；**不改产品代码**，等明示「开始做」。

## 1. 角色与目标锚点

| 项 | 内容 |
|----|------|
| 角色 | 培训师，录软件操作；后续还有智能体根据日志排障、改功能 |
| 金路径 | 启动录制 → 停止 → 编辑 → 导出 |
| 落点 | **G1** 出问题能从日志对上阶段；**G4** 不过度设计（本机文件即可，不上云、不上 APM） |
| 范围 | 仅 Windows；`dev-creator`；简体中文 + 英文界面；日志内容可用中英混排技术字段 |

## 2. 用户要什么

1. **异常和问题能从日志里找出来**  
   例如成片卡顿、鼠标动态跟不上画面（见 `R20260906-09`）——这种现场问题应当有对应记录，方便日后运营、运维、修复、加功能、持续演进。

2. **有错误弹框的地方，日志里也必须有一条**  
   `alert`、系统对话框、toast 错误、编辑器红字，不能只闪一下就没了。

3. **每一次启动创建一份新的日志**  
   智能体分析时打开「这一次」即可。禁止所有运行挤进一份越来越长的文件，浪费上下文。

4. **若现有日志对不上上述尺子，要配一套专业、可落地的可观测方案**  
   专业 = 能定位、能关联金路径阶段、能给智能体读。  
   不是 = Sentry / OpenTelemetry 全家桶、远程上报、复杂仪表盘。

5. **日志里要有资源消耗**（2026-09-06 追加，对上 `R20260906-12`）  
   相位切换和录/导/字幕过程中能看到内存、粗 CPU、Electron/子进程是谁。用来解释整机卡住，不是做仪表盘。

## 3. 成功长什么样

- 双击打开应用 → 立刻出现一份**本次启动**的日志文件（文件名带时间 + 进程号）。
- 录制开始/停止、采集后端、光标监视、合成、导出、字幕失败，都有结构化记录。
- 同一次启动的日志里能看到资源快照（RSS/内存、Electron metrics、wgc/whisper 等子进程），能对上当时相位。
- 用户看到的错误（弹框 / toast / 页面红字）与日志里的 `event=ui.error`（或等价字段）对得上，含同样的文案或错误码。
- 智能体只要 Read **最新这一份**（或用户指定的那一次启动），不必在巨型文件里检索。
- 旧会话文件有上限（例如保留最近 N 次），磁盘不会无限涨。
- 设置或日志目录可被打开；Portable / 安装版路径规则一致、可写。

## 4. 失败长什么样

- 打包后的 exe 双击运行，控制台输出全部丢掉，磁盘上没有日志。
- 弹了「无法开始录制」，日志里没有同一句话。
- 只有成片旁边一份 `*.recording-diagnostics.json`，应用启动、编辑器、导出、弹框都不在里面。
- 所有日期的日志追加进同一个 `main.log`，分析一次就要吞几万行。
- 为了「可观测」引入远程采集、账号、采样率配置等培训师用不上的东西。

## 5. 对工作流

本主题不改变录→停→编→导步骤。日志对用户默认不可见；需要时才「打开日志文件夹」。老用户无需改操作。
