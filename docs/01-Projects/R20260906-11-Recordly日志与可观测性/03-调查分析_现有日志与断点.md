# 03 · 调查分析：现有日志与断点

> 依据：2026-09-06 仓库源码（`electron/`、`src/`、`package.json`）。结论以文件为准，不是印象。

## 1. 总判断

**没有应用级可观测性。** 没有 `electron-log` / winston / pino，没有 `app.getPath("logs")` 会话文件，没有 `crashReporter`，没有 `uncaughtException` / `unhandledRejection` 落盘，没有「打开日志」入口。

现有输出分三类，**都对不上**「每一次启动一份新日志、弹框必入档」：

| 通道 | 落在哪 | 按次启动？ | 打包后还在吗 | 覆盖金路径 |
|------|--------|------------|--------------|------------|
| `console.*` | 进程 stdout/stderr | 否，流式追加到终端 | **双击 exe 通常丢掉** | 散落、无级别契约 |
| `*.recording-diagnostics.json` | 成片旁边 sidecar | 按**一条成片**，不是按启动 | 有（写得进磁盘才有） | 仅采集/混音阶段 |
| 光标 telemetry sidecar | 成片旁边 JSON 采样点 | 按成片 | 有 | 是数据，不是运维日志 |

对 `R20260906-09`（卡顿 / 鼠标不同步）：磁盘上**没有**「本次启动时间线」。最多事后翻该条录像的 diagnostics / cursor sidecar；弹框和编辑器错误不在里面。

## 2. 依赖与入口：没有日志库

`package.json` 的 `dependencies` / `devDependencies` 不含日志或 APM 包。主进程 `electron/main.ts` 只对 stdout/stderr 做了 `EPIPE` 忽略（避免管道断开把进程打崩），**没有重定向到文件**。

启动时仅有：

- `RECORDINGS_DIR` / `userData` 打到 `console.log`
- GPU 诊断只在 `RECORDLY_SMOKE_EXPORT=1` 时打印

`electron/appPaths.ts` 只钉 `userData` 与 `recordings`，没有 `logs` 目录。

全库搜索：`openLog` / `showLog` / `getPath("logs")` / `ELECTRON_ENABLE_LOGGING` / `writeLog` → **零命中**。

## 3. 主进程：`console` 当日志

`electron/` 下大量 `console.log` / `warn` / `error`，主要文件：

| 区域 | 代表 | 记什么 |
|------|------|--------|
| 窗口 | `windows.ts` | 编辑器加载失败、`render-process-gone`、PERF 计时 |
| 录制 IPC | `ipc/register/recording.ts` | 原生采集启停失败、FFmpeg、混音、存盘、光标 sidecar 读写失败 |
| Windows 采集 | `ipc/recording/windows.ts` | mux 音频失败 |
| 诊断 | `ipc/recording/diagnostics.ts` | PERF：探测时长 |
| 导出 | `ipc/register/export.ts`、`ipc/export/native-video.ts` | 导出存盘失败（仍是 console） |
| 工程 | `ipc/register/project.ts` | 打开/保存工程失败 |
| 字幕 | `ipc/register/captions.ts`、`captions/parser.ts` | 选文件失败、Whisper JSON 解析失败 |
| 设置 / 资源 | `settings.ts`、`assets.ts` | 读写失败 |
| 光标 | `cursor/monitor.ts`、`cursorHider.ts` | helper 缺失、隐藏系统光标失败 |

特点：

- 没有统一 `logger`，前缀有的有（`[mux-win]`、`[editor-window]`），有的没有。
- `PERF:MAIN` 很多，运维排障和性能探针混在一起。
- `render-process-gone` 打了 `console.error`，**没有写文件**，崩溃后更看不到。
- 没有拦截渲染进程的 `console-message`。

## 4. 渲染进程：同样只打控制台

`src/` 里 `console.error` / `warn` / `log` 很密，尤其：

- `hooks/useScreenRecorder.ts`（约 58 处 console）——录制金路径
- `lib/exporter/*`（`modernVideoExporter`、`videoExporter`、`frameRenderer` 等）——导出
- `VideoPlayback.tsx`、工程库、设备枚举

渲染进程的 console 在打包应用里默认进 DevTools，**用户不会开、也不会落盘**。主进程收不到，除非另接 IPC。

`electron/preload.ts` 没有 `log.write` 一类桥。

## 5. 成片 sidecar：唯一「像日志」的磁盘物

`electron/ipc/recording/diagnostics.ts`：

- 路径：`<videoPath 去扩展名>.recording-diagnostics.json`
- 结构：`version: 1`，`events[]`，每次 `writeRecordingDiagnosticsSnapshot` 追加相位（采集、pad、mic-sidecar、mux-*）
- 含媒体探测：体积、容器时长、视频流帧率/帧数、伴音 delay
- `processOutput` 截到约 12000 字符

**能帮忙的：** 停录后混音是否失败、视频时长是否对得上、麦克风间隙（`summarizeMicrophoneChunkTiming`）。

**帮不上的：**

- 应用启动、权限弹框、编辑器打开、导出、字幕、设置
- 画面是否丢帧、编码是否跟不上（没有 dropped-frames / fps 时间序列）
- 鼠标与画面时钟是否漂移（光标是另一份 telemetry 采样，diagnostics 不写偏差摘要）
- 跨多次启动对比（文件跟成片走，不跟「这次打开应用」走）

光标 `ipc/cursor/telemetry.ts` 写的是归一化采样点（`timeMs`、`cx`、`cy`），给回放用，不是「helper 启动失败 / 采样中断」的运维账。helper 失败只在 `cursor/monitor.ts` 的 `console.warn`。

## 6. 用户看得见的错误 vs 是否入档

### 6.1 `alert`（系统弹框）

全部在 `src/hooks/useScreenRecorder.ts`（测试里的 `javascript:alert` 不计）：

| 约略行 | 场景 |
|--------|------|
| 560 / 583 | macOS 屏幕录制 / 辅助功能权限（Windows 金路径不走） |
| 1139 / 1612 | 未选源 |

这些 `alert` **没有**配套的「写入会话日志」。同文件里有的失败会 `console.error`（如 2256），有的只有 alert。`notifyRecordingFinalizationFailure` 只 `toast.error`，不写盘。

### 6.2 主进程 `dialog.showMessageBox`

- `electron/ipc/register/recording.ts`：macOS TCC / 麦克风权限（Windows 日常用不到）
- `electron/updater.ts`：更新提示（非错误账本）

**没有** `dialog.showErrorBox`。

### 6.3 `toast.error`（Sonner）

散落在导出、工程打开/保存、字幕、字体、设置背景、快捷键、公告链接、时间轴通知等。抽查这些调用点：**没有**同时打主进程文件日志的 IPC。

代表（去重后的产品文件）：

- `useScreenRecorder.ts`
- `useExportRunner.ts` / `exportRunnerSupport.ts` / `useExportDialogActions.ts`
- `useProjectOpenActions.ts` / `useProjectSaveActions.ts`

- 公告三件套

### 6.4 编辑器整页红字

`EditorShell.tsx`：`project.error` 时渲染 `text-destructive`。来源包括 `useInitialEditorSource.ts`（无视频、加载失败等）。**只改 React state，不写盘。**

## 7. 对照用户尺子（`01` §3）

| 尺子 | 现状 |
|------|------|
| 每次启动一份新文件 | 不满足 |
| 卡顿 / 鼠标不同步能从日志对阶段 | 不满足；最多翻成片 diagnostics，且缺丢帧/时钟场 |
| 弹框 / toast / 红字入档 | 不满足 |

| 旧日志有上限 | 无会话文件，谈不上轮转；diagnostics 跟成片目录涨 |

## 8. 对 `R20260906-09` 的含义（只下诊断结论，不修卡顿）

即使现在去修卡顿，**也没有会话日志可证伪「录的时候卡 vs 整合时卡」**。  
要让日后运营能纠，必须先有：启动会话文件 + 录制/混音/导出生命周期事件 + UI 错误镜像。丢帧与光标时钟是下一层指标，可以写进同一套会话日志，不必另起一套系统。
