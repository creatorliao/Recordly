## 一、发布策略（后说的覆盖先说的）

| 层 | 决定 |
|----|------|
| **对内分发** | 只给 **解压即跑 ZIP**（`dir` 产物再压缩，或 builder 的 win `zip` 且内含 exe） |
| **构建能力** | 仍可打 NSIS，不当日常分发（备胎） |
| **单文件 portable** | 不作为默认；除非 T12 证明它比 ZIP 更不被拦 |
| **身份** | 继续 Electron |
| **彻底停打 NSIS** | 等 T3（安装包）+ T12（ZIP 内 exe）对比后再升格为死规定 |

代决原文：`R20260906-02/14` **D17**。你可在那一格改判。

## 二、分步（不跳级）

> **执行状态（2026-09-06）**：步骤 A 已做，并按 [`13`](13-方案_产物目录收敛与目录包不分发zip.md) 收紧为 **`dir` 目录包**（`release/recordly-portable-<version>/`，不打 zip）；步骤 B 已做且升级为**彻底移除**全部 GitHub 自动更新（`9dad25fe`）；步骤 C/D 未做（真机过了再说）。

### 步骤 A · 只出能跑的目录包（P0，跟轨道 B）【已做】

**改什么：** `electron-builder.json5` 的 `win.target` 增加 `dir`（和/或 `zip`）。脚本可加 `build:win:portable`，避免和现有 `build:win` 搅在一起。

**不改什么：** `app.setPath("userData")` 仍默认 AppData；金路径代码不动。

**验收：**

- `release/` 下有目录或 ZIP，打开后能见到 `electron.exe`（或当前 `executableName`）。  
- 不出现安装向导。  
- 双击能启动；走一遍录→停→编→导。  
- 监控是否拦截：**记 T12**。  
- NSIS 仍能打出来（抽查 `build:win`）。

**手册：** 加「内网：解压 → 进入目录 → 打开 exe」；写明不要发安装包给会被拦的机器。

### 步骤 B · 关掉会把人带回安装包的更新（P1，随 A 或紧接）【已做：彻底移除】

ZIP 运行时：`RECORDLY_DISABLE_AUTO_UPDATES=1` 或代码里对「非 NSIS 安装」跳过 `autoUpdater`。  
避免静默下载又一份会被拦的 installer。

### 步骤 C · 数据可选跟 exe 走（P2，真机 A 过了再做）

仅当「换电脑还要带走项目/模型」成为痛点：

- 启动最早（`app.ready` 前）检测 exe 旁 `portable.ini` 或 `data/`，有则 `app.setPath("userData", …)`。  
- **默认没有这个文件** = 行为与今天相同（N6）。  
- Whisper 模型、`recordings`、设置 JSON 会跟着走。  
- U 盘只读、多开实例要写失败提示，不要静默写回 AppData 造成「两个脑子」。

### 步骤 D · 才考虑单文件 portable（P3，可选）

仅当 T12 失败且有人证明自解压 exe 反而过关。默认不做。

## 四、建议实现要点（确认后才写代码）

1. `win.target`：`["nsis", "dir"]` 或分开脚本；`dir` 的 `artifactName` 与 NSIS 区分开，避免都叫同一个 `.exe`。  
2. 本机日常：**只要目录**（`dir`，文件夹名 `recordly-portable-<version>`）。需要网传时再手工压该文件夹。不要生成自解压 `portable`。详见 [`13`](13-方案_产物目录收敛与目录包不分发zip.md)。  
3. `signAndEditExecutable` 保持 `false`（现配置）；不引入未备案签名。  
4. 更新：未安装（`!app.isPackaged` 以外再判是否 NSIS）则 disable updater。  
5. 步骤 C 用显式标记文件，禁止「检测到 U 盘就自动搬家」。

**冲突：** 无「有了 ZIP 就没了安装包」的代码互斥。发布清单二选一即可。
