# 11 · 理解：本机采集为什么起不来，和浏览器采集差在哪

> 给培训师 / 本仓库主人把「这一段」讲清楚。现象与修法仍以 [`10`](10-问题_本机Windows采集启动失败回退浏览器.md) 为准。  
> **只讲事实，不改产品代码。**

先记一句：**这次不是权限问题，是「要运行的小程序找错地方了」。**  
系统允许抓屏、麦克风也可以用；失败发生在 Recordly **还没开始抓画面之前**——它想启动一个独立的 `wgc-capture.exe`，但指到了一个操作系统打不开的路径。

---

## 1. 点「开始录制」之后，软件其实想走哪条路

Windows 上 Recordly 有 **两条采画面的路**。正常设计是先走左边，左边起不来再走右边。

```
你点开始录制
        │
        ▼
① 先问：本机 Windows 采集能不能用？
   （系统是不是 Win10 19041+？磁盘上有没有 wgc-capture.exe？）
        │
        ├─ 不能用 → 提示「本机采集不可用」，直接走浏览器
        │
        ▼ 能用（这次就是这一支）
② 启动独立进程：wgc-capture.exe
        │
        ├─ 成功 → 本机 WGC 采屏，写成 mp4（这是 Windows 主路径）
        │
        ▼ 失败（这次就是这里）
③ toast：「本机 Windows 采集启动失败，已回退到浏览器采集。」
        │
        ▼
④ 用 Chromium 的桌面捕获（浏览器采集）继续录
   金路径没断，但成片走的是弱路径
```

这次卡在 **②**，不是卡在「Windows 不让录屏」。

三条 toast 不要混：

| 文案 | 含义 | 这次是不是 |
|------|------|------------|
| 本机 Windows 采集**不可用** | 系统太旧，或根本找不到 exe | 否 |
| **无法检测**本机 Windows 采集 | 问主进程时出错 | 否 |
| 本机 Windows 采集**启动失败**，已回退… | 检查说「能用」，真正拉进程失败 | **是** |

---

## 2. 为什么起不来：不是权限，是路径

### 2.1 先排除常见误会

| 猜测 | 这次是不是 | 怎么判断 |
|------|------------|----------|
| Windows「屏幕录制」权限没开 | **否** | 回退后浏览器采集立刻能录，说明系统允许抓屏 |
| 麦克风权限 | **否** | 错发生在启动画面 helper；麦是另一条 |
| 要以管理员运行 | **否** | `wgc-capture.exe` 不要求提权 |
| 杀毒 / 拦截把 exe 删了 | **否** | 文件还在，只是不在程序去找的那个位置 |
| Win10 太旧、不支持 WGC | **否** | 本机 19044 ≥ 19041，可用性检查已通过 |
| WGC / 显卡初始化失败 | **否** | 进程**根本没启动成功**，还没走到「Recording started」 |
| 选错屏幕 / 窗口句柄坏了 | **否** | 错误是 `ENOENT`（路径上没有可执行文件），不是「找不到显示器」 |

日志里的原句：

```text
spawn …\resources\app.asar\electron\native\bin\win32-x64\wgc-capture.exe ENOENT
```

`ENOENT` = Error NO ENTry，口语就是：**这个路径上，没有一个 Windows 能执行的文件。**  
不是 Access denied（拒绝访问），不是权限码。

### 2.2 asar 是什么，为什么「看得见、跑不起来」

打包后，大部分 JS/资源会被打进一个叫 `app.asar` 的归档（可以想成 **只能给 Electron 读的压缩包**）。

| | `app.asar`（归档） | `app.asar.unpacked`（旁边解开的真文件夹） |
|--|-------------------|------------------------------------------|
| 是什么 | 一个大文件，里面装着代码 | 普通目录，里面是真 `.exe` / `.dll` |
| Electron 的 `fs.access` | **能**「看见」里面有这个名字 | 能，而且是真文件 |
| Windows 的 `spawn` / 双击运行 | **不能**。系统不会进压缩包里执行程序 | **能** |

`wgc-capture.exe` 这种独立小程序，打包时已经按规矩放到了 unpacked 里。本机磁盘上它在：

```text
…\resources\app.asar.unpacked\electron\native\bin\win32-x64\wgc-capture.exe
```

程序却去启动：

```text
…\resources\app.asar\electron\native\bin\win32-x64\wgc-capture.exe
```

中间少了 `.unpacked`。  
Electron 检查「文件在不在」时，对着归档说「在」；Windows 真正启动进程时，对着归档说「没有这个程序」。所以：**检查过了，启动失败。** 这就是每次都会 toast 的原因。

### 2.3 为什么会指错（和「对内做成 Electron 身份」绑在一起）

对内要不被拦安装包，主程序故意叫 `electron.exe`（`productName` / 身份 = Electron，这是已拍板的 R19）。

Electron 43 看到进程名还是 `electron.exe`，就认为 **自己是开发用的裸 Electron，不是打好的应用**，于是 `app.isPackaged = false`。会话日志第一行已经写死了。

路径函数只在「已打包」时才把 `app.asar` 改写成 `app.asar.unpacked`。  
这次它以为没打包，**改写被跳过**，路径就停在归档里。

所以根因是两层叠在一起：

1. **身份策略**（必须叫 Electron）让 `isPackaged` 变假。  
2. **路径代码错误地信任 `isPackaged`**，该改写时没改写。

第一层不能改（改了又可能被内网拦）。第二层才是要修的。Whisper 模型路径已经按「不要依赖 `isPackaged`」写过了；采集 helper 还没改到同一口径。

### 2.4 用生活比喻

你把剪刀放进抽屉旁边的工具盒（unpacked）。  
软件问档案柜目录（asar）里「有没有一把叫剪刀的？」档案柜说「有这个名字」。  
它伸手进档案柜去拿，柜子是锁死的本子，拿不出真剪刀。  
于是它说「剪刀坏了，改用美工刀」（浏览器采集）。  
美工刀也能剪，但剪出来的边没有剪刀整齐。

## 3. 本机采集和浏览器采集，到底哪里不一样

两边都是「把屏幕画面变成视频」，但 **谁在采、写成什么、鼠标怎么来、质量怎么掉**，不是同一套。

### 3.1 本机 Windows 采集（设计上的主路径）

- **谁在干：** 独立进程 `wgc-capture.exe`。  
- **系统 API：** Windows Graphics Capture（WGC）。Win10 2004 / 19041 以后才有。  
- **画面：** GPU 纹理 → Media Foundation 编成 **H.264 的 mp4**。  
- **系统声 / 麦：** 同一 helper 里用 WASAPI 写成旁边的 wav，停录后再和视频对齐。  
- **鼠标：** 另起 `cursor-monitor.exe` 记位置和点击，编辑器里再叠指针、做自动缩放。  
- **和界面的关系：** 采集在自己的进程里，不跟编辑器页面抢同一条 Chromium 管道。

培训师日常应走这条：成片更稳、码率和帧率可控、后面的鼠标缩放也靠它的旁路数据。

### 3.2 浏览器采集（失败后的退路）

- **谁在干：** 还是 Recordly 这个窗口里的 **Chromium**。  
- **API：** `getUserMedia` + `chromeMediaSource`（Electron 把 `desktopCapturer` 的源塞进去）。不是再开一个 exe。  
- **画面：** 浏览器里的 `MediaRecorder` 录成 **WebM**（再转/再封装），不是 helper 那条 mp4。  
- **系统声 / 麦：** 走 Chromium 的音轨；麦和系统声有时要在页面里混。  
- **鼠标：** 可以请 Chromium 把系统指针**烧进画面**；本机 `cursor-monitor` 这次同样 spawn 失败，编辑器里的「鼠标轨迹 / 建议缩放」更容易空。  
- **和界面的关系：** 采、编、界面在同一棵进程树里，更容易和 UI 抢 CPU/GPU。

这次 toast 之后你仍然能录完、能进编辑器，就是因为退路不需要那个 exe。

### 3.3 对照表（培训师能感觉到的差别）

| 维度 | 本机 WGC（主路径） | 浏览器采集（这次实际在用） |
|------|-------------------|---------------------------|
| 要不要再开 exe | 要 `wgc-capture.exe` | 不要 |
| 输出容器 | 本机 mp4 | 浏览器 WebM 再处理 |
| 编码 | Media Foundation H.264 | Chromium / MediaRecorder |
| 鼠标数据 | `cursor-monitor` 旁路，可做自动缩放 | 这次 helper 也挂了；指针可能烧进画面，时间轴缩放容易没数据 |
| 窗口下拉菜单 | Win10 上 WGC 常**整块不进**（见 `R20260906-10`） | 窗口表面同样容易漏；选「屏幕」会好一些 |
| 成片卡顿 / 鼠标对不齐 | 仍可能（见 `R20260906-09`），但是主路径 | 回退后更容易和「采的时候就软」叠在一起 |
| 整机占用 | 独立进程，档位（30fps 等）管 helper | 和页面、Tab、GPU 进程挤在一起（见 `R20260906-12`） |
| 系统权限弹窗 | 一般不弹「分享屏幕」条 | 走 Chromium 桌面捕获；这次能录，说明权限是够的 |
| 失败时你看到什么 | 这次：起不来，toast | 无 toast，继续录 |

一句话：**浏览器采集是「网页抓桌面」；本机采集是「系统级小工具抓桌面」。**  
退路保证「还能录完」，主路径才是给培训课用的质量。

## 4. 回退之后，你实际经历了什么

1. 倒计时前后弹出那条警告（只弹一次，避免刷屏）。  
2. 录制**没有取消**，画面开始走浏览器路径。  
3. 停录一样进编辑器。  
4. 成片是退路产物：容器、码率、鼠标、是否卡，都按浏览器那套来。  
5. 同一瞬间 `cursor-monitor.exe` 也按错误的 asar 路径去 spawn，日志里是另一条 `ENOENT`。所以「采集回退」和「进 Studio 没有鼠标缩放」可以是 **同一个打包路径 bug 的两个症状**。

这和「完全录不了」不同：金路径没死，但 **G1 的质量目标没达到**。

## 5. 和旁边几份问题怎么叠（不要当成互不相关）

| 主题夹 | 和这次的关系 |
|--------|----------------|
| 本夹 `10` | 同一件事的根因、修法、验收 |
| `R20260906-10` 窗口漏下拉菜单 | 那是 **WGC 采到了之后** 菜单不进画面。这次连 WGC 都没启动，菜单问题还没轮到。修好主路径后，窗口模式仍可能漏菜单 |
| `R20260906-09` 成片卡顿 / 鼠标不同步 | 回退到浏览器后，卡顿和鼠标更容易出现；根因未在 09 里查完。先把主路径拉起来，再判断还剩多少是 09 |
| `R20260906-12` 资源占用 | 回退后 GPU / Tab 更肥；日志里这次也是浏览器在采、helper 没起来 |
| 本夹 `06` / `08` 光标遥测 | 有的是 sidecar 空写；**这一次**还有「monitor 根本没启动」。修路径后要再验 Studio 时间轴 |
| `R20260906-11` 会话日志 | 这次能 10 分钟内钉死，就是因为日志写下了 `isPackaged` 和完整 spawn 路径 |

开发态（`pnpm dev`）走源码树里的 exe，**通常不会踩这条**。所以「开发机能录、Portable 每次 toast」是符合这个根因的，不是两套业务逻辑。

## 6. 修什么、不修什么（理解用，执行仍等确认）

要修的是：**看见路径里有 `app.asar\`，就改写成 `app.asar.unpacked\`，不要问 `isPackaged`。**  
可用性检查和真正启动必须用同一条「Windows 能双击运行」的磁盘路径。  
同一改动应带上 `cursor-monitor.exe`。

不要修的是：

- 不要改成管理员启动、不要去开「屏幕录制」隐私开关当主因。  
- 不要把主程序改回 Recordly.exe（身份策略）。  
- 不要关掉本机采集、默认只用浏览器（那是掩盖）。

改完必须 **重打 Portable**。你现在解压的 `1.4.0-beta.6` 不会自己好。

详细步骤、六问、验收清单见 [`10` §5](10-问题_本机Windows采集启动失败回退浏览器.md)。
