# 分析报告：转写模型在本机怎么跑起来 · 硬性条件 · 能力边界 · GPU 加速可行性

> **一句话结论**：它跑起来靠的是**三段流水线**（Electron 主进程抽音频 → 独立的 `whisper-cli.exe` 进程做 CPU 推理 → 主进程回写时间轴），对硬件几乎没有硬门槛（8 核 CPU + 900 MB 内存就够），但**默认配置浪费了 30% 的算力**（whisper-cli 默认只用 4 个线程）；这台机器的 GPU（GTX 750 / 2014 年 Maxwell）**能跑但基本不值**——官方 v1.8.4 的 CUDA 包在它上面直接崩溃，换成 v1.9.2 的 CUDA 包能正常运行，可提速只有 **18%（英文）/ 0%（中文）**，因为卡已经跑满（平均利用率 87.5%）却依然很慢。

| 分析主题 | 本地推理链路、硬性条件、模型能力边界、GPU 加速可行性 |

## 0. 三句话结论（标-本-药）

**标（现象）**：一段 3 分半的录屏，点「生成字幕」要等约 **1 分钟**（本机实测）；中文偶尔出现整段重复的怪字幕；任务管理器里 GPU 全程 0%，因为**根本没有 GPU 版本在用**。

**本（根因，全部为本机实测）**：
1. **默认只用了 4 个线程**。whisper-cli 的默认值是 `-t 4`，而 App **从不传 `-t`**（`generate.ts:248-259`）。本机 8 核 → **一半 CPU 空转**。实测同一段英文：`-t 4` = **80.5 s**，`-t 8` = **52.4 s**（**快 35%**）。
2. **默认带着"上文"解码，会触发重复幻觉**。App 不传任何上下文/阈值参数。中文实测出现 **7 次**同一句循环字幕（相邻重复 6 条）。加 `-mc 0` 或 `--vad` 后，**重复降到 0 次，而且更快**（93.4 s → 74.3 s / 83.8 s）。
3. **GPU 这条路被两件事挡住**：官方 v1.8.4 的 CUDA 预编译包在这台 GTX 750 上**识别得出显卡、然后 4.7 秒崩溃退出**；换成 v1.9.2 的 CUDA 包能跑通，但**只快 18%（英文）**、中文**还慢 3%**——因为 GTX 750 已经被榨干（GPU 平均利用率 **87.5%**、峰值 100%），它只是**又老又慢**，不是没被用上。

**药（按性价比排序，三条）**：
1. **给 whisper-cli 传 `-t <CPU 核数>`**（改动：一行；收益：**+35% 速度**；风险：无）。
2. **传 `-mc 0` 关掉跨段上文**（改动：一行；收益：**消除整段重复幻觉 + 再快 20%**；风险：极少数跨句语境会丢，需 A/B）。
3. **启用 VAD**（改动：随包多 885 KB 的 `ggml-silero-v6.2.0.bin` + 传 `--vad -vm <path>`；收益：**重复幻觉 7→0，且更快**；风险：字幕条数变多，需看断句口味）。

> GPU 的结论是**不建议为此改造产品**：为了 +18%（英文）／0%（中文），要把安装包从约 4 MB 的 CPU 运行时换成 **640 MB 的 CUDA 运行时**（`ggml-cuda.dll` 单文件就 512 MB），性价比极低。GPU 应当是"高阶玩家自选下载"，不是默认内置。

### 1.3 测试方法与口径声明（先说清，免得数字被误用）

- **音频是合成的**：用 Windows SAPI 把固定文稿读成 WAV，再 ffmpeg 转 16 kHz 单声道。**它不是真实录屏音轨**——真实录屏有系统声、麦克风、房间噪声、口音，耗时会略高，识别率会略低。所以下面所有时间数字应读作**同机同物料下的相对比较**，不是"你的 3 分钟录屏一定 45 秒"。

- **每个配置的重复次数写明了**；单次结果标了"单次"。本机计时方差不小（同一配置 52.4–63.2 s），所以结论只看**量级差异**（35%、20% 这种），不看小数点。
- **不测中文横评**：本报告不排名"哪个模型中文最准"，只测**当前这个模型 + 当前这套参数**的真实表现。

## 2. Q1：它在本机是怎么跑起来的

### 2.1 全景：三段式流水线，只有中间那段是"模型"

```text
┌─ Electron 主进程（Node） ────────────────────────────────────────┐
│  ① 收到 IPC "generate-auto-captions"                              │
│  ② 解析引擎路径  resolveWhisperExecutablePath()                   │
│  ③ 选音频源      resolveCaptionAudioCandidates()                  │
│     候选顺序：录制 mp4 本体 → 伴生音频（system/mic）→ webcam      │
│  ④ ffmpeg 抽音频 → 临时 WAV（16 kHz / 单声道 / pcm_s16le）        │
└──────────────────────────┬───────────────────────────────────────┘
                           │  spawn 子进程（超时 30 分钟）
┌──────────────────────────▼───────────────────────────────────────┐
│  ⑤ whisper-cli.exe  ← 这里才是"模型在跑"                          │
│     -m <ggml-small.bin> -f <wav> -osrt -of <base>                 │
│     -l <语言> -np -ojf                                            │
│     · 加载 ggml 模型（465 MB）→ 内存/显存                          │
│     · 音频按 30 s 窗口编码 → 解码 → 输出 SRT + 词级 JSON           │
└──────────────────────────┬───────────────────────────────────────┘
                           │  退出，主进程读文件
┌──────────────────────────▼───────────────────────────────────────┐
│  ⑥ 读 JSON 拿词级时间戳；拿不到就退回 SRT（无词级）                │
│  ⑦ ffmpeg silencedetect 找真实停顿                                 │
│  ⑧ 按停顿重新断句（丢幻觉、合并连续语音）                          │
│  ⑨ 回写字幕轨；删除临时 WAV / SRT / JSON                           │
└───────────────────────────────────────────────────────────────────┘
```

**要点**：模型**不在 Electron 进程里**，它是一个**独立的原生 EXE 子进程**。所以它卡死不会拖垮界面，但也意味着**任何参数调优都得通过命令行参数**传进去。

### 2.2 逐步证据

| 步 | 做什么 | 证据 |
|----|--------|------|
| ① | 前端点「生成字幕」→ `window.electronAPI.generateAutoCaptions(...)` → IPC `generate-auto-captions` | 【代码】`electron/ipc/register/captions.ts:224-236`、`electron/preload.ts:718-721` |
| ② | 引擎查找顺序：用户首选路径 → **随包候选** → `WHISPER_CPP_PATH` → macOS Homebrew → `PATH` 里的 `whisper-cli.exe` | 【代码】`electron/ipc/captions/generate.ts:61-103` |
| ③ | 音频源候选：录制文件本身 → 伴生 `*.system.*` / `*.mic.*` → webcam；**逐个尝试直到成功** | 【代码】`generate.ts:105-129` |
| ④ | 抽音频命令：`-y -i <源> -map 0:a:0 -vn -ac 1 -ar 16000 -c:a pcm_s16le <wav>`，超时 **5 分钟** | 【代码】`generate.ts:148-166` |
| ⑤ | 推理命令：`-m -f -osrt -of -l -np -ojf`，超时 **30 分钟**（`timeout: 30*60*1000`） | 【代码】`generate.ts:25-30, 248-263` |
| ⑤b | JSON 不受支持时自动降级重跑（只出 SRT） | 【代码】`generate.ts:261-275`、`parser.ts:180+` |
| ⑥ | 词级 token 解析；token 时间戳缺失就整体放弃词级 | 【代码】`parser.ts:19-74` |
| ⑦⑧ | `silencedetect=noise=-30dB:d=0.5`；≥1500 ms 的停顿才切句；<150 ms 的语音段当噪声丢弃；边缘留 80 ms | 【代码】`silence.ts:17-27`、`generate.ts:189-211,294-310` |
| ⑨ | 临时文件三件套在 `finally` 里删掉 | 【代码】`generate.ts:316-322` |

### 2.3 引擎内部在干什么（whisper.cpp 侧）

- **模型加载**：读 `ggml-small.bin`（465 MB）→ 权重进内存（CPU 版）或显存（CUDA 版）。
- **音频处理**：按 Whisper 的固定 30 秒窗口做 log-Mel；**编码器**把 30 s 音频压成声学特征，**解码器**自回归吐 token（这就是为什么"上文"会影响后面的输出，也是重复幻觉的来源）。
- **输出**：SRT（整句）+ JSON（词级 `offsets.from/to`）。
- **语言**：`-l auto` 时先做一次语言检测；App 的语言下拉给了 `auto/en/es/fr/de/it/pt/zh/ja/ko` 10 项【代码】`SettingsPanel.tsx:697-708`。
- **版本**：随包的是 **whisper.cpp v1.8.4**，Windows 走官方预编译 `whisper-bin-x64.zip`（**纯 CPU 构建**，无 CUDA/Metal/Vulkan）【代码】`scripts/build-whisper-runtime.mjs:14,254-298`。

> ⚠️ **本机当前状态**：Windows 侧**还没有生成** `electron/native/bin/win32-x64/whisper-cli.exe`（该目录被 `.gitignore` 排除，需先跑 `npm run build:whisper-runtime`）。也就是说**现在这个 checkout 直接点「生成字幕」是找不到引擎的**，会走到"这台构建缺少内置运行时"的报错分支。

## 3. Q2：硬性条件

### 3.1 硬门槛（缺一个就跑不起来）

| # | 条件 | 为什么 | 证据 / 实测 |
|---|------|--------|-------------|
| R1 | **Windows x64**（本机 Win11 26200 ✓） | 随包二进制按 `win32-x64` 取；非该平台直接报 "No Whisper runtime was found for …" | 【代码】`paths/binaries.ts:29-50`、`generate.ts:99-102` |
| R2 | **Microsoft Visual C++ x64 运行库** | 缺了 `whisper-cli.exe` 起不来，退出码 `0xC0000135` | 【代码】`runtimeErrors.ts:1`、`generate.ts:32-36`；【实测·本机】我用 CUDA 11.8 包复现了 `-1073741515`，正是这个码 |
| R3 | **录制文件必须有音轨** | 没音轨就没有可转写的东西 | 【代码】`generate.ts:184-186`：`"No audio was found to transcribe…"` |
| R4 | **引擎可执行 + 模型可读** | 两者都做 `access` 检查 | 【代码】`generate.ts:227-228` |
| R5 | **首次要能访问 `huggingface.co` 下载 465 MB 模型** | main 分支唯一补模型路径 | 【代码】`whisper.ts:113-151` |
| R6 | **单次推理必须在 30 分钟内结束** | 硬编码 timeout | 【代码】`generate.ts:28` |

### 3.2 资源门槛（本机实测值，可直接当预算用）

| 资源 | small 模型实测 | 说明 |
|------|----------------|------|
| **磁盘 · 模型** | 465 MiB（487,601,967 B） | 放 `%APPDATA%\Recordly\whisper\`（dev 态 `Recordly-dev`） |
| **磁盘 · 临时 WAV** | **音频时长 × 32 KB/s** | 1 小时录屏 ≈ **115 MB**；落在 `app.getPath("temp")` = **C 盘** |
| **内存（CPU 版峰值）** | 工作集 **882 MiB** / 私有 **1,283 MiB** | 【实测·本机】采样 200 ms 一次取峰值；与 whisper.cpp 官方表 "small ≈ 852 MB" 吻合 |
| **内存（GPU 版峰值）** | 工作集 **385 MiB** / 私有 **1,685 MiB** | 【实测·本机】权重搬到显存后主机侧变小，但 CUDA 上下文把私有内存推高 |
| **显存** | 峰值 **1,025 MiB** | 【实测·本机】small 模型 + 计算缓冲；4 GB 卡余量充足 |
| **CPU** | **x86-64；AVX2 + FMA 有则明显更快；不需要 AVX-512** | 【实测·本机】i7-9700 有 AVX2/FMA、**无 AVX-512**；whisper-cli 会打印检测结果 |
| **GPU** | **不需要** | 随包是纯 CPU 构建 |
| **网络** | 仅首次下载模型需要 | 之后完全离线 |

> **一个容易踩的坑**：临时 WAV 写 **C 盘**（`%TEMP%`），而本机 **C 盘只剩 12.9 GiB**（D 盘 54.8 GiB）。**一小时的录屏 ≈ 115 MB 临时音频**，单次完全够用；但它和用户数据目录同在 C 盘，长时间批量转写时要注意。

### 3.3 性能旋钮与"默认值陷阱"（本节是全文最有价值的部分）

whisper-cli 有一堆参数，App **一个都不传**。于是全部吃默认值——而默认值是"通用保守值"，不是"你这台机器的最优值"：

| 参数 | whisper-cli 默认 | App 传了吗 | 本机实测影响 |
|------|------------------|-----------|--------------|
| `-t`（线程数） | **4** | ❌ | **-t 4 = 80.5 s → -t 8 = 52.4 s（快 35%）**【实测·本机】 |
| `-p`（并行处理器） | 1 | ❌ | 未测 |
| 文本上下文 | 开启 | ❌ | 关掉后**重复幻觉 7→0**，且 **93.4 s → 74.3 s**【实测·本机】 |
| `--vad` / `-vm` | 关 / 空 | ❌ | 开启后**重复幻觉 7→0**，**93.4 s → 83.8 s**【实测·本机】 |
| `-et`（熵阈值） | 2.40 | ❌ | 未测 |
| `-lpt`（对数概率阈值） | -1.00 | ❌ | 未测 |
| `-fa`（flash attention） | v1.8.4 无此项；**v1.9.2 默认开** | — | 开关差异 ≤ 噪声（GPU 45.1 s vs `-nfa` 50.2 s） |

**线程数细节**（v1.8.4 CPU 构建，英文 206.4 s，单次）：

| 线程 | 耗时 | 相对 |
|------|------|------|
| 4（= 默认 = App 现状） | **80.5 s** | 1.00× |
| 6 | 53.9 s | 1.49× |
| 8（= 物理核数） | **56.7 s** | 1.42× |

> 6 线程和 8 线程基本持平（这台 i7-9700 是 8 核 8 线程，没有超线程可榨），**取"物理核数"即可**。注意：**不要**机械地设成逻辑核数 ×2 之类的值——whisper.cpp 多线程超过物理核数没有收益。

## 4. Q3：这种级别的模型目前能干什么

### 4.1 它到底是个什么模型

| 项 | 值 |
|----|-----|
| 型号 | OpenAI Whisper **small**（多语言版），转成 ggml 格式 |
| 参数量 | **244 M** |
| 语言 | 多语种（Whisper 系列约 99 语），App 下拉给 9 语 + auto |
| 输入 | 16 kHz 单声道 PCM（App 已用 ffmpeg 归一） |
| 输出 | 带标点的文本 + **词级时间戳**（`-ojf` 的 JSON，本机实测 206 s 音频产出 138 KB JSON） |
| 运行方式 | 本机离线，**零 API 费用、零联网**（前置报告已确认 `API 花费为 0`） |

### 4.2 实测：英文几乎完美

TTS 英文稿（含 `Recordly`、`word-level timestamps`、`The quick brown fox…` 这类专有/固定短语），**逐字正确**，无错字、无重复、标点齐全。

### 4.3 实测：中文的真实表现（有具体错例，不是感觉）

同一段中文文稿重复 5 遍（267.6 s），baseline 输出 36 条，观察到的**三类问题**：

| 类型 | 实例 | 次数 | 性质 |
|------|------|------|------|
| **整段重复幻觉** | 「我们今天要比较**具**处理器和用显卡来加速…」连续出现、时间戳各自前推 | **7 次**（相邻重复 6 条） | ⭐ **最严重**。Whisper 的经典 failure mode：解码器陷入循环 |
| **同音/近音误识** | 「方便后**缅**做断句和排版」（应为"后**面**"） | 3 次 | 稳定复现，属模型能力上限 |
| **专有词误识** | 「**护程盒**」/「**护程和**」（应为"**护城河**"） | 2 次（两种错法） | 正是你上次复盘里记录的同类问题（护城河/roadmap/灰度测试） |
| 标点不规范 | 用**半角** `,` `?`，不是全角 `，` `？` | — | 中文排版的观感问题 |

> 注：上面「护城河、路线图、灰度测试、视频素材」是我**故意**放进测试稿的难词。结果是**路线图 / 灰度测试 / 视频素材 全对，只有"护城河"错**——这比"中文识别不行"更准确的说法是：**常用词基本可靠，专有名词/近音词是主要失分点**。

### 4.4 实测：幻觉可以按参数消掉（三条路都有效）

| 配置（中文 267.6 s） | 耗时 | 条数 | 相邻重复 | 「比较具处理器」出现 |
|----------------------|------|------|----------|----------------------|
| baseline `-t 8`（= App 现状近似） | 93.4 s | 36 | **6** | **7 次** |
| `+ -mc 0`（关文本上下文） | **74.3 s** | 41 | **0** | **0 次** |
| `+ --vad -vm ggml-silero-v6.2.0.bin` | **83.8 s** | 56 | **0** | **0 次** |

**两个都有效，而且都更快**（少了重复解码的浪费）。区别：
- `-mc 0`：更"顺"，条数 41，接近原样；代价是完全不看前文，长句跨段可能被切。
- `--vad`：条数 56，按真实语音段切得更细；对**长录屏里的静音段**收益更大（前置报告与本次都指向同一结论）。

### 4.5 它明确**做不了**的

| 做不到 | 说明 |
|--------|------|
| **说话人分离**（"谁说的"） | small 不支持；whisper.cpp 侧只有英文 `-tdrz` 模型，且前置报告未能核实其下载地址 |
| **翻译** | whisper-cli 有 `-tr`（译成英文），但 **App 没暴露** |
| **情绪 / 语速 / 重叠语音** | 不支持；两人同时说话会糊成一句 |
| **专业术语、人名、缩略语** | 就是"护城河"这种错；需要热词表或后处理纠错 |
| **标点风格定制** | 中文出来是半角，且无法指定；App 侧也没有标点后处理 |
| **富格式** | 只有文本 + 时间；没有说话人、没有置信度（`--print-confidence` 存在但 App 不用） |

### 4.6 App 在模型之外**额外做的**（这部分是产品价值，别忽略）

1. **词级时间戳 → 静音重断句**：用 ffmpeg 的真实停顿（≥1.5 s）切句，而不是听 Whisper 自己的边界。**这是它比"直接跑 whisper-cli"好的地方**。
2. **丢幻觉段**：把落在长静音里的零散词当噪声扔掉。
3. **音频源自动回退**：录制文件没音轨时，自动去找伴生 `system`/`mic` 音轨。

## 5. Q4：本机 GPU 能不能充分利用起来

### 5.1 本机 GPU 体检（先看是什么卡，再谈能不能用）

| 项 | 值 |
|----|-----|
| 独显 | **NVIDIA GeForce GTX 750**（`DEV_1381` = GM107） |
| 架构 / 算力 | **Maxwell 第一代 / compute capability 5.0**（2014 年） |
| 显存 | `nvidia-smi` 报 **4096 MiB**（空闲 4004 MiB）。⚠️ GTX 750 常见规格是 1–2 GB，4 GB 属少见/OEM 变体，**这一项存疑**（见未知清单 U1） |
| 驱动 | **560.94**，最高支持 **CUDA 12.6** 运行时 |
| 核显 | Intel UHD 630（whisper.cpp 无现成后端可用，见 §5.4） |
| Tensor Core / 快速 FP16 | **没有**（Maxwell 都没有） |

**结论先行**：这是一张**比 CPU 强不了多少**的卡。GM107 的 FP32 约 1 TFLOPS 量级；而 i7-9700 的 8 核 AVX2+FMA 也不弱。这张卡注定不可能带来现代显卡那种 5–10× 的提速。

### 5.2 三条实测结论（都做了实验，不是推断）

| # | 实验 | 结果 |
|---|------|------|
| **G1** | 官方 **v1.8.4 CUDA 12.4 预编译包**（436 MiB，自带 cudart/cublas，无需装 CUDA） | ❌ **崩溃**。日志：识别出 `Device 0: NVIDIA GeForce GTX 750, compute capability 5.0, VMM: yes, VRAM: 4095 MiB` → 紧接 `ggml-cuda.cu:98: CUDA error` → **4.7 秒退出**，退出码 `0xC0000409`。**不是"不支持 Maxwell"的拒绝**，是 CUDA 调用失败 |
| **G2** | 官方 **v1.8.4 CUDA 11.8 预编译包**（56 MiB） | ❌ **缺 DLL**。包内**没有** `cublas64_11.dll`，退出码 `0xC0000135`（DLL 未找到）→ 必须另装 CUDA 11.8 工具链，**不是即插即用** |
| **G3** | 官方 **v1.9.2 CUDA 12.4 预编译包**（639.5 MiB） | ✅ **正常运行**。`load_backend: loaded CUDA backend from …ggml-cuda.dll`，退出码 0，SRT 正常产出；**App 用的全部参数（`-m -f -osrt -of -l -np -ojf`）在 v1.9.2 上依然有效**，同时产出 `.srt` 与 138 KB 的 `.json` |

> **因此有一个明确的分水岭**：**要用 GPU，运行时必须从 v1.8.4 升到 v1.9.2**（v1.8.4 的 CUDA 后端在这张卡上有个已修掉的 bug；具体修了什么我未能定位，见未知清单 U2）。

### 5.3 提速到底有多少（跑满 GPU 也只有这么多）

**英文 206.4 s（3 次重复，取中位）**

| 配置 | 各次耗时 | 中位 | 相对 CPU |
|------|----------|------|----------|
| v1.8.4 CPU -t 8（≈ App 现状） | 52.4 / 57.6 / 63.2 | 57.6 s | 1.00× |
| v1.9.2 CPU `--no-gpu` -t 8（同一二进制） | 66.7 / 53.1 / 55.0 | 55.0 s | 1.05× |
| **v1.9.2 GPU（默认）** | **45.1 / 46.9 / 44.7** | **45.1 s** | **1.28×（快 18%）** |
| v1.9.2 GPU `-nfa`（关 flash attention） | 50.2（单次） | — | — |

**中文 267.6 s（2 次重复）**

| 配置 | 各次耗时 | 中位 |
|------|----------|------|
| v1.9.2 CPU `--no-gpu` -t 8 | 86.2 / 87.5 | 86.9 s |
| **v1.9.2 GPU** | 91.1 / 88.8 | **90.0 s（比 CPU 慢 3%）** |

**为什么"充分利用"了却还是不快——用采样证明**：

```
v1.9.2 GPU 运行期间（300 ms 采样一次，共 121 个点）：
  GPU 利用率  最大 100%   平均 87.5%
  利用率分布  80–99%: 93 点   100%: 19 点   60–79%: 3 点   0–19%: 5 点
  显存峰值    1025 MiB
```

**GPU 是真的在满负荷跑**（近八成时间在 80–100%），不存在"没 offload 上去""CPU 在等 IO"这种问题。**它就是慢**，原因有四条：

1. **Maxwell 没有 Tensor Core，也没有快速 FP16** → ggml 的 fp16 路径帮不上忙。
2. **ggml 对 ≤ Pascal 的卡关掉了 MMQ（量化矩阵乘快速核）** ——【实测·抓取】`ggml-cuda.cu` 里有 `if (cc <= GGML_CUDA_CC_PASCAL)` 的降级分支。量化模型在这张卡上拿不到专用 kernel。
3. **显存带宽低**（GM107 约 80 GB/s 量级），Whisper 解码是带宽敏感的。
4. **whisper-small 太小**（244 M），大部分时间花在串行解码循环上，能并行化的矩阵运算占比不够高——**GPU 的加速比本来就随模型变小而衰减**。

> 另外：**GPU 版与 CPU 版的字幕文本逐字完全相同**（我对同一段中文做过全文比对，`True`）。所以"上 GPU"**只影响速度，不影响准确率**——flash attention 在 CC 5.0 上也没有引入质量劣化。

### 5.4 要让 GPU 真正发挥作用，需要什么

| 方案 | 可行性（本机） | 代价 | 判断 |
|------|----------------|------|------|
| **a. 升级运行时到 v1.9.2 + CUDA 12.4 包** | ✅ 已实测跑通 | 安装包从 ~4 MB 运行时涨到 **640 MB**（`ggml-cuda.dll` 单文件 **511.9 MiB**，`cublasLt64_12.dll` 451.6 MiB） | ⚠️ **只对"有 NVIDIA 卡的自己人"值**，不适合做默认内置 |
| b. 自编译 `-DGGML_CUDA_NO_VMM=ON -DCMAKE_CUDA_ARCHITECTURES=50` 打在 v1.8.4 上 | ⚠️ 未验证。上游确实有 `GGML_CUDA_NO_VMM` 这个 opt-out（【实测·抓取】`ggml-cuda/CMakeLists.txt:146-147`），且 llama.cpp 有多个"某些配置下 VMM 不可用"的 PR | 需要装 CUDA Toolkit + VS Build Tools；自编译包还得自己维护 | ❌ **投入产出不划算**（换 v1.9.2 现成包已经能用） |
| c. 用 **Intel UHD 630** 核显 | ❌ whisper.cpp 的 Intel GPU 路径是 **OpenVINO**，需要 OpenVINO 运行时 + 专门的 encoder 模型（`*-encoder-openvino.xml`），官方 Windows 预编译包里没有 | 高 | ❌ 不做 |
| d. Vulkan 后端 | ⚠️ GTX 750 支持 Vulkan，whisper.cpp 有 `-DGGML_VULKAN=1`，但**官方 Windows 预编译包不含 Vulkan 版**，要自编译 | 中高 | ❌ 不做 |
| e. **换更好的卡** | — | 硬件钱 | 唯一能真正改变"GPU 有没有意义"的选项 |

### 5.5 还有一个"卡在哪"的细节：App 现在**没法**让你换引擎

`electron/ipc/captions/generate.ts` 的引擎查找顺序是：

```text
用户首选路径 → 随包候选(whisper-cli.exe) → WHISPER_CPP_PATH → (mac)Homebrew → PATH 查找
```

- **随包候选排在环境变量前面**。所以在**打包后的 App** 里，即使你用 `WHISPER_CPP_PATH` 指向 CUDA 版，**随包的 CPU 版仍然优先**——**换不动**。
- UI 上有"选择模型"按钮，但**没有"选择 Whisper 可执行文件"按钮**：`SettingsPanel.tsx:637` 声明了 `onPickWhisperExecutable` 这个 prop，`useEditorSettingsPanelProps.ts:204` 也把回调接上了（`useAutoCaptionController.ts:102` 会调 `openWhisperExecutablePicker()`），**但面板里从头到尾没有渲染出这个入口**。
- **在当前这个 Windows checkout 上反而"能用"**：因为 `electron/native/bin/win32-x64/whisper-cli.exe` **还没生成**（随包候选落空），所以 `WHISPER_CPP_PATH` 会生效。**这是本机做 GPU 实验的唯一现成路径**（我就是这么验证 G3 的）。

> 顺带一个**报错误导**：`runtimeErrors.ts` 把**所有** `0xC0000135`（DLL 未找到）都判定成"缺 VC++ 运行库"。我实测 CUDA 11.8 包（缺 `cublas64_11.dll`）也报同一个码，界面会提示"请安装 Microsoft Visual C++ x64 Redistributable"——**用户照做也不会好**。

## 7. 风险与坑

| # | 坑 | 证据 | 提示 |
|---|----|------|------|
| K1 | **默认 4 线程**（8 核机器半闲置） | 【实测·本机】`--help` 显示 `-t [4]`；`generate.ts` 不传 `-t` | 这是现在最大的、免费的性能损失 |
