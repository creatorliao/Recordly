# 方案：可选路径与决策建议

> 等人确认后再动手。本页只给决策，不改代码。

## 一、推荐总架构（不论选哪条底座都按这个切）

```text
录制器                    分析器                      执行器（按对象插）
屏幕 + 键鼠钩子      →    步骤压缩 + 意图        →    Electron: Playwright/CDP
窗口/进程证据              定位器绑定                    标准 Win: UIA (FlaUI/pywinauto)
点击瞬间截图               （可选 OmniParser 框）         自绘: 找图/OCR + 热键
UIA 快照（可空）           成功判据                       失败: 停，不要盲点
DOM（仅 Electron）
        ↓
   桌面 archive（自己的格式或 OpenAdapt rec）
        ↓
   生成「自动化应用」（脚本/MCP 工具/现有 rpa-agent 应用壳）
```

原则：

1. **分析可以调模型；健康回放尽量不调模型**（对齐你已有网页交付物）。
2. **定位器分层**，禁止「全程只有坐标」。
3. **三类对象不要共用一个假 DOM**；Electron 走真 DOM，其余走 UIA 或视觉。
4. **不要改造 Recordly 成 RPA**。本仓继续做视频；桌面录制另起工作区或另仓。

## 二、四条可选路径

### 方案 S1 — 改造 OpenAdapt（最贴金路径）

**做什么**：把 OpenAdapt / openadapt-capture / openadapt-flow 当底座；补中文 IME、你关心的三个客户端资格报告、以及「导出成你现有自动化应用壳」。

| 维 | 判断 |
|----|------|
| 优点 | 录-编-放闭环已在；Windows 后端明确；理念与「生成应用」一致 |
| 缺点 | Beta；微信/企微未担保；要啃编译产物与资格矩阵 |
| 适合 | 你要的是「可重复工作流产品」，而不是聊天式玩电脑 |
| 改造量 | 中：接中文输入、接你们的应用打包、对 (a)(b) 写视觉锚 |

### 方案 S2 — 自建薄录制器 + 现成执行器（可控、工作量大）

**做什么**：自己写 Windows 录制器（可抄 Recordly 的钩子思路，但**新项目**）：事件 + 窗 + 截图 + UIA 快照 → 自有 archive → 智能体填定位器 → 回放调用 FlaUI / Playwright / 找图。

| 维 | 判断 |
|----|------|
| 优点 | 格式完全按你网页 rpa-agent 习惯设计；不绑 OpenAdapt 生命周期 |
| 缺点 | 「编译与自愈」要自己做；>500 行很容易，需拆阶段 |
| 适合 | 你已有网页分析/生成流水线，只要桌面档形状对齐 |
| 零件 | 钩子：`uiohook` / Win32；树：FlaUI-MCP 或 pywinauto；Electron：Playwright；视觉：OmniParser + SikuliX |

### 方案 S3 — Computer-Use 助手（UI-TARS / Agent-S / UFO）

**做什么**：装 UI-TARS Desktop 或接 OmniParser，让模型看着屏复现。

| 维 | 判断 |
|----|------|
| 优点 | 开箱能点未知界面；对 (a)(b) 探索最快 |
| 缺点 | 不是「生成应用」；每次推理、贵、难回归；和网页金路径交付物不一致 |
| 适合 | **只做分析器/修复器**，或第一周人工看「模型能不能讲清步骤」 |
| 建议 | 可作 S1/S2 的感知插件，**不要当主方案** |

### 方案 S4 — 应用专用库拼装（wxauto / pywechat / wx_work_auto）

**做什么**：不为「任意步骤」建模，只封装「发消息、开会话」等已知 API。

| 维 | 判断 |
|----|------|
| 优点 | 对固定业务快 |
| 缺点 | 不是录制器；版本一升级就废；部分仓带 DLL/解密，合规风险 |
| 适合 | 你的日常其实只有少数几个微信动作——那就别上通用 RPA |
| 建议 | 当控件字典与反例，不作为改造母体 |

## 三、综合打分（闸门后，1–5，5 最好）

闸门：落进「桌面金路径」；不过度设计；不默认改 Recordly；不把逆向当底座。

| 方案 | 风险 R（高=更安全） | 贡献 C | 效能 E | S≈ | 建议 |
|------|---------------------|--------|--------|-----|------|
| S1 OpenAdapt | 3.5 | 5 | 4 | **4.1** | 优先试点 |
| S2 自建录制器 | 3 | 5 | 3.5 | 3.8 | 若 S1 资格不过或协议不合再上 |
| S3 Computer-Use 主路径 | 2.5 | 3 | 3 | 2.8 | 仅插件 |
| S4 专用库母体 | 2 | 2.5 | 4 | 2.7 | 仅窄业务 |
| 改 Recordly | 2 | 1 | 2 | 1.7 | 不做 |

公式与 `AGENTS.md` 一致：`S = 0.40R + 0.35C + 0.25E`。

## 四、对象 × 技术对照（落地时按此选执行器）

| 对象 | 第一定位器 | 回退 | 第一期建议 |
|------|------------|------|------------|
| Electron（你能加启动参数） | CDP / Playwright DOM | UIA | **先打穿**，对齐现有网页流水线 |
| Electron（别人打包、无调试口） | UIA | 视觉 | 第二期 |
| 标准 Win32/WPF | UIA（FlaUI-MCP / pywinauto） | 视觉 | 与 Electron 并行做「记事本级」探针 |
| 微信 4.x | 视觉 + 热键；UIA 能用再升 | 坐标最后 | 只探针，不承诺生成通用应用 |
| 企业微信 4.x | 同上（DirectUI） | 降版本仅作实验，不作产品依赖 | 只探针 |

Mac：与 Windows 对称，用 Accessibility 树替换 UIA；Electron 仍走 CDP。第一期可不做 Mac。

## 五、建议的第一期（若你点头）

6 周量级、可停、可验，不一次做完三类对象：

1. **周 1**：本机跑 OpenAdapt tutorial + `record --backend windows` 对记事本；另用 Playwright 对一个开了 CDP 的 Electron 示例走「录-放」。写出资格表（过/不过）。
2. **周 2**：微信、企微各录 3 步（点会话、点输入区、粘贴发送）。记录 UIA 是否为空、找图是否稳。写入本夹 `05-探针记录`（尚未建，确认后建）。
3. **周 3–4**：按探针选 S1 或 S2；定义桌面 archive 字段（事件、窗、图、UIA、DOM）。
4. **周 5–6**：只把 **Electron 一条**接到「智能分析 → 生成应用」；微信/企微若探针失败则写入暂缓，不堵主路径。

Recordly：继续当视频产品，**零行**进 RPA。钩子代码只允许**阅读参考**。
