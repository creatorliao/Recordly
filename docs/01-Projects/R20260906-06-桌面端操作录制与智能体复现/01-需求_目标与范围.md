# 需求：桌面端操作录制 → 智能体理解 → 自动化复现

## 一、角色与为什么要做

| 项 | 内容 |
|----|------|
| 角色 | 日常在 Windows（及将来 Mac）上操作客户端软件的人，希望把重复步骤变成可回放的自动化应用 |
| 已有能力 | **网页**自动化录制已打通（Playwright 式：点网页 → 存操作序列 → 智能体理解 → 生成应用） |
| 缺的一段 | **桌面客户端**没有同等链路：微信、企业微信、Electron 封装应用没有网页那种稳定 DOM |
| 金路径 | 启动录制 → 在屏幕上点击/键入 → 停止并落盘 → 智能体分析步骤与逻辑 → 生成可复现的自动化应用 |
| 衡量 | 同一台机器、同一套窗口布局下，生成的应用能走完一次「曾亲手做过」的步骤；失败时能指出卡在哪一步，而不是瞎点 |

本主题**不服务** Recordly 的「录课导出视频」。Recordly 只是调查起点：它已经会记鼠标，用来对照「记下来的东西能不能给 AI」。

## 二、原始问题（原话压缩）

1. Recordly 能录鼠标操作，它是怎么做的？记下来的是什么？AI 能不能理解？
2. 有没有可能做成：日常工作录成操作序列 → AI 理解步骤与逻辑 → AI 帮我复现？
3. 希望基于开源项目改造，而不是从零发明一套。不知道该用什么技术、方法和仓库。

## 三、目标流程（必须对齐）

```text
① 启动录制     用户在 Windows 或 Mac 上对第三方客户端点、键
② 存储数据     停止后落盘（结构化事件 + 证据，而不是只有视频）
③ 智能分析     智能体读档，还原步骤与意图
④ 生成应用     产出可重复执行的自动化（类似现有网页 RPA 应用）
```

操作对象（重点）：

| 类型 | 例子 | 用户心里的「DOM」 |
|------|------|-------------------|
| (a) 微信 PC | 个人微信客户端 | 会话、输入框、按钮——多数**不是**网页 DOM |
| (b) 企业微信 | WXWork | 同上，新版本大量自绘 |
| (c) Electron 封装桌面应用 | 各类用 Chromium 壳的工具 | **才有**真正的 DOM / CDP，最接近 Playwright |

用户描述的核心实现：

1. **录制**：鼠标点击、键盘输入等。
2. **智能体找目标**：在界面上找到对应「控件 / 视觉目标」（用户说 DOM，见下文纠正）。
3. **模拟执行**：对目标做同等操作（RPA 回放）。

## 四、必须先钉死的技术事实（调查结论预告）

桌面端**没有统一 DOM**。

| 表面 | 真正可抓的结构 | 接近 Playwright 的程度 |
|------|----------------|------------------------|
| Electron / 内嵌 WebView（开了调试口） | Chromium DOM + CDP | 高，可沿用现有网页录制思路 |
| 标准 Win32 / WPF / 部分 Qt | Windows UI Automation 树（无障碍树） | 中，像「桌面版 DOM」 |
| 微信 4.x / 企业微信 4.x 自绘 | 树经常空或残缺，只能截图 + OCR + 坐标/图像匹配 | 低，必须视觉层 |
| macOS AppKit | Accessibility (AX) 树 | 中，与 UIA 同类 |

因此「智能体在界面上找到对应 DOM」对 (a)(b) **字面做不到**；要对 (c) 才字面成立。方案里应改称：**按应用类型选定位器（DOM / UIA / 图像+OCR）**，而不是强行找 DOM。

## 五、范围

**做（本夹）**

- 写清 Recordly 现有鼠标链路与落盘格式。
- 联网检索开源项目，按「录制 / 理解 / 回放」拆类。
- 给出可改造的底座与分层方案，等人拍板。

**不做（本夹）**

- 不改 Recordly 产品代码，不把视频编辑器改成 RPA。
- 不代实现微信/企微逆向、DLL 写入、本地库解密。
- 不承诺一次改造就覆盖全部客户端；先选一条可验证的窄路径。

**合规围栏**

- 只自动化**自己账号、自己机器、自己工作步骤**。
- 不把「破解客户端 / 读加密库 / 热补丁 DLL」当推荐底座（调查里会点名存在，并标风险）。
- 微信 / 企业微信官方使用条款通常禁止未经授权的自动化；应用专用库只能当参考，不能当合规保证。

## 六、成功 / 失败（拍板用尺子）

成功（第一期建议）：

1. 对**一个可控 Electron 应用**走通：录 → 档 → 分析 → 回放（DOM/CDP）。
2. 对**一个标准 Windows 窗口**（记事本 / 资源管理器）走通：录 → UIA 快照 → 回放。
3. 对微信或企微只做**探针**：录一次，看 UIA 树是否为空、截图+点击坐标能否复现 3 步以内的固定流程；据此决定视觉层投入。

失败：

- 只用 Recordly 的 `*.cursor.json` 让模型「理解并复现」日常工作（缺键盘、缺控件、缺截图像素语义）。
- 假设所有目标都有 DOM。
- 选一个只会「每次重新看屏幕瞎点」的 Computer-Use 智能体当唯一产物——那是助手，不是可交付的自动化应用。
