# 调查：开源项目与线上同类方案

检索时间：2026-09-06。星数以当日 `gh repo view` 为准，会变。  
检索关键词：desktop RPA record-replay、computer-use、UI Automation、WeChat/企微自动化、Electron Playwright/CDP。

## 一、先分清四类东西（不要混着选）

| 类 | 它解决哪一段 | 产物 | 适不适合「生成可维护应用」 |
|----|--------------|------|----------------------------|
| A 演示编译 / 录一次编成脚本 | 录 → 存 → 编译 → 确定性回放 | 本地程序，健康路径可不调模型 | **最贴你的金路径** |
| B 控件树驱动（UIA / AX / DOM） | 找得到树就能像 Playwright 点 ref | 脚本或 MCP 工具 | 标准窗、Electron 强；微信 4.x 弱 |
| C 视觉 Computer-Use 智能体 | 每步看图再点 | 对话式助手 | 探索好、当唯一产物差（贵、飘、难验收） |
| D 应用专用库 | 只打微信/企微某几个动作 | Python API | 能抄控件经验，不能当通用录制器 |

你的网页链路属于 **A + B（DOM）**。桌面要对 (c) 复制同一配方；对 (a)(b) 必须 **A + C 兜底**，B 经常失效。

## 二、A 类：录制 → 编译 → 回放（最接近目标）

### 1. OpenAdapt 家族（首选对照）

| 仓 | 星 | 许可 | 一句话 |
|----|----|------|--------|
| [OpenAdaptAI/OpenAdapt](https://github.com/OpenAdaptAI/OpenAdapt) | ~1715 | MIT | 启动器：演示一次，编译成带独立校验的程序 |
| [OpenAdaptAI/openadapt-flow](https://github.com/OpenAdaptAI/openadapt-flow) | 少（新引擎） | MIT | 编译器：健康回放零模型调用；漂移则重解析或停 |
| [OpenAdaptAI/openadapt-capture](https://github.com/OpenAdaptAI/openadapt-capture) | ~13 | MIT | 原生桌面录制：屏幕、输入、时间、窗口证据对齐 |

文档：[docs.openadapt.ai](https://docs.openadapt.ai/)

它明确覆盖：浏览器、**Native Windows（WAA/UIA）**、macOS、Linux、RDP/Citrix。命令形态接近：

```text
openadapt-flow record --backend windows --window "Target App" --task "…" --out rec
openadapt-flow compile rec --out bundle
openadapt-flow replay bundle --backend windows
```

**为什么贴你的目标**

- 金路径就是「录日常 → 存证据 → 编成可跑应用」，不是「每次让大模型重新玩电脑」。
- 落盘不是 Recordly 那种纯坐标：带窗口范围与视觉锚。
- 漂移时停下来等人/模型，而不是默默点错。

**风险**

- `openadapt-flow` 自标 Beta，针对每个应用要单独资格认证。
- 对微信/企微自绘，官方不会替你保证；要自己跑探针。
- 引擎新、文档密，改造成本在「读懂编译产物」而不在「会不会 hook 鼠标」。

### 2. 传统图像录放（SikuliX / Lackey / PyAutoGUI）

[SikuliX](https://github.com/RaiMan/SikuliX1)（MIT）：截按钮图 → 屏幕找图点击。Java 生态。  
**能**覆盖自绘客户端，**不能**单独给 AI 高质量语义；分辨率、主题、缩放一变就碎。适合当**视觉执行器插件**，不适合当唯一底座。

## 三、B 类：桌面「DOM」——控件树 / CDP

### 1. Windows UI Automation

| 仓 | 星 | 许可 | 备注 |
|----|----|------|------|
| [pywinauto/pywinauto](https://github.com/pywinauto/pywinauto) | ~6156 | BSD-3 | Python；`win32` / `uia`。作者一直想做可靠 record-replay，**至今不是产品级录制器** |
| [FlaUI/FlaUI](https://github.com/FlaUI/FlaUI) | ~3115 | MIT | .NET 里最常用的 UIA3 库 |
| [shanselman/FlaUI-MCP](https://github.com/shanselman/FlaUI-MCP) | ~91 | MIT | 把 UIA 树暴露成 MCP：`windows_snapshot` 出 ref，再 `windows_click` —— **口号就是「Playwright 对桌面」** |

FlaUI-MCP 的工具面：启动、快照、点、键入、填空、取文本、截图、列窗、聚焦。  
这是智能体「找到对应控件」在 **标准 Windows 应用**上的正确接口。  
微信 4.x / 企微 4.x：**树经常空**（见 D 类仓库自己写的原因）。

### 2. Electron = 真 DOM（应复用你已有网页能力）

| 路径 | 说明 |
|------|------|
| Playwright `_electron.launch` | 官方实验支持：起你的 Electron，拿 `Page`，选择器和网页一样 |
| `connectOverCDP` + 启动参数 `--remote-debugging-port=9222` | 附着已运行、开了调试口的壳 |
| [electron-stagewright/electron-stagewright](https://github.com/electron-stagewright/electron-stagewright) | MIT，MCP：launch / attach / inject；星少、方向对 |

对 (c)：**不要重新发明桌面钩子**。优先：能控启动参数 → CDP → 现有 rpa-agent 网页录制几乎可平移。  
打包后的别人家 Electron：若对方关死调试口，只能退回 UIA 或视觉。

### 3. JS 桌面驱动

[nut-tree/nut.js](https://github.com/nut-tree/nut.js)（~2848）：Node 里鼠标键盘 + 找图。核心开源，高级插件（OCR、录屏、RDP）走订阅。适合当你已有 TS 栈、只要**执行器**，不是完整「录制编译器」。

## 四、C 类：看屏幕的智能体（理解强、当应用弱）

| 仓 | 星 | 许可 | 角色 |
|----|----|------|------|
| [bytedance/UI-TARS-desktop](https://github.com/bytedance/UI-TARS-desktop) | ~38867 | Apache-2.0 | 端到端桌面 Computer-Use 应用 + Agent TARS |
| [microsoft/OmniParser](https://github.com/microsoft/OmniParser) | ~25372 | CC-BY-4.0 | 截图 → 可点元素框，给任意 VLM 当感知层 |
| [simular-ai/Agent-S](https://github.com/simular-ai/Agent-S) | ~12231 | Apache-2.0 | 规划 + 记忆 + grounding，偏研究框架 |
| [microsoft/UFO](https://github.com/microsoft/UFO) | ~9651 | MIT | UFO³，Windows 系智能体 / 多设备 |
| [trycua/cua](https://github.com/trycua/cua) | ~22250 | MIT | 沙箱/虚拟机里跑 computer-use，偏评测与安全隔离 |

线上综述（2026）：[Open-Source Computer-Use Agents](https://dreaming.press/posts/open-source-computer-use-agents.html)、[17 Best Computer-Use AI Agents](https://www.turingpost.com/p/computer-use-ai-agents) 都把栈拆成：**代理循环 / 接地模型 / 屏幕解析 / 沙箱**。OpenAdapt 被单独标成「录一次，编成确定性回放」。

**怎么用在你的目标里**

- 分析阶段：OmniParser 或 UI-TARS 把「点击坐标」抬成「第 17 号框 = 发送」。
- 回放阶段：健康路径应走编译脚本（UIA/DOM/图像锚），**不要**每步再调 72B。
- 单独把 UI-TARS Desktop 当「生成应用」：你得到的是每次都要模型在场的助手，和现有网页 RPA 交付物不一致。

## 五、D 类：微信 / 企业微信专用（对象 a、b）

事实（各仓库 README 自述，2026）：

| 仓 | 星 | 做法 | 对你的含义 |
|----|----|------|------------|
| [cluic/wxauto](https://github.com/cluic/wxauto) | ~7293 | 经典 UIA；**微信 4.x 自绘后树断** | 3.9 时代经验，不能当 4.x 底座 |
| [Hello-Mr-Crab/pywechat](https://github.com/Hello-Mr-Crab/pywechat) | ~1895 | pywinauto，宣称支持 4.x 部分操作，无 Hook | 可作「按钮怎么点」的手册，版本绑定极紧 |
| [fanyuantaier/wechatauto-replica](https://github.com/fanyuantaier/wechatauto-replica) | 检索可见 | 读本地 SQLCipher 库 + UIA/OCR；并写 Weixin.dll 打开无障碍门 | **能力强、合规与稳定性风险高，不推荐当改造底座** |
| [yangyuexiong/wx_work_auto](https://github.com/yangyuexiong/wx_work_auto) | ~2 | 企微 4.1 为 DirectUI，无标准 UIA Pattern；建议降到 3.1.10 或 热键+找图 | 证明 (b) 与「找 DOM」冲突；4.x 要视觉/热键 |

**探针结论（文献级，待你本机验证）**

- (a)(b) 新客户端：**不要假设存在可点的 DOM/UIA**。
- 通用录制器应在点击瞬间同时存：坐标、截图、当时 UIA 快照（可空）、前台进程。
- 回放策略：UIA 命中则走控件；否则 OCR/找图；再否则坐标（最脆）。
- 专用库适合「已知动作」（发消息给某人），不适合「任意日常步骤录一遍就生成应用」。

## 六、和「网页 Playwright 录制」的对照

| | 网页（你已有） | 桌面目标 |
|--|----------------|----------|
| 结构真源 | DOM + 选择器 | 分层：CDP / UIA / 像素 |
| 录制器 | Playwright codegen / 你们的 rpa-agent archive | 缺通用开源「桌面 codegen」；OpenAdapt-capture 最接近 |
| 分析 | 选择器 + 截图，模型很好用 | 必须喂「步骤 + 框 + 窗」，不能只喂 cx/cy |
| 回放 | Playwright | Electron→Playwright；Win 标准窗→FlaUI/pywinauto；自绘→Sikuli/OCR |
| 稳定 | 高 | 标准窗中；微信/企微低，要资格认证 |

## 七、可行性总判

**可能实现，但不能用一个仓库打穿三类对象。**

1. 工程上：钩子、截图、UIA、CDP、找图都是成熟零件。
2. 产品上：缺的是「桌面 archive 格式 + 编译成应用」——OpenAdapt 在做这件事，FlaUI-MCP / Playwright Electron 覆盖执行两端。
3. 对象上：(c) 半年内最可能做出和网页同品质的东西；(a)(b) 要接受「视觉 RPA + 窄场景」，并做本机探针后再加码。

没有检索到「开箱即用、专打微信+企微+任意 Electron、录完自动生成可维护应用」的单一明星项目。合理策略是**选一个 A 类引擎或自建薄录制器，再按对象插 B/C 执行器**。
