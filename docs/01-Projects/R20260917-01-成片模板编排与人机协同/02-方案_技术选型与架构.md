# 02 · 方案：技术选型与架构

> 决策依据见 `03-决策_ADR.md`；全部事实依据见 `04-借鉴_Recordly实现分析.md`。
> **本方案不修改 Recordly 源码**（唯一例外：`fontFamily` 走上游 PR，见 ADR-05）。

---

## 1. 一句话方案

> 做一个**独立 CLI（`rlc`）+ 伴生 Skill**，把「已有 MP4 + 三类文档」编排成一个**项目**；
> 项目的纯文本副本是唯一事实源，`.recordly` 是每次由工具再生的**制品**；
> 出片复用 `rlex`。人可以在**五个代价递增的协同面**上任选其一插手，
> 工具用**交接锁 + 字段映射**保证人的改动不丢、AI 能接着跑。

---

## 2. 架构总览

```
┌─────────────────────────── 人的五个协同面（任意一个即可） ───────────────────────────┐
│  S0 无（AI 全自动）   S1 文本（.srt/.toml）   S2 试穿（对比图）   S3 Recordly GUI   S4 rld 体检  │
└───────┬────────────────────┬──────────────────────┬──────────────────┬─────────────────┘
        │                    │                      │                  │
        ▼                    ▼                      ▼                  ▼
┌──────────────────────────────────────────────────────────────────────────────────────┐
│                            项目（唯一事实源，可整体拷贝）                              │
│   compose.toml │ captions.srt │ style.toml │ media/ │ vendor/ │ .compose/state.json    │
└──────────────────────────────────────────────────────────────────────────────────────┘
        │                                            ▲
        │ apply（文本 → 制品，幂等，默认 dry-run）      │ pull（制品 → 文本，带差异 + 解锁）
        ▼                                            │
┌───────────────────────────────────────┐   ┌────────┴──────────────────────────────┐
│  编排层（纯离线，不需要 Recordly）      │   │  交接层                                │
│  init / import-* / template / review  │   │  锁协议 · 指纹校验 · 留痕 · 备份        │
│  apply / verify / relocate / status   │   └───────────────────────────────────────┘
└───────────────────┬───────────────────┘
                    │ build/<name>.recordly
                    ▼
┌───────────────────────────────────────┐
│  渲染层（需要 Recordly 运行体）         │
│  rlc export  →  rlex export run        │   ← 复用，不自研
│              →  <name>.mp4 + report    │
└───────────────────┬───────────────────┘
                    ▼
┌───────────────────────────────────────┐
│  验证层                                │
│  rlc verify（项目自检）· rld（成片体检）│
└───────────────────────────────────────┘
```

**关键分层原则**：**编排层完全离线**（对标 `rlz` 的"纯离线、不需要运行体"），
只有 `export` 需要 Recordly 在场。这让 80% 的功能可以无 Recordly 开发与测试。

## 3. 技术选型

| 层 | 选型 | 理由 |
|:---|:---|:---|
| 语言 | **Python 3.12** | 家族四仓一致（`rlex`/`rlz`/`rld` 都是 Python + Typer） |
| CLI 框架 | **Typer** | 家族一致；免费拿到 `--help`、补全、类型校验 |
| 数据校验 | 自写白名单校验（对标 `rlex/core/schema.py`） | 需求是"逐条报出"，不是抛异常 |
| 文档转图 | **pypdfium2**（BSD-3-Clause / Apache-2.0） | ⚠️ **许可证优先于"本机已装"**：PyMuPDF (`fitz`) 本机可用但为 **AGPL-3.0**，并入 MIT 仓即冲突。pypdfium2 同为一步到位的 PDF 渲染且许可宽松。**本机未装**，需加依赖。依据见 `01-需求` §11.5、ADR-07 |
| DOCX/PPTX | 走 `documents2md` / `pptx-creator` 技能族，或先转 PDF | 【实测】本机**无 LibreOffice**，不能本地光栅化 |
| 图像处理 | **Pillow** | 【实测】可用；缩页、JPEG、拼对比图 |
| 视频工具 | **ffmpeg / ffprobe**（经 `ffmpeg-cli` 解析路径） | 家族一致；抽帧、`overlay` 模式合成、媒体事实 |
| 项目配置 | **TOML**（`compose.toml` / `style.toml`） | 人可读、可注释；比 JSON 友好，比 YAML 不易踩缩进 |
| 字幕 | **SRT**（`captions.srt`） | 与既有链路（`subgen`/`subtitle-optimize`/`subtitle-burn`）无缝 |
| 渲染 | **调用 `rlex`** | ADR-02：不变量，不重复实现导出 |

**三通道（家族惯例）**：同一份 `core/`，三个人口 ——
① 人用 CLI（`rlc`）；② 智能体 Skill（`.agents/skills/recordly-compose-master/`）；③ 程序 API（`rlc api list` 列出）。

## 4. 项目结构

```
<项目目录>/
├─ compose.toml              # 项目清单（SSOT 入口）
├─ captions.srt              # D1 字稿（权威副本，人可直接改）
├─ style.toml                # D3 字幕/画面样式（权威副本）
├─ template.toml             # 选用的模板 + 覆盖项
├─ media/                    # D2 内容文档转出的画面素材
│   └─ doc-p01.jpg ...
├─ vendor/                   # 原样携带的 Recordly 侧车（跨机必需，ADR-08）
│   ├─ <video>.cursor.json
│   └─ <video>.recordly-session.json
├─ .compose/
│   ├─ state.json            # 交接锁 + 留痕 + 上次 pull 指纹
│   ├─ backup/               # 写盘前备份（ADR-04 R6）
│   └─ logs/
└─ build/                    # 再生区：可整目录删除后重建
    ├─ <name>.recordly
    ├─ <name>.mp4
    ├─ <name>.mp4.report.json
    └─ review/
        ├─ fast-<模板名>.png
        └─ strip-render.mp4
```

### 4.1 `compose.toml` 示例

```toml
[project]
name = "红杉第一篇"
created = "2026-09-17T07:00:00+08:00"

[source]
# 默认「引用」外部素材：记绝对路径，不复制（`[修-1]`，避免几十 MB 视频被无声拷贝）
# 若用 `init --embed`，素材被拷进 media/ 且路径变为相对 —— 跨机可迁移（ADR-08）
video = "D:/录像/我的录屏.mp4"
poster = ""

[captions]
file = "captions.srt"
language = "zh"

[templates]
active = "clean-bar-white"     # 来自模板库（§6.3）
# 允许项目级覆盖模板默认值
[templates.overrides]
font_size = 46
bottom_offset = 6

[content]
# D2 内容文档进画面的策略（ADR-07）
mode = "inline"                # inline | overlay | text
inline_max_kb = 800
inline_max_pages = 12

# `[修-10]` 页 → 时间的映射必须显式给出（走查 P-09：没有时间就没有标注）
# 二选一：手写 at/hold，或用 `import-doc --from-captions` 按序与字幕条配对
[[content.pages]]
file = "media/doc-p03.jpg"
at   = "00:00:40"              # 或 from_caption = "第3条"
hold = 6.0                     # 秒
slot = "right-bottom"          # 预设位（避免手算百分比）

[export]
quality = "good"
fps = 30
backend = "auto"               # 透传给 rlex
```

### 4.2 `style.toml` 示例

```toml
# 全部字段名对齐 Recordly 的 AutoCaptionSettings（04 §2.2）
# 但 fontFamily 需特别标注：录制渲染时会被 Recordly 重置（ADR-05）

[caption]
font_family = '"Source Han Sans CN", "Microsoft YaHei", sans-serif'
font_size = 46                   # 16..72
bottom_offset = 6                # 0..30 (%)
max_width = 70                   # 40..95 (%)
max_rows = 2                     # 1..4
animation = "pop"                # none | fade | rise | pop
box_radius = 12                  # 0..40
text_color = "#FFFFFF"
inactive_text_color = "#A3A3A3"
background_opacity = 0.0         # 0.0 = 纯白字无底框（06 §2 已验证）
```

> `font_family` **照常保存**，但 `apply` 时必须输出警告：
> 「该字段本次渲染无效（Recordly 会重置），实际使用系统 CJK 兜底字体」——
> 呼应需求 R-4，**不许静默**。

## 5. 命令面

> ⚠️ 本表已包含 `08-场景走查.md` 的修正（标注 `[修-n]` 的为走查后新增/变更）。

| 命令 | 用途 | 需要 Recordly |
|:---|:---|:---:|
| `rlc doctor` | 环境自检（Recordly 运行体 / ffmpeg / 字体 / 侧车） | ❌ |
| `rlc init --video <mp4> [--embed] [--from <项目>]` | 建项目；**默认引用外部素材**，`--embed` 才拷入 `media/` `[修-1]`；`--from` **白名单继承** `[修-12]` | ❌ |
| `rlc import-captions --srt <f>` | D1：字幕文稿 → `captions.srt`；**编码嗅探 + 剥离非主语言行** `[修-2/4]` | ❌ |
| `rlc import-captions --auto` | 调 `subgen` 转写（可选上游；长视频走分段 + 缓存 `[修-13]`） | ❌ |
| `rlc import-doc --pdf <f> [--mode] [--from-captions]` | D2：内容文档 → `media/` + `[[content.pages]]` 时间映射 `[修-10]` | ❌ |
| `rlc import-config --toml <f>` | D3：外部配置 → `style.toml` | ❌ |
| `rlc template list\|show <name>` | 模板库 | ❌ |
| `rlc template use <name> [--global]` | 选用模板（`--global` 写用户级默认 `I-01`） | ❌ |
| `rlc review [--fast\|--render] [--compare a b]` | 试穿；`--fast` **多帧覆盖亮/暗背景 + 对比度标记** `[修-5]` | ⚠️ `--render` 需要 |
| `rlc apply [--out] [--yes]` | 文本 → `.recordly`（默认 dry-run，幂等，**语义级 diff** `[修-6]`） | ❌ |
| `rlc pull [--yes]` | `.recordly` → 文本（差异报告 + **指纹硬校验** `[修-9]` + 解锁） | ❌ |
| `rlc open [--review]` | **准备 + 落锁 + 放进项目库 + 打印指引**（**不自动打开** `[修-7]`） | ✅ |
| `rlc export [--out <mp4>]` | 调 `rlex export run` + 回读报告 | ✅ |
| `rlc verify` | 项目自检（**自建项**，不依赖 `rlex validate` `[修-15]`） | ❌ |
| `rlc relocate --video <新路径>` | 重定位外部素材（ADR-08） | ❌ |
| `rlc status` | 锁状态 / 留痕 / **成片新鲜度** `[修-11]` / 待办 | ❌ |
| `rlc logs [--tail N]` | 诊断日志位置 | ❌ |

### 5.1 `verify` 的自建检查项 `[修-3/11/15]`

**不允许**把 `rlc verify` 做成 `rlex project validate` 的转发 —— 后者有两个已确认盲区
（放行 `zoomMotionBlurTuning`、误报 `webcam.corner`，见 `04` §9 与 `08` P-14）。
`rlc verify` 自建至少这些项，`rlex validate` 只作为**并列展示**的附加信息：

| # | 检查项 | 判据 | 对应 |
|:--:|:---|:---|:---|
| V1 | 素材存在性 | 所有引用的视频/图片/侧车路径可读 | ADR-08 |
| V2 | 侧车齐全性 | 录屏类素材的 `.cursor.json` / `.recordly-session.json` 在 `vendor/` | ADR-08 |
| V3 | **字幕时间码越界** | 末条 `endMs` ≤ 视频时长；越界列出条目号 | `[修-3]` P-03 |
| V4 | 字段可用性 | 用到的字段是否被 Recordly 强制重置（`fontFamily` 等） | R-4、ADR-05 |
| V5 | **成片新鲜度** | 输入指纹 vs 成片生成时间；陈旧报 `STALE` | `[修-11]` P-10 |
| V6 | 项目体积 | `.recordly` 大小 vs ADR-07 阈值（inline 图片保护） | ADR-07 |
| V7 | 字幕可读性 | 单行字数 / 停留时长 / 阅读速度（复用 `subtitle-optimize` 的判据） | S02 |

**退出码**（对齐 `rlex`）：`0` 成功 · `1` 参数/前置 · `2` 内部错误 · `3` 报告缺失 · `4` 报告说失败 · `5` 超时。
所有查询类命令支持 `--json`。

## 6. 关键设计

### 6.1 `apply` / `pull` 的字段映射

这是整个工具最容易腐坏的地方，必须**显式表格化**并随 Recordly 版本维护。

| 文本源 | `.recordly` 目标 | 方向 | 备注 |
|:---|:---|:---:|:---|
| `captions.srt` | `editor.autoCaptions[]` | → | 工具写 JSON（CLI 不支持数组，见 `04` §2.4） |
| `captions.srt` | `editor.autoCaptionSettings.enabled` | → | 设 `true` |
| `style.toml[caption].*` | `editor.autoCaptionSettings.*` | → | 字段名对齐（除 `font_family`→`fontFamily`） |
| `compose.toml[templates].active` | `editor.autoCaptionSettings.*` | → | 模板默认值 + `overrides` |
| `media/doc-*.jpg` | `editor.annotationRegions[].imageContent` | → | base64 inline（ADR-07） |
| `media/source.mp4` | `videoPath` | → | 相对 → 绝对 |
| `compose.toml[export].*` | 传给 `rlex` 的参数 | → | 不写进项目 |
| —— | `editor.autoCaptions[]` | ← | `pull`：导出 SRT |
| —— | `editor.autoCaptionSettings.*` | ← | `pull`：回写 `style.toml` |
| —— | `editor.zoomRegions[]` 等 | ← | `pull`：只报告，不自动写（超出本工具职责） |

**`apply` 的幂等保证**：`build/<name>.recordly` 每次**从零重建**，所以连跑两次结果一致（验收 A-6）。
工具先算出目标 JSON，与现有文件**比对**后才写；相同则报"0 处真实变更"。

**差异判定必须是语义级的** `[修-6]`（走查 P-06）：
人用自己的编辑器改一个字再保存，常会顺手改掉 **BOM / 换行符 / 序号 / 行尾空格**。
如果按字节 diff，会报一堆与内容无关的差异，让"只改该处"的验收（A-3）误判。
**做法**：把两侧都解析成 cue 列表再逐条比对；格式层面的变化单列为 `INFO`，不计入内容变更。

**「关字幕」的语义必须定死** `[修-14]`（走查 P-13，这是方案级缺口）：

> ⚠️ 背景：Recordly 的**现代导出路径不看 `enabled`，只看 `cues.length`**
> （`captionRenderer.ts:26` vs `modernFrameRenderer.ts:1617`，见 `04` §4.2）。
> 所以"把 `enabled` 翻成 `false`"在实机上**不会关掉字幕**。

| 动作 | 错误做法（会静默失效） | 正确做法 |
|:---|:---|:---|
| 关掉全部字幕 | `enabled = false` | **清空 `autoCaptions`**：把 `captions.srt` 移入 `captions.disabled.srt`，`apply` 写空数组 |
| `pull` 读到 `enabled=false` | 直接写回 `style.toml` | **翻译成**"把 cue 列表移出"，并提示"已按关闭处理（Recordly 的开关不起作用）" |

**`pull` 的指纹校验是硬要求** `[修-9]`：因为 P-07 修正后，"人绕过工具直接打开项目"
成了**主路径**，交接锁拦不住。此时 `pull` 的制品指纹比对是**唯一防线**，必须执行且必须报差异。

**`pull` 的差异报告**（验收 A-4）格式：

```
[!] pull: 检测到 3 处改动
  editor.autoCaptionSettings.fontSize:      34 -> 44      → 已写入 style.toml
  editor.autoCaptionSettings.bottomOffset:   4 -> 8       → 已写入 style.toml
  editor.autoCaptions[7].text:  "灰度AB测试" -> "灰度AV测试"  → 已写入 captions.srt
[!] 警告：editor.autoCaptionSettings.fontFamily 被 Recordly 重置为默认值
    （你设的 "SimSun" 无法生效，见 ADR-05）。style.toml 中的值已保留。
[i] 锁已释放。
```

### 6.2 交接锁协议（ADR-04 的落地）

状态存在 `.compose/state.json`：

```json
{
  "lock": {
    "holder": "human",
    "acquiredAt": "2026-09-17T07:12:00+08:00",
    "artifact": "build/红杉第一篇.recordly",
    "fingerprint": "sha256:...",
    "pid": 12345,
    "staleAfterHours": 12
  },
  "history": [
    { "at": "...", "surface": "S1", "field": "style.toml[font_size]", "from": 34, "to": 44 }
  ],
  "lastPullFingerprint": "sha256:..."
}
```

**规则**（与 ADR-04 R1–R6 一一对应）：

```
rlc open --review
  → 先 apply（确保制品最新）
  → 记录 fingerprint = sha256(build/<name>.recordly)
  → 落锁 holder=human
  → 把制品复制/链接进 Recordly 的项目目录，并置顶最近项目
  → 打印一句话指引（不做"自动打开"，见下）

rlc apply         # 锁被占时
  → [X] 拒绝：有人正在编辑（锁于 07:12 获得，制品 红杉第一篇.recordly）
        请先 `rlc pull` 回收改动，或用 `rlc status --force-unlock` 强制接管

rlc pull
  → 读 build/<name>.recordly
  → 比对 fingerprint：相同 → 提示"未检测到改动"
                       不同 → 抽差异 → 报差异 → 写文本 → 备份 → 释放锁
```

> ⚠️ **`rlc open` 不能自动打开项目** `[修-7]`（走查 P-07，方案级缺口）。
>
> 依据：Recordly **没有对外 CLI/API**；`RECORDLY_SMOKE_EXPORT*` 只触发导出并
> `window.close()`；`RECORDLY_DEV_OPEN_RECORDING_INPUT` 打开的是**视频**不是项目；
> `open-project-file-at-path` 仅应用内可达；全仓无 argv 解析（`04` §7）。
>
> **所以 `open` 的实际动作是"准备 + 指引"，不是"启动并布景"**：
> ① 确保制品在 Recordly 的**项目目录**里（这样人能在项目浏览器/最近项目里**一次点击**打开）；
> ② 落锁并记指纹；③ 在 `style.toml` 顶部写好"本次要调什么"；
> ④ 打印明确指引 —— 「在 Recordly 里打开 **<项目名>**，调完保存，回来跑 `rlc pull`」。
>
> **`--open-project` 启动参数已记入 `07-VOC与后续路线.md`。**

> **为什么落锁时必须记指纹**：否则无法区分"人改过"与"人没动"。
> 只比时间是不够的（人可能打开后什么都没做）。

### 6.3 模板库

模板 = **一个命名 TOML**，存在工具仓的 `assets/templates/`（内置）与用户的
`~/.config/recordly-compose/templates/`（自定义）：

```toml
# assets/templates/clean-bar-white.toml
[meta]
name = "clean-bar-white"
label = "极简底栏·纯白无底框"
desc = "小字号、贴底、白字无底框；适合信息密度高的口播"

[caption]
font_size = 43
bottom_offset = 5
max_width = 62
max_rows = 2
animation = "fade"
box_radius = 12
text_color = "#FFFFFF"
background_opacity = 0.0
```

**首批内置模板建议**（与 `P08` / `P09` 的结论对齐，避开 libass 做不到的）：

| # | 模板名 | 说明 |
|:--:|:---|:---|
| 1 | `clean-bar-white` | 极简底栏纯白无底框（`06`§2 实测已验证可渲染） |
| 2 | `punch-pop` | 大字弹出，短句冲击 |
| 3 | `slide-stack` | 要点上滑，多行堆叠 |
| 4 | `title-mask` | 大标题居中 |
| 5 | `karaoke-glow` | 逐字扫光（**依赖 `inactive_text_color`，当前为死设置**，见 `04` 与 `05`） |

**模板试穿**见 ADR-06：`--fast`（毫秒级近似）为默认，`--render`（真实片段）为可选。

**`review --fast` 必须多帧、且刻意覆盖亮/暗背景** `[修-5]`（走查 P-05）：

> ⚠️ `P09` 的场景还原里记录过一次真实误判：
> 「**误判 4 个模板白色文字不可读** —— 原因是抽帧的窄裁剪切到了浅色墙面；
> 全幅复查后发现深色背景上完全正常。」
>
> 如果 `--fast` 只抽一帧，**这个误判会被自动化重演**，而且人会信它。

因此 `--fast` 至少要做三件事：

1. 抽 **2–3 帧**，用**亮度直方图**挑选（刻意覆盖最亮与最暗的场景），**不做均匀采样**
2. 每个候选模板在**每一帧**上都画一遍（而非只在第一帧）
3. 对每个"模板 × 帧"格子算**字幕区与背景的对比度**，低于阈值**直接打标**
   （把 `P09` 那次人工教训变成工具能力，而不是继续依赖肉眼）

### 6.4 内容文档进画面（ADR-07 的落地）

```
PDF ──pypdfium2──> 逐页 PNG ──Pillow──> 缩到目标宽 + JPEG q80
                                        │
                          ┌─────────────┴─────────────┐
                     ≤阈值且页数≤上限            超阈值
                          │                           │
                    inline 模式                  overlay 模式
                base64 → imageContent         存 media/ → 出片后 ffmpeg 叠加
```

**inline 模式的定位**：`position` / `size` 是**画面百分比**，`position` clamp `0..100`，
`size` clamp `1..200`（`04` §6.1）。工具提供 `--slot` 预设（右下 / 左下 / 全屏留边）
避免让用户算百分比。

**时间维度的映射必须显式给出** `[修-10]`（走查 P-09）：

> ⚠️ `AnnotationRegion` 是**带 `startMs`/`endMs` 的时间区间** —— **没有时间就没有标注**。
> 而"第 3 页该在第 40 秒出现"是**内容决策**，AI 猜不准。原方案完全没定义这一层。

两种给法（二者都落到 `compose.toml` 的 `[[content.pages]]`）：

| 方式 | 命令 | 适用 |
|:---|:---|:---|
| 人给表 | 手写 `[[content.pages]]` 的 `at` / `hold` | 正式报告、节奏明确 |
| 按序配对 | `import-doc --from-captions` | 口播类"边讲边翻页"——按字幕条顺序逐页配对 |

`verify` 需检查：页图数量与映射条数一致、区间不与彼此重叠、区间不越出视频时长。

## 7. 性能预算

### 7.1 实测基线（详见 `06`）

| 项 | 实测值 | 出处 |
|:---|:---|:---|
| 导出倍速（复杂项目） | **1.59×** 实时 | 报告 A：17.18s 片 → 27.34s |
| 导出倍速（最简项目） | **0.70×** 实时 | 报告 B：4.00s 片 → 2.79s |
| 字幕布局成本（314s 片，中文口径） | **≈10.1s**，占导出总量 **2.0%–4.6%** | 本次基准 |
| 应用启动固定开销 | **6.0–8.4s**（`ready-to-show`） | 应用日志 |
| 导出内固定开销 | **≈2.0s**（`metadataLoad` 1143ms + `rendererInit` 808ms） | 报告实测 |

### 7.2 本工具各步的预算

| 步骤 | 目标 | 依据 |
|:---|:---|:---|
| `init` / `apply` / `pull` / `verify` / `status` | **< 5s**（验收 P-1） | 纯文本 + 本地文件 IO |
| `import-captions --srt` | **< 5s** | 编码嗅探 + 解析；**不含 ASR** |
| `import-doc --pdf` | **≈页数 × 0.2–1s** | 页图光栅化 + 缩页 + JPEG |
| `review --fast` | **< 3s** | 抽帧 + PIL 绘制 + 拼图 |
| `review --render` | **≈10–15s × 模板数** | 启动 6–8s + init 2s + 短片段渲染 |
| `export` | **不劣于 `rlex` 基线**（验收 P-2） | 直接调 `rlex` |
| **`import-captions --auto`（ASR）** | **见 §7.4 —— 单独计，且是长视频的真正瓶颈** | `P02` 实测 RTF 3.363 |

### 7.3 三个必须提前告知的成本

1. **试穿 `--render` 很贵**：5 个模板 ≈ **1 分钟纯开销**（一次启动只能导一次，`04` §3.2）。
   所以默认走 `--fast`（ADR-06）。
2. **长视频的字幕布局成本是 O(条数 × 帧数) = O(时长²)**（`04` §5.1）。
   【外推】按中文口径：5 分钟 ≈10s、10 分钟 ≈37s、30 分钟 ≈5.5 分钟。
   **工具侧无法修**（在 Recordly 里），只能：① 在 `verify` 里对该成本**给预警**；
   ② 建议上游加时间窗口裁剪。→ 记入 `05-待确认清单` 与 `07-VOC`。
3. **长视频的 ASR 成本比渲染还大** —— 见 §7.4。

### 7.4 ⚠ 转写才是长视频的真正瓶颈 `[修-13]`

原方案的 §7 只算了渲染与布局，**漏了 `import-captions --auto`**。而 `P02` 的实测是：

```
转写：163 条，elapsedSec=0.56（命中缓存），首次预计 17 分 36 秒（RTF 3.363）
```

按 **RTF 3.363** 外推（无缓存）：

| 片长 | ASR 耗时 | 对比：渲染（按 1.59×） | 对比：字幕布局 |
|:---|:---:|:---:|:---:|
| 5 分钟 | ≈ 17 分钟 | ≈ 8 分钟 | ≈ 10 s |
| 30 分钟 | **≈ 101 分钟** | ≈ 48 分钟 | ≈ 5.5 分钟 |
| 60 分钟 | ≈ 202 分钟 | ≈ 95 分钟 | ≈ 22 分钟 |

> **⇒ 30 分钟录课的转写（约 100 分钟）比渲染（约 48 分钟）还长一倍。**
> "AI 全自动跑完"在长视频上的真实瓶颈是 **ASR，不是导出**。
> 原方案若按渲染预算承诺，会严重失真。

**对策（三条，都必须在第一期就做）**：

| # | 对策 |
|:--:|:---|
| 1 | 长视频强制**分段转写 + 缓存复用**（`subgen` 已有缓存，实测命中时 0.56s） |
| 2 | 允许 **`--srt <已有稿>` 完全跳过 ASR** —— 有稿就不要重转 |
| 3 | `doctor` / `status` 对 ASR 时长**给预估**，让人在开跑前就知道要等多久 |

```
subtitle-generate ─┐
                   ├─→ captions.srt ─┐
subtitle-optimize ─┘                 │
                                     ▼
recordly-zoom ──→ 镜头计划 ──→ ┌──────────────────┐      ┌──────────────┐
（录屏类素材）                  │  rlc             │─────→│ rlex         │──→ mp4
                              │  recordly-compose │      │ export run   │
文档（PDF/DOCX/MD）──────────→ │  编排 + 模板 + 协同 │←─────│ + report.json│
                              └──────────────────┘      └──────────────┘
                                       │
                                       ▼
                                rld（成片体检）
```

**三条不变量**：

1. `rlc` **不实现渲染**，一律调 `rlex`
2. `rlc` **不碰 Recordly 源码**
3. `rlc` **不替代 `subtitle-burn`** —— 任意 MP4 + 精细 ASS 模板仍走 `subtitle-burn`
