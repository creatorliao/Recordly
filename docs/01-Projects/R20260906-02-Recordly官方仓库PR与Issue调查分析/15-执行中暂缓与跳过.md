## 一、什么叫「过不去」且「决策过得去」

**过不去（写入本文，不合）：**

- 四闸任一门不过（范围 / 落不进 G / 六问不过 / 体量禁忌）
- 象限是「高价值高风险」或「不碰」，且本轮没有「拆小后再合」的现成 diff
- cherry-pick / 一次 rebase 仍冲突
- 合上后 `npm test` / lint / typecheck 红，按 D3 revert
- diff 与当前树对不上（上游已修或 PR 过期）
- 平衡矩阵筛完不进极高分，也不在本轮队列里硬插

**决策过得去（因此不必问你）：**  
上面这些，方案里已经规定动作 = **暂缓并跳下一条**。没有「既不能合又不能跳、必须等人」的空档。  
只有 D11（连续两条金路径都 revert）才暂停整轨，仍先写本文再停。

**不要写进本文的：** 需要你事后勾的代决策（去 `14` §二）；合成功但要人眼看的（去 `14` §三）。

## 二、每条必须写全（否则你回来看不懂）

追加时用下面这块，**不准只写「#xxx 失败」**。

```
### S-__  ·  #<号>  <标题一句话>
- 时间：
- 队列位置：上一条做成了 #… / 下一条将做 #…
- 动作：暂缓 | 跳过（本轮不再重试）
- 过不去的点：（闸门 / 六问 / 冲突 / 测试红 / 对不上树 / 其他）
- 综合考量：R/C/E/S 或「未打分（闸门已杀）」；象限；为什么不能硬合
- 试过什么：cherry-pick / rebase 一次 / 测试命令与结果
- 仓库状态：已 revert / 从未合上 / 工作树干净
- 你回来可以怎么处理：下轮再取 / 改手工 / 认定不做
```
