# 02 · PR 分级建议（对齐你的目标）

> ⚠️ 过程稿。P0 仍混有 macOS/Linux。**执行以 [`12-综合完善方案.md`](12-综合完善方案.md) 为准。**

> 分级前提，把你的目标再钉一遍：
> - **角色**：培训师，录制软件操作过程
> - **核心路径**：启动录制 → 停止 → 编辑 → 导出视频
> - **三大诉求**：① 减轻剪辑工作量 ② 字幕/配音 ③ **功能完善、体验良好，但不过度设计**
>
> 结论一句话：**优先保「录得稳、点得动、听得清、剪得省、导出顺」这五件事，其余的一律往后放；巨型 Slop PR 坚决不碰。**

---

## 分级标准

| 级别 | 含义 | 判据 |
|------|------|------|
| **P0 必合** | 核心路径不出事，培训师刚需 | 影响「能不能录、点不点得到、有没有声音、导出成不成」+ 零/低风险 |
| **P1 应合** | 让培训效率明显提升 | 贴合「减轻剪辑工作量 / 字幕配音」，中等改动，价值高 |
| **P2 可选** | 锦上添花 | 有用但冷门，或非你平台/场景必需 |
| **P3 不建** | 过度设计 / 高风险 / 重复 | 违背「不过度设计」，或改动巨大、带 Slop、与现有 PR 重复 |

## 四、给你的最终建议（一句话版）

1. **先合 P0 里「点得动 + 有声音 + 保存得了」这几个**（#875、#803、#785、#825、#777、#796、#712、#823、#874/#865）——这些合完，你「录软件操作 → 导出视频」的完整路径就基本稳了。
2. **再合 P1 里「教学向 + 省剪辑」的**（#733 按键叠加、#774 区域录制、#732 裁剪、#719 高亮）。
3. **P3 巨型 Slop PR 一律不碰**——这正是「不过度设计」的底线，宁可功能少而稳，不要大而危。
