# 07 · 验证与回退计划

> 四层验证思路仍可用。回退写成 `push origin main`、批次含 macOS 的部分 **作废**。以 [`12` §七](12-综合完善方案.md) 为准。

> 原则：**边合边验，小步快跑，错了能退。**
> 合并粒度 = 验证粒度 = 回退粒度。每合一个 PR，就验一次、留一个可回退点，绝不一锅端。

---

## 一、验证计划（四层，逐层递进）

### 第 1 层：自动化验证（合并前）

```bash
# 每个 PR 合并前，本地跑全量测试 + 类型检查 + lint
npm test          # 关注改动相关模块的测试
npm run typecheck # 如有
npm run lint      # 如有

# 看 PR 自带 CI 状态
gh pr checks <PR号> --repo webadderallorg/Recordly
```

- ✅ 全绿才进下一层；`UNSTABLE` 先查失败项，是无关 lint 波动就 rebase 重跑，是真失败就**不合并**。

### 第 2 层：单 PR 专项验证（合并前，人手点一遍）

每个 PR 按其「服务的目标」做对应专项验证：

| 批次 | PR | 专项验证动作 |
|------|----|-------------|
| 一批 | #823 | 语言列表「简体中文」四个字显示正确 |
| 二批 | #803 | 录制中点击被录软件**底部按钮**，能点到 |
| 三批 | #875 | macOS 选窗口录制后，目标软件焦点不丢、可操作 |
| 三批 | #785/#825 | 录 3 分钟带讲解，全程麦克风有声、不断 |
| 四批 | #796 | Windows/Linux：保存项目 → 关闭 → 打开项目，状态恢复 |
| 四批 | #855 | 用变帧率源编辑，播放头不冻结 |
| 五批 | #712 | 带讲解片段一键生成字幕，字幕出现且可编辑 |
| 五批 | #777 | 降噪开关切换生效 |
| 六批 | #733 | 开启「显示按键」录一段，画面上出现按键，默认关闭不录隐私 |

### 第 3 层：整链路冒烟（每批合并后，统一跑一遍）

批合并完成后，走一遍完整路径，任一失败即进入回退：

1. ✅ 启动 → 选窗口 → 开始录制（倒计时正常）
2. ✅ 录制中点击被录软件，交互正常
3. ✅ 停止 → 自动进编辑器
4. ✅ 修剪（T）→ 应用自动缩放 → 生成字幕
5. ✅ 保存项目 → 重新打开
6. ✅ 导出 MP4 → 文件能播放、有声音

### 第 4 层：灰度验证（可选，发版前）

- 切一个 **beta 版**，让少量真实用户（含中文培训师）用一周，收集回归反馈。
- 指标：录课冒烟耗时 ≤ 15 分钟、无新增「点不动/没声音/导不出」类 issue。

## 二、回退计划（三级，越往上级越重）

### 级别 1：单 PR 回退（最常用）

```bash
# squash 合并后，回退单个 PR 就是 revert 那一个 commit
git log --oneline -5          # 找到该 PR 的 merge commit（含 PR 号）
git revert <commit-sha>       # 生成一个反向 commit
git push origin main
```

- 适用：某 PR 引入回归，其余正常。

### 级别 2：整批回退（连续多个 PR 都有问题）

```bash
# 定位该批「第一个」PR 的 commit，用 range revert 整段
git log --oneline --first-parent -20   # 找批次起点
git revert --no-commit <起>..<止>      # 或逐个 revert 后一起 commit
git commit -m "revert: roll back batch 3 (#785 #825)"
git push origin main
```

- 适用：同一批多个 PR 相互影响，需整体退回上一稳定点。

### 级别 3：版本回退（已发布后出事）

```bash
# 回退到上一个 release tag，重新出包
git tag                       # 看历史 tag
git checkout <上一个稳定tag>
# 基于它重新构建、重新发版，并公告用户降级
```

- 适用：已发版、影响面大，先退回旧版止损。

### 回退演练（合并前先练一遍）

在开始合并 P0 之前，先在本地练一次 `git revert`，确认能干净回退，避免真出事时手忙脚乱。

## 三、提交计划（提交策略与规范）

### 3.1 合并方式：一律 squash

```bash
gh pr merge <PR号> --squash --repo webadderallorg/Recordly
```

- 每个 PR 压成**一个干净 commit**，便于定位和回退（对应「级别 1 回退」）。

### 3.2 提交信息规范（含目标标注）

格式：`<type>(<scope>): <摘要> [目标] (#PR号)`

| 示例 | 说明 |
|------|------|
| `fix(hud): pass clicks through recording overlay [G1] (#803)` | 标出服务 G1 |
| `feat(captions): improve auto-caption runtime [G3] (#712)` | 标出服务 G3 |
| `docs: drop discontinued marketplace [G4] (#865)` | 标出服务 G4 |

- 好处：以后 `git log` 一眼看出每个改动服务于哪个目标，回退时也好定位。

### 3.3 分批提交节奏（对应 05 合并方案）

| 批 | 内容 | 提交节点 |
|----|------|---------|
| 一批 | 中文 + 文档 | 每 PR 一 commit，合完即验 |
| 二批 | HUD 点击穿透 | 只合 #803（主方案），重叠 PR 关闭 |
| 三批 | 焦点 + 麦克风 | #875 → 验 → #785 → 验 → #825 → 验 |
| 四批 | 保存 + 编辑稳定 | #796 → 验 → #855 → 验 |
| 五批 | 字幕 + 降噪 | #712 → 验 → #777 → 验 |
| 六批 | 教学提效 | 逐个合、逐个验（#733 重点审查 Slop） |

> **节奏铁律**：每批内部「合一个 → 验一个 → 再合下一个」，严禁一次堆多个不验证。

### 3.4 里程碑打 tag（验证通过后）

```bash
# 每完成一个里程碑（P0 全合、P1 全合）打 tag，作为可回退锚点
git tag -a v1.4.0-p0 -m "P0 reliability: focus/hud/mic/save/captions"
git push origin v1.4.0-p0
```

## 四、验证-回退联动总表

| 阶段 | 验证动作 | 失败时回退到 |
|------|---------|-------------|
| 合并前 | 自动化测试 + CI 全绿 | 不合并（rebase 重试） |
| 合并后 | 单 PR 专项验证 | 级别 1：revert 该 PR |
| 每批后 | 整链路冒烟 | 级别 2：revert 整批 |
| 发版后 | 灰度用户反馈 | 级别 3：切回上一 tag |

---

## 五、执行清单（合并 P0 时的操作顺序）

```
□ 1. 本地练一次 git revert（确保能退）
□ 2. 拉最新 main，打好基线 tag
□ 3. 一批：#823 → npm test → 冒烟 → tag
□ 4. 二批：#803 → 专项验证 → 冒烟 → tag，关 #797/#845/#730
□ 5. 三批：#875 → #785 → #825，每个都专项验证 + 冒烟
□ 6. 四批：#796 → #855，验证项目保存 + 编辑不冻结
□ 7. 五批：#712 → #777，验证字幕 + 降噪
□ 8. 六批：P1 逐个合、逐个验
□ 9. 全程：出错就 revert，回到最近一个稳定 tag
```
