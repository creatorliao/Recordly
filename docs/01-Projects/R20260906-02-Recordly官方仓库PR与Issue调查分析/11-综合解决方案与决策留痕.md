## 四、冲突分级与共存设计（站在用户角度）

> 原则：所有功能增强必须**不改变核心工作流程、不破坏原有体验**。冲突分两级。

### 4.1 真互斥（无法共存，需二选一）

- **#794 CUDA 导出 vs 现有 Lightning/CPU 导出**：除非做双引擎（工程量巨大），否则二选一。当前选「不合并」。

### 4.2 可共存（通过设计并存，默认保原体验）——典型：追加录制 vs 独立文件

**表面冲突**：追加录制 = 一个文件接着录；独立文件 = 每次一个新文件。

**实际可共存**：

| 设计 | 行为 |
|------|------|
| **默认** | 每次录制仍是**独立文件**（老用户无感知，原有体验不变） |
| **可选** | 录制完成后，编辑器/启动页新增「**继续录制（追加到本文件）**」入口 |
| 触发 | 用户**显式选择**才追加；不选就是原来的独立文件 |

**价值**：培训师分段录课时可「接着录」，避免碎片文件；录错了可原地继续，不必重开新文件。

**执行分工**：属功能增强 + 改动较大（#689 +344 行），**暂缓**；将来按「默认独立文件 + 可选追加」设计重做（不采用原 PR 的「替换」式改法）。
