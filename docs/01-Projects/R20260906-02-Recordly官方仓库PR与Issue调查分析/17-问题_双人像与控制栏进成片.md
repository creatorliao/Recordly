> **结案（2026-09-06）**：不是缺功能，是不会用。控制条不成片、录时看摄像头、成片不贴头像，现有选项已够。**不改产品。** 用法见 `R20260906-01/02` §三；开关对账见 [`18`](18-调查_控制条不进成片与摄像头仅预览.md)。本节问题关闭。

**结论先说：**

| 你看见的 | 算不算问题 |
|----------|------------|
| **录的时候**显示器上有一条「录制中」控制条 + **一个**悬浮头像 | **正常**。给你自己看、给自己点停，不是成片。 |
| **编辑器预览 / 导出成片**里还有控制条，或 **两个人像叠在一起** | **是问题**（或设置关反了）。成片里最多只该有 **一份**摄像头叠加。 |

前面那些 PR **没有修「进不进成片」**，修的是另一件事，见 §三。  
开关是否已经够用：见 [`18-调查_控制条不进成片与摄像头仅预览.md`](18-调查_控制条不进成片与摄像头仅预览.md)。

## 1. 现状（对照你的两张图）

**图 A（编辑器里两个人像叠着）**  
同一人、两扇圆角小窗错开叠在画面上。典型结构是：

1. **烧进录像的那一层**：录屏时屏幕上的「悬浮摄像头预览」被一起录进去了；  
2. **编辑器再叠一层**：摄像头是单独旁路文件，Studio 右侧「摄像头」默认再贴一份。

两层都开着，就是「两个人」。

**图 B（录制中控制条）**  
「录制中 00:23」、暂停、停止、减号、叉。  
**录的时候你自己屏幕上必须能看见**，否则没法停。  
它该不该出现在**成片**里，是另一条开关，见 §四。

右侧黄条、编辑器按钮，若只出现在 Studio 窗口里、导出没有，那是编辑器壳，不是录像。

## 2. 产品本来怎么设计的（三套东西，别混）

录制时其实有 **三个窗口/轨道**，职责不同：

```
① 被录的软件/整屏     → 进主视频
② HUD 悬浮窗（控制条 + 可选头像预览）→ 只给你看；默认可从采集里排除
③ 摄像头旁路文件      → 停录后编辑器再贴到成片上（一份）
```

悬浮头像和成片头像是 **同一路摄像头的两个用途**：前者是取景器，后者才是成片。  
取景器如果没从采集里排除，就会和成片头像叠成两个。

---

## 3. 为什么 #803 / #542 / #730「修过了」还会这样

那些 PR / 树上的等效实现，修的是 **鼠标点击穿透**：

- 点 HUD **透明区域** → 点到后面被录的软件（#803 簇，`setIgnoreMouseEvents(..., { forward: true })`）  
- 拖完 HUD 穿透还在（#542）  
- 拖到顶条还在（#730）

见 `15` S-01～S-04、`14` T6：**「点得动后面、HUD 按钮还能点」**。

它们 **不负责**：

- 控制条不进录像  
- 悬浮头像不进录像  
- 编辑器里不要两个人像  

「穿透」在仓库里 = **鼠标穿过去**，不是 **画面隐身**。  
画面隐身走的是另一条：`BrowserWindow.setContentProtection(true)`（Windows 上接近 `WDA_EXCLUDEFROMCAPTURE`），开关文案是 **「从录制中隐藏 HUD」**。

所以：前面那些关注过了、树上也有了，**这张双人像图仍然可以出现**——不是那些 PR 没合上，是 **另一类问题**。

## 4. 正确设置（先对这个，再判断要不要改代码）

默认代码里 `hudOverlayHiddenFromCapture = true`（从录像里藏 HUD）。  
但会写成 `%APPDATA%\Electron\hud-overlay-settings.json` 的 `hiddenFromCapture`。你若点过一次「在录制中显示 HUD」，下次会记住。

### 4.1 不要让控制条 / 取景器进成片

启动窗 **三点菜单**：

| 项 | 应处于 |
|----|--------|
| **从录制中隐藏 HUD**（眼睛上有斜杠、高亮） | **开着** |
| 若变成「在录制中显示 HUD」 | 关了保护，控制条和悬浮头像都会进主视频 |

Windows 支持这个 API（`supportsHudCaptureProtection("win32") === true`）。

### 4.2 录的时候只要「自己看见一份」头像

摄像头按钮弹出层：

| 项 | 作用 |
|----|------|
| **隐藏悬浮预览** | 取景器从你屏幕上拿掉（仍可录旁路，编辑器里还能贴） |
| **显示悬浮预览** | 默认开。只应出现在你的显示器上，不应进主视频（前提是 4.1 开着） |

### 4.3 编辑器里只要「成片一份」头像

右侧 **摄像头**：

| 情况 | 怎么做 |
|------|--------|
| 主视频里 **已经有**烧进去的头像 | **关掉**摄像头叠加，否则一定是两个 |
| 主视频是干净桌面，头像只在旁路 | **开着**叠加（这是正路，只有一个） |

关掉叠加 **去不掉**已经烧进主视频的那一层，只能重录。

### 4.4 别和「减号隐藏」搞混

控制条上的 **「−」** = `hideHud`：条从你眼睛里收起来，方便操作。  
**不是**「从录像里排除」。排除只认三点菜单那一项。

使用指南 `R20260906-01/02` §五把「隐藏 HUD」写成「不进成片」，和代码不一致，容易误导。

## 5. 根因（按你怎么验，对号入座）

```
录全屏/屏幕
    ├─ 保护开着且 WGC 认 setContentProtection
    │      → 主视频无条、无取景器；编辑器再贴旁路 → 一个人像  ✓
    ├─ 保护被关掉（设置或 json）
    │      → 主视频有条 + 取景器；编辑器再贴 → 两条 + 两个人像  ✗ 设置
    └─ 保护开着但采集仍录到 HUD（WGC/亲和性未生效）
           → 同上 ✗ 产品缺口（要另修采集，不是再合 #803）
```

本仓 Windows 主采集是 **wgc-capture**，源码里 **没有**再写一遍排除逻辑，完全指望 Electron 给 HUD 窗 `setContentProtection`。  
多数机器有效；个别环境 WGC 仍会把带亲和性的窗录进去——那才要动 helper，**不能**靠再 cherry-pick 点击穿透 PR。
