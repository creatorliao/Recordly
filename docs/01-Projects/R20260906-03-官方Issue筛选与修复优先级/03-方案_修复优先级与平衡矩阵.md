### 1.6.1 问题记录：将来发布是否只出 portable、不再发安装包？

**谁提的 / 何时：** 你，2026-09-06。  
**原话要点：** 每次安装包都会被内部软件拦截；将来发布会不会 **只做 portable、不要安装包** 更好？

**为什么这是真问题（G1 装得上）：**  
身份已改成 Electron（`a2e32fa1`），拦的若不只是厂商名，而是 **「向 Program Files 写、要提权、像安装器」** 这一类行为，那 NSIS 再改名字也会拦。培训师课都开不了。这比「多一个 zip 好玩」更重。

**三种产物，别混：**

| 产物 | 是什么 | 和拦截的关系 |
|------|--------|----------------|
| NSIS 安装包（现状 `build:win`） | 向导、写目录、快捷方式，常要管理员 | **你已踩过**：每次都被内部软件拦 |
| electron-builder `portable` 单文件 | 一个自解压 exe，先解到临时目录再跑 | **仍很像安装器**，EDR 常按同一套启发式拦，**不能默认押在这上面** |
| **解压即跑的目录 / ZIP**（`dir` 再打包） | 文件夹里有 `electron.exe` + 资源，无向导、不写 Program Files | **最不像安装**；仍可能拦「未知 exe」，但比 NSIS 对症 |

**综合考量（六问 + 利弊）：**

| 问 | 判断 |
|----|------|
| 服务哪个 G | G1 装得上。拦安装 = 金路径第一步就断 |
| 不过度设计 | 改的是**分发形态**，不是新功能。ZIP 比自研启动器小 |
| 回归 | 无开始菜单、无自动更新、路径含空格/中文要小心；`userData` 第一步仍可在 AppData |
| 用户真需要吗 | 你已说安装包**每次**被拦，不是偶发 |
| 会困惑吗 | 手册要从「双击安装」改成「解压 → 打开 exe」。同事会问「怎么没安装包」——写一句「内网请用 ZIP」 |
| 奇怪影响 | 杀软仍可能拦 exe；USB 盘权限；便携目录被只读策略锁住 |

| 只发 ZIP | 只发 NSIS | 两份都打、主发 ZIP |
|----------|-----------|---------------------|
| 对内最可能跑起来 | 对内你已判定经常挂 | 构建多一次，分发只给 ZIP |
| 别人机器若允许安装，少了快捷方式 | 别人机器也许能装 | 能力不丢，主路径对内 |

**代决（写入 `14` D17，你可改判）：**

1. **对内 / 将来你自己发布：默认只发「解压即跑 ZIP」**，不把 NSIS 当主产物。理由：安装包已被你定性为每次拦截。  
2. **流水线仍保留打 NSIS 的能力**（`win.target` 可同时留着），不删、不当日常分发。哪天监控松了或外网要用安装包，还能打。  
3. **不要把 electron-builder 单文件 `portable` 当成「发布默认」**，除非 T12 真机证明它比 ZIP 更不被拦。  
4. 身份继续 Electron。手册（做 portable 时）写清：内网用 ZIP，不要双击 installer。  
5. **现在不改产品代码、不改 `electron-builder.json5`。** 等确认 + 轨道 B 再做产物。T3（拦不拦安装包）和 **T12（ZIP 里的 exe 拦不拦）** 对比后，才能把「彻底停发安装包」从代决升级成死规定。

**和上一版「NSIS + portable 共存」的关系：**  
构建上仍可共存；**发布策略**改成「主发 ZIP、安装包降为备胎」。后说的覆盖先说的（R18b）。
