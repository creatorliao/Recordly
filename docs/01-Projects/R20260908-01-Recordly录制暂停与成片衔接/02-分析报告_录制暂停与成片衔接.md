# 02 · 分析报告：录制暂停与成片衔接

## 结论（先看这一段）

**同一次录制里暂停再继续，出来的是一段视频、一个工程主片，不是两段文件、也不是时间轴上的两个 clip。**

中间不是「先写 A 再写 B 再拼接」，而是**同一条编码会话不停、暂停期间不写帧，继续后把时间戳往前挪，接在暂停前最后一帧后面**。墙钟上停了多久，成片里就少多久；暂停期间的画面和声音不会进文件。

停录再开下一次录制，才会得到另一份 `recording-*.mp4`——那是另一条产品问题（见 `R20260907-04`），和本夹的暂停无关。

---

## 1. 用户看到的入口

控制条在 `LaunchWindow` 进入 `recording === true` 后，把暂停/继续绑到同一颗按钮：

- 组件：`src/components/launch/RecordingControls.tsx`
- 未暂停：暂停图标，调用 `pauseRecording`
- 已暂停：播放图标，调用 `resumeRecording`
- 计时：`useRecordingTimer` 在暂停时停秒表，继续后从累计暂停时长里扣掉墙钟，HUD 上的 `00:12` **不含**暂停时间

停止仍是左边红色录制钮（`toggleRecording` → `stopRecording`），和暂停是两回事。取消会丢掉当前会话，也不会拆成两段。

---

## 2. Windows 主路径：原生捕获（一段 MP4）

现阶段 Windows 走原生 helper（`windows-capture` / `wgc-capture`），不是浏览器 `MediaRecorder`。

### 2.1 开始时只订一个输出路径

`electron/ipc/register/recording.ts` 在启动时生成**一个** `recording-{timestamp}.mp4`，整段会话写进这个文件。暂停、继续**不会**换路径、不会再开一个 helper、不会再开一个编码器。

### 2.2 暂停：停写，不停会话

主进程 IPC `pause-native-screen-recording` 向 helper 的 stdin 写一行 `pause`；`resume-native-screen-recording` 写 `resume`。进程还在，编码器还在，输出文件还是原来那个。

`electron/native/windows-capture/src/main.cpp`（WGC 同思路）：

| 时刻 | 画面 | 系统声 / 麦（WASAPI） |
|------|------|------------------------|
| 收到 `pause` | 帧回调直接 `return`，**不** `writeFrame` | `audioClient_->Stop()`，采集线程空转，**不**往 WAV 追加 |
| 暂停期间 | 桌面还在变，文件里没有这些帧 | 没有这些采样 |
| 收到 `resume` | 下一帧继续写；把「暂停墙钟」累加到 `g_accumulatedPausedHns` | `audioClient_->Start()`，继续往**同一个** WAV 写 |
| 写帧时间戳 | `adjustedTimestamp = 墙钟时间戳 − 累计暂停` | 音频是连续 PCM，长度≈有效录制时长 |

因此接缝处是：

```text
… 暂停前最后一帧 (T)  →  继续后第一帧 (T+Δ编码间隔)
```

`Δ` 是正常帧间隔量级（按设定 fps），**不是**用户暂停了 3 分钟就空 3 分钟。没有黑场、没有静音垫、没有「第二段文件」。

停止时 `encoder.finalize()` 一次收口，得到**一个** MP4。音频 sidecar 仍是各一个 WAV，再由 `muxNativeWindowsVideoWithAudio` 挂到同一会话（当前实现偏「sidecar 就位」，不是再 concat 两段视频）。

### 2.3 渲染进程只做同步，不拆文件

`useScreenRecorder.pauseRecording` / `resumeRecording`（原生分支）：

1. 等原生 pause/resume 成功  
2. 同步暂停/继续摄像头 `MediaRecorder`、麦兜底 recorder  
3. `markRecordingPaused` / `markRecordingResumed`：只累加暂停毫秒，给停止时的 `expectedDurationMs`  
4. `pauseCursorCapture` / `resumeCursorCapture`：光标采样时间减去累计暂停，与成片时钟对齐  

停止后 `finalizeRecordingSession(finalPath, …)` 只把**这一条** `videoPath` 交给编辑器。

---

## 3. 对照路径：浏览器 MediaRecorder（同样一段）

非原生时走 `MediaRecorder.pause()` / `resume()`。浏览器语义是：**同一个 recorder、同一组 `chunks`，pause 不触发 `onstop`**。停止时把 chunks 合成**一个** Blob，再 `storeRecordedVideo` 成一个文件。摄像头、麦兜底也是 pause/resume，不是 stop 再 new 一个 recorder。

这条路径在 Windows 主产品上通常不是默认，但机制与「一段成片」一致。

---

## 4. 进编辑器之后：一个主片，不是两个 clip

`setCurrentVideoPath` / `setCurrentRecordingSession` 只带一个 `videoPath`（外加可选 `webcamPath`）。编辑器按**当前工程一条主视频**打开。

暂停/继续**不会**在时间轴上生成「片段 1 + 片段 2」。用户若在时间轴上看到两段，那是后来手动分割，或另一次录制进了别的工程/素材方案，不是本次暂停写出来的。

---

## 5. 各轨道怎么「连在一起」

| 通道 | 暂停时 | 继续后如何对齐 |
|------|--------|----------------|
| 屏幕视频 | 不写帧，时间戳扣掉累计暂停 | 同一编码器连续时间轴 |
| 系统声 / 原生麦 | WASAPI Stop，不写采样 | 同一 WAV 继续追加，时长跟有效画面走 |
| 浏览器麦兜底 | `MediaRecorder.pause` | 同一段音频；内部记了 pause interval，用于时长诊断 |
| 摄像头 | `webcamRecorder.pause` | 同一段摄像头文件，不是第二路独立成片 |
| 光标遥测 | `pauseCursorCapture*`，暂停后采样不计入有效时间 | `timeMs` 用「墙钟 − 累计暂停」，和画面同尺 |
| HUD 秒表 | 停走 | 显示有效录制秒数 |

没有「先出两段再 ffmpeg concat」的现行主路径。仓库里 `electron/ipc/ffmpeg/filters.ts` 的 `normalizePauseSegments` / `buildPausedAudioFilter` 是**按墙钟切掉暂停段再拼音频**的旧/备用滤镜；当前**没有任何调用方**。现行设计是捕获期就扣掉暂停，而不是成片后再切。

---

## 6. 和「两段视频」容易混的边界

| 用户动作 | 结果 |
|----------|------|
| 一次开始 → 暂停 → 继续 → 停止 | **一段** MP4，**一个**工程主片 |
| 多次暂停/继续 | 仍是同一文件；每次暂停都从时间轴上抠掉 |
| 暂停中直接停止 | 仍是一段；停止时会把未闭合的暂停算进「已扣时长」 |
| 停止后再点开始录制 | **另一份** `recording-*.mp4`，另一会话；默认各开各的工程 |
| 取消录制 | 丢掉当前会话，不成片 |

培训师体感：暂停像「录像机暂停」，磁带还是那一盘；不是「先存一盘再开一盘」。

---

## 7. 风险与待真机看的点（不阻塞本结论）

源码已经能定性「一段、时间戳衔接」。下列只影响接缝观感，不改变「是一段还是两段」：

1. **接缝一帧**：继续后第一帧与暂停前最后一帧之间是正常帧间隔，画面可能跳一下（桌面已变），这是预期，不是切到第二个文件。  
2. **音画微差**：视频用帧时间戳减暂停；音频是停采后连续 PCM。极端长暂停或设备时钟漂移时，接缝附近可能有很小的音画差，需真机听。  
3. **摄像头 / 麦兜底**：走浏览器 `MediaRecorder.pause`，与原生屏幕时钟靠 `Date.now()` 边界对齐，不是同一硬件时钟。  
4. **`buildPausedAudioFilter` 未接线**：若以后有人按「墙钟成片再切暂停」理解音频，会和现行捕获期扣时不一致；不要当现行行为。

---

## 8. 判断

| 问题 | 答案 |
|------|------|
| 两段还是一段？ | **一段视频文件，编辑器一个主片** |
| 中间怎么连？ | **同一编码会话；暂停不写；继续后时间戳减去累计暂停，接在上一帧后面** |
| 要不要为「暂停=分段」改产品？ | 现行已对齐剪映/Camtasia「暂停不拆条」习惯；拆条应留给停止后再录或用户手动切，不在本夹改代码 |

本夹只调查，不改产品代码。
