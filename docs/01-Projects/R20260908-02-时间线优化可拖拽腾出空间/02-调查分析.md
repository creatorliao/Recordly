# 调查分析

## 角色与金路径

- 角色：使用 Recordly 制作培训课程视频的培训师。
- 金路径：录制 -> 停止 -> 打开编辑器 -> 调整时间线 -> 预览 -> 导出。
- 目标：服务 G2（减轻剪辑工作量）和 G4（专业、不过度设计的编辑体验）。
- 范围：Windows 优先，简体中文和英文，当前 `dev-creator` 分支；不涉及上游 PR。

## 源码现状

1. `src/components/video-editor/layout/EditorShell.tsx` 已用 `timelineHeight` 控制时间线高度，范围为 160 到 560 像素，指针拖拽方向正确，双击可恢复 200 像素。
2. `EditorShell` 使用纵向 flex 布局，预览区是 `min-h-0 flex-1`，所以时间线缩小时预览区会自然撑开，不需要改视频渲染逻辑。
3. `EditorTimelinePanel.tsx` 只有透明的 8 像素拖拽区域，没有视觉抓手、折叠按钮或状态反馈，用户很难发现能力。
4. 时间线面板没有折叠状态；已有 `editor.timeline.expand/collapse` 文案，但源码没有使用它们。
5. `EditorHeader.tsx` 的 `SidebarSimple` 按钮实际切换 `settingsPanelVisible`，标题却是泛化的 `Toggle sidebar`。左侧工具轨和右侧设置面板共存时，按钮语义容易被理解成控制错误的一侧。
6. 预览工具栏及时间线空态仍有 `rounded-full`/`rounded-lg`，与专业剪辑软件的紧凑控制面板风格不完全一致。

## 根因与影响

- 根因不是布局计算缺失，而是已有底层能力没有完成交互表达：缺少可发现的把手、折叠动作和动画状态。
- 若把时间线改成独立窗口或重做拖拽引擎，会扩大回归面并影响播放头、轨道滚动和导出前预览，不符合不过度设计原则。
- 顶部按钮的问题主要是标签和控制对象命名不准，不宜通过改变左右布局来“修复”一个语义问题。

## 风险分级

| 改动 | 优先级 | 风险 | 决策 |
| --- | --- | --- | --- |
| 时间线抓手、折叠、动画 | P1 | 低 | 实施 |
| 双击恢复默认高度 | P1 | 低 | 保留并明确化 |
| 设置面板按钮语义 | P1 | 低 | 实施 |
| 全量重做所有设置控件 | P2 | 高 | 本轮不做，另立项目 |
