# 03 · 方案：窗口模式纳入下拉菜单

> 方案未获「开始做」前 **不改产品代码**。先对照实验，再选一条实现。默认工作流（录→停→编→导、优先选窗口）保持不变。

## 1. 六问

| # | 问 | 答 |
|---|----|----|
| ① | 哪个 G？ | **G1**：成片必须看见点开的菜单。G2：少一次因菜单没录上而重录。 |
| ② | 不过度设计？ | 修窗口模式本身，不新开「菜单采集」开关，不换整套引擎。 |
| ③ | 回归？ | 动窗口采集会碰到卡顿/光标（`R20260906-09`）、HUD 排除、多显示器。必须两边回归。 |
| ④ | 用户需要吗？ | 需要。培训师讲软件，菜单就是操作本身。 |
| ⑤ | 会困惑吗？ | **修窗口模式**：老用户不用改习惯。**只改口令去录屏幕**：和现手册「优先选窗口」打架，必须改手册并提示。 |
| ⑥ | 奇怪副作用？ | 屏幕源会录进桌面/其它窗；DXGI 与 WGC 的丢帧、UAC、多 GPU 行为不同。窗口源扩大裁切可能短暂带进桌面边。 |

## 2. 立刻能用的规避（不改代码）

同一段操作，HUD 改选「**屏幕**」再录。

- 用来确认菜单能不能进成片，也给现在就要出片的培训师一条路。
- **不**把「以后都改录屏幕」写成产品默认：成片会脏，和现手册冲突。
- 若确认只发规避、不修窗口模式：必须改 `R20260906-01/02`，写明「点系统菜单时不要用窗口源」。

## 3. 动手前闸门（一次对照，二选一实现）

同一台 Windows 10、同一段 Typora「点主题(T)」：

| 结果 | 含义 | 实现 |
|------|------|------|
| **屏幕有菜单、窗口没有** | WGC 整屏纹理里有像素，窗口漏在**只裁主窗** | **分支 A**：裁切矩形并入 owner=所选窗的 popup（`#32768` / `WS_POPUP`） |
| **屏幕和窗口都没有** | WGC 采集面就不含系统菜单 | **分支 B**：窗口源改走已有 DXGI helper（桌面复制 + 裁切，裁切同样并入 popup） |
| **窗口反而有** | 与本报告不符，先停，核对当时是否其实走了屏幕源 / 浏览器采集 | 不改采集 |

按本机 **Win10 19044 + 整块缺失 + 菜单位于主窗画面内**，先验是 **分支 B**。对照若推翻，改走 A，不两套一起做。

## 4. 推荐实现（过闸后再做）

### 分支 B（先验，动采集面）

窗口源启动改为已有 `electron/native/windows-capture`（`DxgiSession`：`DuplicateOutput` + 按窗裁切）。整屏源继续 WGC，降低波及。

裁切不要只取主窗 `DWMWA_EXTENDED_FRAME_BOUNDS`：每帧枚举 owner 为该 HWND、可见、类名 `#32768` 或 `WS_POPUP` 的顶层窗，矩形与主窗求并，再与显示器相交。并集超出原编码尺寸时，只拷相交部分，**不要重开编码器**（现有「编码器尺寸固定」约束必须保住）。

还要核对：`WDA_EXCLUDEFROMCAPTURE`（HUD「从录制中隐藏」）在所用 DXGI API 上是否仍生效；不生效就只对窗口源用 DXGI，或改 `DuplicateOutput1`。

规模：接线 + 并入 popup 矩形，预期百行级；但是**金路径采集**，按工作法交人拍板，AI 不自动开工。

### 分支 A（对照证明纹理里已有菜单）

保持 `CreateForMonitor`，只改 `updateWindowCropRect`：并入 owned popup 矩形。不动编码器尺寸策略。Win10 上若纹理里其实没有菜单，这分支**零效果**，所以必须先对照。

### 明确不做

| 做法 | 原因 |
|------|------|
| 改用 `CreateForWindow` | 比现在更漏菜单；测试已禁止 |
| 把 `IncludeSecondaryWindows` 当本机方案 | 要 Win11 24H2；本机没有；系统菜单仍常漏 |
| 默认改成录屏幕 | 改变操作方式，成片变脏 |
| 给每个菜单单独建 WGC item 再合成 | 菜单窗经常建不成 item，行数和风险都超 |
| 和 `R20260906-09` 捆成一次改 | 根因不同；最多共享回归清单 |

## 5. 决策卡

闸门：范围 Windows ✓ · 落 G1 ✓ · 六问过 ✓ · 非换引擎 / 非巨型 Slop ✓。

| 项 | R 风险（高=更安全） | C | E | S | 动作 |
|----|---------------------|---|---|---|------|
| 文档 + 屏幕源规避 | 5 | 3 | 4 | **4.05** | 本轮已做；对照实验可立刻做 |
| 分支 A 扩大裁切 | 4 | 4 | 4 | **4.00** | 仅当屏幕源已能录到菜单 |
| 分支 B 窗口源走 DXGI | 3 | 5 | 5 | **4.15** | 先验；动核心，等人说「开始做」 |
| 默认改录屏幕 | 4 | 2 | 3 | **3.10** | 不进优先池 |

分支 B 落在「高价值、采集核心」：只进方案，**不自动改代码**。

## 6. 怎么验

自动化（改代码后）：

- 现有 `windows.test.ts`「禁止 CreateForWindow / 裁切主窗」若改为「并入 popup」，同步改断言。
- 补：owned `#32768` 矩形与主窗求并、超出编码器尺寸时不重分配纹理。

真机（`R20260906-02/14` §三 同类）：

1. 窗口源 · Typora · 点「主题」——成片有完整下拉。
2. 窗口源 · 记事本或资源管理器 · 点菜单栏——同样有。
3. 窗口源 · 不点菜单——成片仍只是该窗，不要整桌面。
4. 屏幕源回归：菜单仍在；HUD「从录制中隐藏」仍有效。
5. 看一眼卡顿/光标（09）：没有明显变差。

## 7. 对手册

- **修窗口模式成功**：手册「优先选窗口」不用改；可在注意里写一句「系统下拉应能录到」。
- **只发规避**：必须改 `R20260906-01/02`，并写变更提示：原建议会漏菜单，点系统菜单请改选屏幕。

## 8. 对工作流

不改变录→停→编→导。新能力默认仍是「选窗口只录该软件」。未获「开始做」前不改产品代码。
