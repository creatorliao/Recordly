# 调查：现状与根因

调查日：2026-09-08。只读源码 + 用户截图。未改产品代码。

## 1. 壳层现状（事实）

### 1.1 窗口骨架 · `EditorShell.tsx`

标题栏全宽。其下：

1. `relative flex min-h-0 flex-1 flex-col`
2. 内层 `relative z-10 flex min-h-0 flex-1`：**横向**放 `EditorSidebar` + `EditorPreviewPanel`
3. 然后 **通栏** `EditorTimelinePanel`（默认高 200，可拖 108–560，见 `R20260908-02`）
4. 再通栏 `footer` 22px（已保存 / 时码）

因此：左轨高度 = 预览行高度，**到不了底栏**。时间轴与底栏的 `left` = 窗口左缘。

### 1.2 左轨 · `EditorSidebar.tsx`

- 活动栏：`w-12`（48px），`h-full`，`justify-between`：上为项目/场景/光标/摄像头/字幕/扩展，下为齿轮。
- 抽屉：场景等走 `SettingsPanel` 固定 **280px**；项目走 `ProjectsPanel` **300px**。
- 齿轮已经在栏底，但栏底 = 预览底，不是窗口底。截图 2 齿轮「浮在时间轴顶上」由此而来。

### 1.3 运输条 · `EditorPreviewPanel.tsx`

预览列 `gap-0`。底部运输条 `h-8`：添加图层、缩放/魔法棒/剪刀、播放簇、音量。  
它只在**预览列**里，不在时间轴组件内。时间轴一通栏，运输条只覆盖预览列宽度，标尺却从窗口左画到右，左段正对左轨/抽屉。

### 1.4 标尺与播头

| 件 | 常量 / class | 实际 |
|----|----------------|------|
| 标尺目标高 | `TIMELINE_AXIS_HEIGHT_PX = 28` | `TimelineAxis` 用 `h-8` = **32px**，不一致 |
| 刻度结构 | 圆点 5px + `mb-1.5` + 10px 数字 + `pb-1` | 竖直偏厚 |
| 左偏移 | `marginLeft: sidebarWidth` | 本仓未给 dnd `setSidebarRef`，`R20260907-02/06` 记 **sidebarWidth=0** |
| 播头 | `PlaybackCursor` 线 2px；手柄盒 16、`-top-1`；拖时气泡 `-top-6` | 手柄/气泡向上伸出标尺 |
| 拖高抓手 | `EditorTimelinePanel` `absolute -top-2 z-30 h-4` | 向上吃进运输条 8px |

轨道行最小高 24、默认可见 2 行：`timelineLayout.ts`。与本夹「标识区太宽」弱相关，不在本夹扩 scope。

### 1.5 样式预设

`VideoEditor.tsx` 把同一 `<StylePresetCard />` 传给 `stylePresetSlot`。  
`SettingsPanel`：

- `sceneSectionContent` 第一项 = slot（场景 / 且 `frame`、`crop` 复用该块）
- `case "cursor"` 再渲染一次 slot

`R20260907-01` `03` D8 原文：卡片挂在「画面」和「光标」两页顶部，理由是调完光标也要存。

### 1.6 时间轴右缘（PR-05）

| 件 | 源码 | 结果 |
|----|------|------|
| 面板 | `EditorTimelinePanel` 无 `pr-*`；抓手 `left-0 right-0` | 横向铺满其包含块 |
| 包含块 | 现状 = 窗口宽；S3 之后 = 预览列宽 | 列右缘仍是窗口右缘（本仓无右抽屉） |
| 轨道 | `TimelineEditor` `overflow-hidden` / 内层 `overflow-auto` | 无右侧内容垫 |
| 折叠 | `absolute right-2 top-1`（8px） | 只给按钮让位，刻度仍顶边 |
| 运输条 | `EditorPreviewPanel` `px-1`（4px） | 音量条几乎贴列右 |

本机未打开剪映量像素；对照依据是桌面剪辑器的**通用壳**（面板铬条 + 内边距），与 `R20260907-02/06` 里 OpenScreen「滚动条不占布局宽、防标尺错位」一致：沟要稳定、不要用会挤刻度的 `scrollbar-gutter: stable`。

## 2. 根因对照诉求

### 2.1 PR-01 标识区太宽

**不是**漏设轨道名列（`sidebarWidth=0`，没有 200px 名列）。

水平：通栏时间轴把 t=0 钉在窗口左。左栏（48 + 280/300）盖住左段。用户在预览列看到的是「00 走廊 + 空白 + 右边才是 Clip」。截图 2 红框与「00 离色块很远」对得上。

竖直：32px 标尺 + 点线结构，相对 32px 运输条不协调；`R20260907-02` 已对标 OpenScreen 28px 单行数字。

### 2.2 PR-02 重叠

两类重叠不要混：

1. **像素侵入（真重叠）**：抓手 `-top-2`、播头 `-top-1` / `-top-6` 对运输条。预览与时间轴之间 **0 缝**。
2. **占位重叠（假 z 叠、真占位）**：标尺左缘与左栏同 x。时间轴没有 `position:absolute` 盖住抽屉文字，但侧栏无法向下长，看起来像「时间轴压在侧栏上」。

修 PR-03 的列模型后，第 2 类自然消失。第 1 类要单独收间距与 overflow。

### 2.3 PR-03 侧栏不通底

根因就是 §1.1 的「先左右、再在下面通栏时间轴」。  
齿轮位置算法没错，错的是活动栏的包含块高度。

VS Code / 剪映习惯：活动栏（或工具轨）从顶到底；时间轴只在中间编辑列。本仓现状相反。

### 2.4 PR-04 预设双入口

实现与 D8 一致，是**产品决策重复**，不是漏删。  
现用户明确视为设计问题。后说覆盖先说：本夹以用户 2026-09-08 提示为准，D8 降为待覆盖旧决策。

### 2.5 PR-05 右缘顶屏

S3 只解决「不要压左轨」，**不**自动产生右留白。  
根因是时间轴（及预览列）把「列宽 = 可用窗口宽」当成画布宽，没有「窗口铬 / 面板内边」。剪映把时间轴放进带边的面板；本仓把轨直接画到 `right: 0`。

与 PR-01 的「左边假走廊」相反：左边是**多占了不该占的窗**，右边是**该留的沟没留**。两边都要算，不能只收左。

> **2026-09-08 后说（PR-06）**：用户复验认为 12px 沟浪费。该段结论作废。现状根因变成「`pr-3` 已落地」。详见 [`05`](05-问题报告_改后复验.md)。

## 4. 风险

改 `EditorShell` 结构会碰到：时间轴拖高计算（仍用指针 y，与列宽无关）、底栏「已保存」是否让出 48px、抽屉打开时预览变窄（本来就会）、`z-10` 是否还需要。  
不动 IPC、导出、录制。预估壳层 + 标尺 + 预设挂载 **远低于 500 行**，属低垂 + 体验，可 AI 施工（须用户说「开始做」）。
