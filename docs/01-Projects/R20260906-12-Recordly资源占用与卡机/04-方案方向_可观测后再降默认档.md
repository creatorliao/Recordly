# 04 · 方案方向：可观测后再降默认档

> 匹配 `01` 与 `03`。**不过度设计**：不换采集引擎、不上性能平台。  
> 未获「开始做」前不改产品代码。日志字段契约写在 `R20260906-11/04`，这里只定优化顺序。

## 1. 目标与六问

| 问 | 答 |
|----|----|
| 哪个 G | G1（录的时候电脑还能用）、G4（默认省、高档可选） |
| 不过度？ | 先日志快照 + 降默认常量；不做自适应机器学习、不做进程优先级魔法 |
| 回归？ | 降分辨率/帧率会改变成片清晰度和顺滑度，必须可选「高画质」以免老用户觉得被降质 |
| 用户真需要？ | 要，整机卡比多 30 帧更伤金路径 |
| 会困惑吗？ | 默认更省；设置里留「采集档：省电 / 标准 / 高清」一类，不拆金路径按钮 |
| 奇怪影响？ | 已有 4K60 工程导出仍按工程设置，不偷偷改旧项目 |

闸门可通过。大改（换编码器、重写预览）不进 AI 自动开工。

## 2. 下一步（按序，不跳级）

### P0 · 日志里写出资源（主题 11，先做）

每次启动会话日志必须能回答「这一秒谁在吃」：

- 相位切换时立刻一条（录开始/停止、mux、进编辑器、导出、字幕）
- 录 / 导 / 字幕期间每 **5s** 一条稀疏 `resource.snapshot`
- 空闲每 **30s** 一条（证明空闲是否仍高）

字段见 11 的 `04` §5（已从「第二期」升为一等能力）。  
**没有这份账，禁止大规模改采集参数当「已经优化完」。**

### P1 · 把默认采集降到培训够用（主题 12 主优化）

建议默认（待你确认后实施）：

| 项 | 现在 | 建议默认 | 可选高档 |
|----|------|----------|----------|
| 帧率 | 60 写死 | **30** | 60 |
| 最长边 | 目标 2160 | **1080**（窗口/屏超过则缩小再编） | 1440 / 源分辨率 |
| 码率 | 18–45Mbps × 60fps 加成 | 1080p30 约 **8–12 Mbps** | 现档 |

原则 7：金路径按钮不变；只改默认真值。已选高档的写进设置，下次沿用。

### P2 · 重活让路（低风险）

- 导出进行中：预览 `ticker.stop()`，字幕按钮可点但排队或提示「导出完成后再生成」
- Whisper 加线程上限（例如 `max(2, cpu/2)`），禁止默认吃光所有核
- 开录时：编辑器窗口若在，停 ticker / 降 backgroundThrottling 让路（先量再决定要不要藏窗口）

### P3 · 导出默认不再 `source`（要确认）

建议默认 `good` + 1080p + 30fps。`source` 留在菜单。  
**会改变导出文件大小和清晰度**，须你点头。旧工程文件里已写 `source` 的不要批量改写。

### P4 · 不在本轮做

- 换采集引擎、换 Electron 版本、上 Process Lasso 一类优先级工具
- 为省资源关掉光标记录（会伤自动缩放和 09）
- 没有快照就猜「一定是内存泄漏」去大重构

## 3. 成功 / 失败

成功：

- 最新一份会话日志能看到相位 + RSS/CPU + 子进程名
- 默认档下，录 1080p 软件操作时，被录应用仍可流畅点击（真机）
- 高档仍在，想要 4K60 的人能打开

失败：

- 只降了码率但日志仍没有资源，下一次还是不知道卡在哪
- 偷偷改默认、界面没说，培训师以为软件坏了（成片变糊）
- 为优化拆掉光标或 WGC

## 4. 对工作流

默认不改步骤。若实施 P1/P3，手册 `R20260906-01` 补一句：默认更省电，要更清在设置里调高。
