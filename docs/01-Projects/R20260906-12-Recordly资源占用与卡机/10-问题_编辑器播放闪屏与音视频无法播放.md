## 3. 录 → 编 → 播 链路（源码事实）

```
停录
  → 立刻开编辑器（主视频路径已有）
  → 后台 Promise.allSettled：webcam / 麦 sidecar / muxNativeWindowsRecording
       mux 开始：setSessionLogPhase("mux") → broadcastPreviewYield(true)
       mux 成功：setSessionLogPhase("editor") → yield false
       mux 失败：catch 写日志，**不切回 editor**，相位可卡在 mux
  → 再 setCurrentRecordingSession（刷新麦/摄像头，不改 videoPath）

编辑器
  → EditorShell.recordingYield ← preview-yield.active
  → suspendRendering = 导出中 || recordingYield
  → VideoPlayback：suspend 为真则 ticker.stop + pause 视频；变回假则 seek + 可能再 play
```

关键文件：

- `electron/sessionLog.ts` `setSessionLogPhase` / `broadcastPreviewYield`
- `electron/ipc/register/recording.ts` 开录 `recording`、mux 起止
- `src/components/video-editor/layout/EditorShell.tsx` `recordingYield`
- `src/components/video-editor/VideoPlayback.tsx` `suspendRendering` effect
- `src/hooks/useScreenRecorder.ts` 停录后台 mux

编辑器窗口若在 mux 广播之后才挂上监听，会错过 `yield false`，初始 `recordingYield` 却是 `false`。更常见的是：**窗口已开着，mux 一开就把预览按死。**

## 4. 根本原因（已能定的设计错 + 待证伪）

### R1 · 已能定：mux 相位误停预览（主因）

金路径上，停录后的 mux **就是**编辑器第一次播放发生的时间窗。  
P2 在这个窗里发 `preview-yield(true)`：

1. Pixi ticker 停、画面元素 pause  
2. 用户点播放：`play()` 把隐藏 `<video>` 拉起来，但 ticker 仍停 → 画布不跟帧，只剩背景在闪/空转  
3. mux 结束再 `yield false`：seek + 重启 ticker，和正在播的时钟打架  
4. mux 失败则相位停在 `mux`，`suspendRendering` **再也回不来** → 声画都像死了

这与「进编辑器、一点播放就闪、声画没有」对齐，也与「刚刚那次修改」对齐。  
不是猜测，是相位枚举和停录时序对得上。

### R2 · 已能定：mux 失败不复位相位

`mux-native-windows-recording` 的 catch **没有** `setSessionLogPhase("editor")`。  
停录本身也不把 `recording` 切走，只靠 `switch-to-editor` 或 mux 成功。  
任一漏广播，让路开关就粘住。

### U1 · 待证：mux 就地改写正在播的同一文件

mux 对 `videoPath` 原文件做音视频合成。预览若已打开该文件，磁盘上的字节在变，Chromium 解码会闪、会停。  
旧行为允许「边 mux 边播」；P2 的 pause/seek/再 play 会把解码器打进更糟的状态。  
证法：会话日志 `mux.start` / `mux.complete` / `mux.error` 与第一次点播放的时间是否重叠。

### U2 · 待证：30fps / 10Mbps 成片解码

P1 改了编码参数。若旧工程（改前录的）也不播，则不是 U2；若只有新录的坏，再查 MF 时间戳/档位。

## 5. 解决方案（先小、对准 R1/R2）

不改采集档，不改导出停预览。只把「让路」收回金路径不该停的相位。

1. **`preview-yield` 只对 `export` / `captions`**  
   去掉 `recording`、`mux`。停录进编辑器必须能播。导出/识别仍停预览（P2 原意）。
2. **mux 的 `finally`（成功或失败）一律 `setSessionLogPhase("editor")`**  
   相位不能粘在 `mux`。
3. **停录成功后若即将开编辑器，相位不要停在 `recording`**  
   避免窗口已存在时误让路。
4. **不在本轮动 Pixi / 时钟 / 采集档**  
   行数小；U1/U2 若修完仍坏，再单独查。

六问：G1 ✓；不过度 ✓；回归是「导出/识别时预览仍停、录/mux 时不误停」✓；培训师刚录完必须能回放 ✓；无新入口 ✓；默认金路径恢复为能播 ✓。

回退：回到本问题记录之前那次提交即可。
