# 13 · 问题报告：编辑器播放闪屏、无声、进度卡住

> 角色：培训师，录软件操作。金路径：录 → 停 → 编 → **回放** → 导出。落 **G1**（编得动 / 播得了）。  
> 范围：仅 Windows；工作分支 `dev-creator`；官方原版 = 本地 `main`（跟踪 `upstream/main` @ `68bca43f`，仓库 `webadderallorg/Recordly`）。  
> 方法：以「官方原版和旧包能播、现在不能」为真源，做版本差分，不靠印象排序。  
> 本文是本问题的**正式报告**。`10` / `11` / `12` 是调查底稿，其中「让路即主因」已被真机证伪。

---

## 1. 问题现状

### 1.1 你看到的

停录进入编辑器，点播放：

| 现象 | 说明 |
|------|------|
| 画面一闪一闪 | 闪的是中间 Pixi 视频层；底下壁纸/背景图仍在（读图是好的） |
| 声音出不来 | 讲解声、系统声都没有 |
| 进度走不动 | 控件停在 `0:00`，播放按钮仍是 Play（`isPlaying === false`） |
| 时长能出来 | 出现过 `0:00 / 1:18`、`0:00 / 0:13`，说明文件不是「完全打不开」 |

工程例：`recording-1788692630055.recordly`。时间轴上可有多段 `1.5x`，背景面板开着。这些不是本故障的开关。

### 1.2 哪一段金路径断了

录得了、停得了、编辑器能打开、时长能读到。**第一下回放**断了。剪和导出还没轮到。

### 1.3 用过哪些包

| 包 / 树 | 回放 |
|---------|------|
| 官方原版（`upstream/main`） | 你确认：**没有这个问题** |
| 本仓 Beta 4 / Beta 5 Portable | 你确认：**能播** |
| 本仓 **Beta 6**（`5fcf6277`，版本从 beta.3 跳到 6） | **开始坏** |
| 本仓 **beta.7**（只收 recording/mux 让路） | 你确认：**仍闪、没声、进度走不动** |

旧包不会自己变好。要从当前源码重打、换目录再验。

### 1.4 和字幕 / 读图不是同一个故障

同画布三层：底壁纸、中视频、上字幕。读图、Whisper 随包已正常。没点「生成字幕」时不进字幕相位。详见 `11`。

## 2. 调查根本原因

### 2.1 方法：拿能播的历史版本对照

不问「看起来像什么」，只问：

1. 官方原版现在还有没有这套播放代码？  
2. Beta 4/5 相对官方，少了我们后来哪几笔？  
3. Beta 6 相对 Beta 5，**第一次**多了什么？  
4. beta.7 拿掉其中一刀之后，真机还坏不坏？

能播的版本里**没有**的东西，才是候选主因。两边都有、官方却能播的，最多是「潜伏扳机」，不是分叉点。

### 2.2 版本对照（Git 事实）

`dev-creator` 与官方 `main` 的 merge-base 就是 `68bca43f`（当前 `upstream/main`）。  
本仓里动过预览/停录、而官方没有的提交：

| 提交 | 内容 | 官方有没有 |
|------|------|------------|
| `d8fe5eba` | 预览时钟从 `requestVideoFrameCallback` 改成每帧 `rAF` 读 `currentTime`（跟 VFR） | **无**（官方仍走视频帧回调） |
| `9ba9a0f3` 18:34 | 会话日志 + **默认 1080p30/10Mbps** + 重编 `wgc-capture` + **`preview-yield`** + 导出一律停预览 | **无** |
| `5fcf6277` 18:36 | 壁纸 data URL、Whisper 入包、版本写成 beta.6 | 壁纸解析不同；**无 yield、无采集档** |
| `72dd1731` | 让路收到只剩 export/captions；版本 beta.7 | 官方本来就没有让路 |

`preview-yield` / `recordingYield` **第一次出现**就是 `9ba9a0f3`。Beta 6 是第一份带上它的 zip。

### 2.3 官方原版 vs 当前提交树：播放器骨架几乎一样

对过 `main` 与 `HEAD` 的 `VideoPlayback.tsx`（提交树，不含本轮未提交修改）：

官方**已经有**、不是我们发明的：

- `allowPlaybackRef`：未开许可时 `handlePlay` **立刻再 `pause`**
- `loadedmetadata`：**一律** `pause` + 清播放许可
- 挂视频纹理的 effect 依赖 `layoutVideoContent`：布局回调一换身份就拆精灵 + `pause`
- 复位镜头的 effect 同样依赖它：先 `pause`，两帧后再 `play()`，且不重开许可

官方 `EditorShell`：`suspendRendering` **只听导出**。没有 `preview-yield`。

官方停录后台：同样立刻开编辑器，webcam / 麦 sidecar / mux 并行。Windows mux **同样只挪 wav**，不改写正在播的 MP4。

因此：**不能**说「官方播放器没有 pause 环所以能播」。环在官方就在。官方能播，说明在官方的采集参数和停录路径下，这个环**没有被打进死循环**。

`VideoPlayback` 上我们相对官方的提交差，几乎只是：壁纸改走 data URL、字幕 aria 中英文化。这两处不改 `videoPath`，不改 play/pause。

### 2.4 官方没有、我们多出来的差异（分叉点）

按「会不会让刚停录的第一次播放死掉」排序：

| # | 差异 | 官方 | 我们（Beta 6 起） | 和症状的关系 |
|---|------|------|-------------------|--------------|
| A | `preview-yield`：相位 recording/mux/export/captions 停预览 | 无 | `9ba9a0f3` 引入 | 停录后的 mux 窗正好是第一次点播放。ticker 停、`pause`。**beta.7 已收回 recording/mux，你仍坏 → A 不是唯一主因** |
| B | 默认采集 60fps、码率按分辨率估算 | 写死 `fps: 60`，无 `bitrateBps` | 默认 standard：**30fps + 10Mbps**；`wgc-capture` 按传入码率编码 | **只影响新录的片子**。官方 / Beta 4/5 成片不是这个编码。进度能读到时长、但播不动，符合「文件能打开、解码/时钟走不了」 |
| C | 导出时一律 `suspendRendering` | 仅 modern MP4 导出才停 | 只要在导出就停 | 你此刻没在导出，不是进编辑器闪屏的开关 |
| D | 预览时钟 rAF（`d8fe5eba`） | 跟视频实际呈现帧 | 跟 `currentTime` 空转也走 | 片子若在播，不应钉死在 0:00；片子若被 pause，两种时钟都不会走 |
| E | 壁纸 data URL | `getAssetPath` | `resolveEditorWallpaperDisplayUrl` | 动底层背景。截图里背景在，说明 E 不是中层闪屏 |

**B 是官方原版和 Beta 4/5 都没有、Beta 6 起默认就有、且 beta.7 没动过的产品差。**  
在 A 被真机证伪之后，历史对照把下一刀指向 B（新录成片），以及「我们多出来的重渲染把官方就有的 pause 环打爆」（A 的残留 + 摄像头会话刷新 + 壁纸 state）。

### 2.5 已证伪（不要再当主因）

| 编号 | 说法 | 为何否 |
|------|------|--------|
| 旧 R1 | mux 相位让路是唯一主因 | beta.7 已不让 recording/mux 停预览，真机仍坏 |
| U1 | mux 就地改写正在播的 MP4 | 官方和我们的 Windows mux 都只挪 sidecar，`muxed: false` |

### 2.6 当前判断（分层，不装成已经钉死）

**已能定（源码 + 版本对账）：**

1. 官方原版能播，不是「这套编辑器天生不能播」。  
2. 分叉从 `9ba9a0f3` 进源码、从 Beta 6 进你手里的包。

4. 编辑器里存在一套官方也有的 pause 环；我们多出来的 yield / 会话刷新 / 布局回调换身份，更容易把它打成：闪 + 没声 + 进度钉在 0:00。

**待真机证伪（按历史差，一次只验一刀）：**

## 3. 解决方案

原则：先回到「官方那种能播的编辑器停转」，再按 H1/H2/H3 动采集。不把 4K60 默认永久加回来当唯一解（那是 G4 要降的），但**金路径播不了时，默认必须先能播**。

### 3.1 立刻做（对齐官方编辑器，已在工作树）

1. **整条 `preview-yield` 撤掉**  
   官方没有这根线。相位只写会话日志。预览停转只听「正在导出」（官方还更窄：仅 modern MP4；我们仍是「只要在导出」——进编辑器回放不受影响）。  
   不 `git revert` `72dd1731`：那会把 mux 让路加回来，比官方更差。

2. **收紧官方就有的 pause 环，避免被我们多出来的重渲染打爆**  
   - 挂纹理、复位镜头：只在 Pixi / 视频就绪翻转时跑，不绑 `layoutVideoContent` 身份  
   - 恢复播放先开 `allowPlaybackRef`  
   - 已经在播时，`loadedmetadata` 只补时长，不再 `pause`

这样即使摄像头会话、壁纸、时长后到，也不会把第一次播放按死。官方能播的路径我们不再比它更容易死。

### 3.2 下一刀（按历史差异，等 3.1 打包装验）

仍闪时按 H1 → H2 → H3 做，**不要三刀一起改**：

1. H1 成立 → 继续只动编辑器，不动采集。  
2. H2/H3 成立 → 标准档成片解码有问题。临时方案：默认采集改走与官方等价的 **high**（60fps、码率估算），或标准档先不传 `bitrateBps`（只降 fps）。长期再修 10Mbps + 源分辨率（原生仍可能 4K）的 MF 编码。  
3. 高清档仍坏、旧工程也坏 → 回到 3.1 查漏，不先动编码器。

采集默认先不改。G4 降档和 G1 能播冲突时，**先保能播**，再另开采集专题。
